## 2. 与 mootdx 现行主源的关系:替代还是补充?

| mootdx 断片补漏 | 2026-07-17 曾 80 节点 0 可用,断片日宽度断点 | FAPI 自动补断片(000001 实例已验证) | 补漏=纯增量,不替换 |
| 北交所 340 | mootdx 0,mootdx+baostock 均不覆盖 | **FAPI 唯一供给**;是否纳入主宽度宇宙另行拍板(beijiao 方案 C 单独出北交所宽度,不动现有主宽度) | 需用户拍板宇宙口径(方案 §2.4) |
| 盘中实时 | 腾讯主源+新浪降级 | 可加 FAPI 第二兜底(P2 秒级已验) | 兜底,不动腾讯主链 |
| 涨停池/龙虎榜 | 东财主源 | FAPI 异源兜底(已落地) | 兜底,东财活不抢跑 |
| THS 概念指数 | akshare thsc_* T+1 | 概念换官方走 1 周并行观察(09-08 评估),观察期 27/27 100% | 换源属展示数据源变更,§21 公示;与主宽度无关 |

## 4. 三个方向对比 + 倾向建议

| 维度 | A. 转正正式兜底源(推荐) | B. 继续观察(≥1 周) | C. 下线 |

| 成本 | 挂互证校验脚本 + 兜底切换收尾 | 继续每日对照(脚本已有,零成本) | 清理 fapi 表/launchd/兜底代码 |

**我的倾向建议:A. 转正正式兜底源。** 理由:
1. 数据说话:所有验证维度(概念对齐/T+0一致/延迟/北交所覆盖/采集稳定)观察期全部通过,不存在继续观察才能消除的已知疑问。
2. 北交所 340 是 **mootdx+baostock 都覆盖不了的硬缺口**,FAPI 是唯一供给;拖一天就少一天北交所数据。
3. 转正是"正式兜底+互证校验",**不是切主源**——主宽度/AI 推荐链路零改动,风险可控(§23.7 只增不改天然合规)。
4. 待长期验证项(兜底真实触发/30% 档/北交所全量历史)不阻断转正,可作为观察期后的专项跟踪,转正后系统本身会自动积累真实故障样本。

**转正条件(建议,供用户拍板)**:
- ①fapi_daily_raw 作为 mootdx 空/断片时的自动兜底源(挂 runner/width 链,复用 multisource 模式)
- ②互证校验脚本挂 deploy 前 check(每日 fapi vs mootdx close 差异 >0.5% 的 code 数 >N 告警,方案 §2.3 已设计)
- ③北交所宽度宇宙口径用户拍板(单独出 beijiao 方案 C vs 全纳入方案 A)
- ④概念换官方独立走 1 周观察(09-08 到期),与本次转正解耦
- ⑤THS 概念/README 数据源段 §21 公示同步(若概念换源落地)

**关键查询(只读)**:
```sql
-- T+0 与 mootdx 一致率(观察期)
SELECT f.date, COUNT(*) AS overlap,
  SUM(CASE WHEN ABS(f.close-m.close)>0.0001 THEN 1 ELSE 0 END) AS close_mismatch
FROM fapi_daily_raw f JOIN mootdx_daily_raw m ON f.code=m.code AND f.date=m.date
WHERE f.date IN ('20260902','20260903') GROUP BY f.date;
-- 北交所覆盖
SELECT COUNT(DISTINCT thscode) FROM fapi_daily_raw WHERE thscode LIKE '%.BJ';
-- fapi 表概况
SELECT MIN(date), MAX(date), COUNT(*), COUNT(DISTINCT code) FROM fapi_daily_raw;

SELECT date, metric_id, value, source FROM daily_metric
WHERE date>=20260901 AND metric_id IN ('a_width_zt_count','lhb_count') ORDER BY metric_id,date;
```
