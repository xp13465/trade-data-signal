## 1. 实测方法

- 采样脚本 `docs/fapi/scripts/latency_probe.py`:每 60s 一轮,盘中连续采集(09:30-11:30/13:00-15:00),落 JSONL
- 标的:600519.SH(茅台)/ 000001.SZ(平安银行)/ 300750.SZ(宁德时代)
- 每轮三要素:FAPI snapshot last_price + data.timestamp(ms)、腾讯秒级真值 last_price + 时间戳、本机采样时刻
- 延迟 = FAPI timestamp − 本机采样时刻;价差 = |FAPI last − 腾讯 last|,<=0.001 算一致
- 后台跑法:09:38 起 `--run` 自动采(latency_probe.pid=51265),15:00 各时段自动识别,15:08 退出;收盘后 `--stats` 统计

## 2. 采样明细

- 采样轮数:**238**(09:30-11:30 + 13:00-15:00 全天连续)
- 有效延迟样本:**229**(9 轮 FAPI snapshot 无有效 timestamp,标注为缺口轮——多为盘中瞬时超时/网络抖动,量级 3.8%,不隐瞒)
- 时间覆盖:09:30:22 → 15:00:02,覆盖全天各时段(含 09:30 集合竞价刚过、10:00/10:30/11:00/13:30/14:00/14:30/14:58 等全部采样点)

| 指标 | 值 |

### 3.1 不一致分布分析(诚实标注)

对 687 对比对中的 168 个「价差>0.001」做了性质抽查:

- **早盘剧烈波动期集中**(09:30-09:34 集合竞价刚结束):茅台价差 1.63 元、宁德 1.04-1.11 元,属价格秒级大幅跳动,60s 轮内取价时刻差放大
- **盘中普通跳动**(0.01-0.13 元):平安/宁德频繁 0.01-0.02 元差,纯粹是「FAPI 取价时刻 vs 腾讯取价时刻」隔着秒级,价格在动
- **结论:未发现 FAPI 价格本身错误**(无 10%+ 级错价、无 0 价/负价);不一致全部可归因于轮内时差

## 4. 结论与推荐

- **延迟档位实测 = 秒级(<1s 中位)**:FAPI snapshot 数据就绪领先采样时刻(负延迟),源头无滞后。偶发 1-3 次 max 2.7s(单轮网络/缓存毛刺),不影响实时定位
- **推荐**:按方案 §6.4,满足「若秒级:可评估将 intraday_snapshot.py 的指数实时源(腾讯→新浪降级)加 FAPI 为第二兜底(§23.3 举一反三:同链)」→ **建议实施 FAPI 作为盘中快照第二兜底源**(腾讯主源在新浪降级之上再加 FAPI)
- **用途边界**:FAPI 做兜底(主源失败才切),不动腾讯主链;与 dump T+0(P0 #16,已逐位一致验证)同源互证,一主一备

## 5. 风险与边界(诚实标注)

- 腾讯是公开行情参考,数据就绪时点可能本身有秒级误差
- 单日实测(2026-09-02),结论只代表当日 FAPI 源状态,不代表长期 SLA;9 轮空缺(3.8%)为盘中瞬时超时,不掩盖
- 价格一致率 75.5% 是「同级内不同时刻取价」的对比,不是严格同 tick 逐位对齐,只作粗校;严格逐位对齐需同 tick 采样(下一轮可做更细粒度)
- 一次脚本 bug(tencent key 纯代码 vs THSCODE 错位)已修后重算,样本数据本身未动
