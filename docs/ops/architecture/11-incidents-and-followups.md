## 状态怎么读

- workflow_status、remediation_state、root_cause_state、deployment_state、verification_state分轴展示；completed只表示交接处置，不是部署或根治。
- 已修且限定PASS不扩大到其它历史键/全部前端；root_cause仅有证据的原逻辑或局部机制标已定位。未定位一律unknown。
- 观察窗口本轮均未实际开启，写待观察并说明期望证据，不能标“正在观察”冒充持续监测。历史不可回放不等恢复。
- 以原SG/DIR/DC/RT/工单编号或原测试/交接名追踪，不新造工单号；原pending-index状态不修改。机器目录见[inventory/incidents.json](inventory/incidents.json)。

## 面板工作流分组（稳定枚举 v1）

每条`workflow_group`只有一个主分组；`workflow_group_label`供显示，`workflow_group_scope`限定范围。它是面板筛选，不改原工单状态，不代替修复/根因/部署/验收/观察各轴，也不裁定授权。

| workflow_group | 展示标签 |
| --- | --- |
| `pending_review` | 待复核 |
| `investigating` | 调查 |
| `repair_pending` | 修复（待实施/处理中） |
| `awaiting_verification` | 待验 |
| `observing` | 观察 |
| `scoped_verified` | 已限定验收 |
| `not_replayable` | 不可回放 |
| `mixed_historical_disposition` | 混合历史处置 |

- `observing`仅用于实际开始且有日期/证据的观察；本轮没有此类记录。待观察不能混入观察组。
- `scoped_verified`只认原验收范围；`not_replayable`不等恢复。七键主组是mixed，JSON子组明确2候选调查与5不可回放，不把五键子集扩大到七键。
- `repair_pending`不代表用户未授权；“待拍板”仅是原文声明，是否仍需额外授权未核实。防复发默认后续仅指前两类，第三类谨慎历史补冻不纳默认推荐、不放宽guard。
