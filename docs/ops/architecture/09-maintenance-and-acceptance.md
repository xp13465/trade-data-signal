# 知识库维护、对账与验收

## 权威与导航

本目录是运行架构的导航与结构化索引。各专题原有规范保留权威位置；本库引用其内容和具体代码锚点。历史事故报告不能自动当当前故障；旧部署快照不能覆盖新运行观察。

同一对象沿用稳定id。图、任务总账、面板、事件、运行手册复用该id；代码ref、部署ref、观察时间、业务日期分别记录，不能只有一个“最后更新时间”。

## 三层对账

- 仓库声明：调度模板/生成器、入口函数、规则、依赖和预期部署位置。
- 部署配置：云端实际unit/cron与本机launchd注册（launchd 已废弃/历史存档，生产定时任务已迁云上 systemd timer，本机 mac 纯开发不跑生产定时任务），入口与时间表达式、开关和timeout。
- 运行与业务事实：最近一次实际触发/结果、输入截止日、产物可读性、发布可见性与服务响应。

名称匹配只帮助归并，不能证明配置一致。repo-only代表本次没观测到，不直接判未部署；runtime-only代表未匹配源声明，不直接判异常。工作日/交易日不应执行的任务不能当漏跑。

## 本次验收标准

- 有一个入口，服务/任务/数据/监控/部署/手册均可导航。
- 所有清单记录有稳定id、来源、证据层级；未知项显式可见，不用推断补齐。
- 运行观察注明采集时点、命令覆盖边界与未覆盖部分；不混淆运行态和健康态。
- 架构图和关联边有来源；计划面板/拟议采集明确标planned。
- 任务能追到调度入口、日历门控、输入输出、失败检测和排障路径；未核字段有owner/下一步。
- 主数据、镜像、静态副本与外部控制面角色区分；不会因为同文件名而视为同一真相。
- 清单JSON可解析并符合结构合同，局部id唯一；跨文件同对象保留各来源观察，不静默覆盖。
- 文档相对链接可解析；不包含凭证、私人通知目标或环境变量值。
- 变更仅限此知识库文档/报告资产，独立codex分支提交推送，交Claude复核合并；不改业务运行配置。

## 后续变更需同步的内容

新增/删除服务或任务：对象登记、部署位置、调度器、依赖、监控和手册；保留移除记录及替代入口。
变更调度：时区/交易日规则/截止时间/锁与超时链/上游晚到与补跑策略，附配置和运行观察。
变更数据资产：生产者/写入合同/消费者/业务日期/版本/备份恢复覆盖，防止写入路径分叉。
变更发布或告警：分阶段结果与恢复条件、投递和业务结果区别、去重升级及证据保留。

## 长期维护责任（建议，待Claude确认）

Claude主控负责实现任务书、代码与配置变更、内部审查、部署和更新知识库；具体模块owner在登记中明确。Codex只读核查、架构分析与外审证据，对事实不一致发报告；不越权修改生产、处置业务findings或代主控发任务。

每个unknown需记录“缺什么证据、从哪取、谁核、何时随变更复核”；允许明确的覆盖边界，不把未知伪装成完成。架构变化后的对账由正常开发/发布流程触发；本次不建立自动定时任务。

## 可重复构建与校验

源事实在inventory各专题JSON中，模板在templates/dashboard.html。catalog、reconciliation和离线预览是派生视图，请不要手工修改。工具只读这些清单，不取生产状态，不导入业务模块或访问网络；源清单在生成期间变化会中止。

```sh
python3 docs/ops/architecture/tools/build_catalog.py --write
python3 docs/ops/architecture/tools/build_catalog.py --check
python3 docs/ops/architecture/tools/check_knowledge_base.py
```

构建仅原子替换本目录三个派生产物，不重写源清单；同一组源输入输出确定。--check默认只校验不写。事实更新必须先修改/重新取证对应源清单和证据，不能用重新构建更新时间冒充新运行观察。

图集的diagrams/manifest.json绑定每个Mermaid块与SVG内容哈希；源图变更未同步导出会被校验拒绝。导出渲染器为临时工具，不作为业务或页面运行依赖；更新图时使用团队审核的Mermaid渲染器并更新manifest。
