## 二、根因（不是崩溃，是刻意设计的 fail-closed）

**exit=5 ≠ errno/EIO，是脚本自己定义的「数据就绪闸 FAIL」退出码**，链路：

```
signal_kelly_backtest.py:2058-2063  任一标的 missing → raise RuntimeError("数据就绪闸 FAIL: N 只 ETF 取不到真实开盘价")
signal_kelly_backtest.py:2398-2402  except RuntimeError → print + sys.exit(5)
kelly_intraday_rerun.sh:93-109      取 BK_RC=PIPESTATUS[0] → 「本轮跳过，留 17:50 全量」→ notify severe → exit 5
```

**本次直接触发**：T=20261009 的买信号涉及 24 只标的，其中 **159513 / 164508 两只在当日 09:40 前一笔都没成交**——两源（腾讯/新浪）都拿不到「可证实为当日」的开盘价：

| 代码 | 腾讯分时首笔 | 备注 |
|---|---|---|
| 159513 | **10:31**（09:30–10:30 volume 全 0） | 开盘后一小时才首笔 |
| 164508 | **09:57** | 全天仅 **20 手 / 2474 元** |

⇒ **不是解析 bug**：步骤 7 现场只读复现显示两码此刻都能取到、88 字段布局正常（`[5]`=今开，`[30]`=当日时间戳）——是 09:40 那个时点**这两只客观上没有当日成交**。

## 三、影响面

- **无永久数据损失**：设计即「跳过本轮 → 17:50 全量兜底」，当日全量轮次会补上。
- **实际损失** = ①今日**盘中档增量没生成**（盘中视图停在上一批 T=20261008）；②**1 条 severe 告警**；③ unit `failed` 在册（影响看门狗分类）。
- ⚠️ **判新鲜度的陷阱**：`static-site/data/signal_kelly_trades_intraday.json` 被盘中链**每 ~10 分钟重写**刷现价（`app/collector/etf_national_team.py:1362-1420 refresh_intraday_cur_prices` + intraday_snapshot 批量重写 site JSON），所以 **`mtime` / `generated_at` 会一直"新鲜"、完全不能当新鲜度信号**。
  - **唯一可靠判据 = `intraday.rerun_date` 字段**（本次事件后其值仍为 `20261008`）。
  - 同型记录：`docs/ops/227-inner-timeout-verdict-20261010.md:134`。
