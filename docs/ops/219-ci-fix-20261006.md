### 为什么选 ②(而不是照抄 test_193 的自带垫片)
- §5.1「优先消除重复」:垫片本质是「CI 环境铺底」,与 conftest 既有三件事(sys.path / REPO / 第三方库 stub)**同一类关注点**,放同一处 = 单一事实源;照抄 ① 会在两个文件各留一份,下次同类坑再犯。
- **不引入新风险**:垫片只设 `GIT_REPO`(经 `setdefault`,不覆盖已有值),不改 `ROOT`/`STATIC_DIR`;
  `_find_env()` 候选顺序是 `ROOT/.env` → `$GIT_REPO/.env` → …,**本机 `ROOT/.env`(真实 `trade/.env`)存在且排在首位**
  ⇒ 本地开发照旧用真实凭证,垫片只在 CI(无 `.env`)时兜底;唯一读 `GIT_REPO` 的仓内模块 `check_failed_units.py`
  用它算 `DEFAULT_REPO` 候选,已核对其测试(test_196)只调纯函数 `_resolve_exec_entries` 并传入显式 `_lookup`,
  与该候选无关 ⇒ 无副作用(见 §4 证据)。
- 已按派单要求「必须证明 test_193 仍 PASS 且行为不变」——见 §4 的 40/40 对照。
