## §P2 发现:check_failed_units ②b「脚本存在性」层生产空转(建议修复,不阻断本次上线)

**现象(云上实测,逐 unit 取证)**:`WATCHMAN_UNITS` 全为 `.timer`;`_run_unit_show(timer)` 取不到 `ExecStart` ——
```
trade-cloud-unit-patrol.timer: ... ExecStart_is_none=True paths=[]
(7/7 全部同形;而配对 .service 均可解析:)
trade-cloud-unit-patrol.service: paths=['/home/ubuntu/code/trade-data/scripts/cloud_unit_patrol.sh'] ...(7/7 均有)
```
`.timer` unit 无 ExecStart 属性(systemd 语义),故 ②b 层在真实数据上拿到的 exec_start 恒 None → `extract_script_paths([])` ≡ [] → **该层生产从不生效**(与文件头承诺「与注册无关的兜底」不符;dry-run 的 rc=0 里它贡献为 0)。

**为何测试全绿没抓到**:`test_cfu_watchman_script_missing_rc1` 用注入样本给 `.timer` 喂了一个现实中不存在的 ExecStart → 层逻辑被测活,但生产的输入形态(timer 无 ExecStart)无人对账(**注入样本形态 ≠ 生产输入形态**,§5.3 测试设计质量/L44 同源病灶)。

**影响面(§23.2 排查同类,已穷举全 repo)**:`extract_script_paths` 仅此一处调用;`systemd_timeout_gradient_audit.py:283` 读的是 unit 文件文本(另一机制,不受影响)。实际覆盖缺口:
- 3 个带 `ConditionPathExists` 的 unit 中,patrol / r2-consistency 另被「注册漏跑」通道覆盖(在 TASKS/C 表内,已实测);
- **check-monitor-heartbeat 无任何其他通道**:其脚本 `check_monitor_heartbeat.py` 被删 → systemd 跳过不跑(无 failed unit、无日志)、不在 monitor TASKS 注册表、不在 LAUNCHCTL_LABELS 清单、cloud_unit_patrol.sh 只比 unit 文件不查脚本存在 → **静默**(恰是 #196 F1 族要根治的病灶形态,只剩 ②b 兜底而它空转)
- 其余 4 个(monitor/self-heal/data-gap/overfit)无 ConditionPathExists,脚本被删 → bash/python 以 127 失败 → ①failed-unit 通道可抓(不依赖 ②b)

**建议修法(最小)**:②b 改查**配对 `.service`**(`u.replace(".timer",".service")`)的 `ExecStart`(可选加 `ConditionPathExists` 一并判);即实测 7 个 service 均可解析到脚本路径,改动后该层即非空转。测试同步:注入样本改为 `.service` 的 show_map(或对 timer 断言 paths=[] 的负向用例),防「假样本养绿测试」复发。

**定级**:P2(不产生假告警、不阻断本次 §0;属兜底承诺未兑现 + 单 unit 覆盖缺口)。建议单独小任务修,不动本次合并。
