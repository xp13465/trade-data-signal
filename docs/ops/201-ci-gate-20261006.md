## 4. 零外发自证(验收点④,§18 L48)

**先证打桩生效,再跑测试。**

1. **原脚本自带三道防线**(在 `main()` 开头,早于任何 `cmd_verify_r2`/上传路径):
   - ① `sys.modules['notify']` 换 Fake + 真实 `notify.send` 挂陷阱(触达即 `AssertionError`);
   - ② `_upload_glob` 打桩(任何路径都不真 PUT);
   - ③ `ur.ROOT` 重定向到临时树。
2. **收尾硬断言**:`_ok(not trap and not put_calls, "真实 notify.send / 真实 _upload_glob 全程零触达")`
   —— 实测 `[C] _upload_glob 触达 0 次, notify send 触达 0 次`。
3. **本包装自身**:零网络、零 subprocess 写、零 DB;垫片值全 dummy(`R2_S3_ENDPOINT=https://invalid.example`)。
4. **负控制(证明还原块是承重的)**:裸调 `t193.main()` 后不复原 →
   `sys.modules['notify'].__file__ = <无>`,`notify.send.__name__ == '_send'`(Fake)
   ⇒ 会话内后续 `import notify` 会拿到 **Fake(真通知被静默吞掉)**。
5. **正控制**:经本包装的 finally 还原后 →
   `sys.modules['notify'] is 原真模块 = True`,`__file__ = …/scripts/notify.py`,`notify.send.__name__ = send`,`GIT_REPO = None`。

> 设计说明(为何有 finally 还原块):原脚本按「独立进程跑完即退出」设计(末尾 `sys.exit()`,且**不还原**
> `sys.modules['notify']`)。放进 pytest 长驻会话必须显式回滚,否则毒化同会话其余 notify 用例
> (`test_196` / `test_notify_r4_dedup` / `test_alertchain`)。3.4 全量套件 PASS 即该回滚的实证。
