# 交易计划「空计划」根因定性报告(2026-09-24)

> 调研对象:用户疑问「交易计划怎么停留在 923 和下一个交易日 928,今天 924 没计划么,卖出计划都没么」
> 调研人:researcher(只读,经云上 ssh 只读核查 + 本地代码/DB 核查)
> 展示层修复(commit 4e958566f)已单独上线,本次回答更根本的问题:**9-24 的计划本身该不该是空的**

## 0. 结论摘要

| 问题 | 结论 | 证据 |
|---|---|---|
| 9-24 为何没计划 | **9-23 晚生成的 9-24 买入计划确实为空**,且空是对的:9-23 当日(固化时点)可入样的买入信号为 0 | 云上日志主链(见 §3) |
| empty:true 是设计态还是故障态 | **设计态**,由明确的互斥分支写出 | 生成器 L996-1005(见 §1) |
| 空计划根因分类 | **「当日确实无(可入样)买入信号」正常态**,非链路故障(exit 0 / 通知正常 / R2 正常 / gap-check 正常跳过) | §3 证据链 |
| 9-24 与 9-28 该不该有计划 | 9-24 今晚 22:30 重跑,大概率仍空(当日买信号仅 cgb_10y_etf,无跟踪 ETF);9-28 是 9-24 的下一交易日(9-25 中秋休市),该日计划由 9-28 晚生成 | §4 |

| 诚实标注 | 9-23 22:30 时点 4 条非买信号逐条无法还原;hk_cesg10 buy 为晚到信号;本地 DB 停 9-17 无法重验 | §6 |

**一句话回答用户**:9-24 没计划是因为 9-23 盘后跑出来当天确实没有任何"可选标的的买入信号"——那天 A 股信号全是卖出类(止损/减仓)和波段持有,唯一的买入信号(10 年期国债 ETF)没有可跟踪的 ETF 标的,所以按规则不出买入计划。这是系统按规则判定的正常结果,不是坏了;页面把它显示成"停在 9-23"是旧数据产物缺"今天是交易日"信息导致前端把 9-24 当非交易日吞掉,已修的展示修复要等今晚 22:30 生成新产物后才真正生效。

## 1. empty 分支触发条件(设计态确认)

`scripts/nextday_plan_generator.py`:
- docstring L48 明示产物两形态:「输出:`data/nextday_plan.json`(本地权威: `{date, plan:[...]}`; 空计划 `{date, empty:true}`)」
- L996-1005 写盘分支(互斥):

```python
plan_doc = {"date": T, "today": T, "is_trading_day": T in set(trade_dates),
            "next_trading_day": _next_trading_day(trade_dates, T)}
if plan:
    plan_doc["plan"] = plan
else:
    plan_doc["empty"] = True
```

- plan 为空列表的触发路径(`_build_plan_for_day` L672-782):①signal_daily 当日无信号(排除 s.*)②无买信号(signal 不在 BUY_SIGNALS={buy,buy_aux,buy_special,buy_backup})③全部未入样宇宙(无跟踪 ETF track_score)④全部被降亏过滤剔除 ⑤prev_close<=0(停牌)或伪跳空>20% 剔除 ⑥交易日历无下一交易日(L715-717 走空)。
- 结论:**empty:true = 当日规则判定无计划的设计形态**,不是异常占位。

## 3. 根因分类:正常态(当日确实无可入样买入信号),非故障

9-23 22:30 主链完整明细(日志原文):

```
[nextday_plan] T=20260923 signal_daily 信号(排除 s.*)=6
[nextday_plan]   - cgb_10y_etf buy_aux 未入样宇宙(无跟踪 ETF track_score)
[nextday_plan]   - cgb_10y_etf buy_special 未入样宇宙(无跟踪 ETF track_score)
[nextday_plan] 当日买入信号通过降亏候选=0
[nextday_plan] K=1 保留信号=[]
[nextday_plan] 计划条目=0 buy_date=20260924
```

故障排除证据(fault-exclusion checklist):
1. **退出码=0**:`nextday_plan.sh 结束 ... 退出码=0`(两次运行均 0),非 fail-closed 阻塞(阻塞会 return 2 + severe 告警)
2. **通知正常**:`notify: 明日买入计划 20260923(空)` + `notify 退出码=0` → 用户当晚收到过「空」计划邮件,空是显式告知的产物,不是静默缺失
3. **R2 上传正常**:`R2 退出码=0` + 落盘三树+快照
4. **无 severe 告警**:生成器无 `[告警] 次日买入计划` 类邮件(9-23 有另一条 gap-check 告警,那是 9-23 上午盘中 akshare 拉开盘价失败,与空计划无关)
5. **当日信号本身确实贫瘠**:云上 DB(9-24 18:55 快照)signal_daily 20260923 共 9 条:买信号仅 cgb_10y_etf buy_aux/buy_special + **hk_cesg10 buy(晚到)**,其余全是 sell/sell_stop_loss/band_hold/band 持有类;cgb_10y_etf 无跟踪 ETF(日志原文"未入样宇宙");hk_cesg10 不在 board_etf_map(无任何 ETF 候选),即使当时可见也会被"未入样宇宙"剔除 → **9-23 可入样买信号确实为 0**
6. **下游一致把空计划当正常态**:9-24 09:26 gap-check「空计划(True), 无执行日买入, 跳过」退出码=0
7. **空仓是正当策略手段**(§5.1 用户定调 memory idle-position-is-valid-strategy):全卖出/持有日不出买入计划=规则内正常输出

## 4. 9-24(今天)与 9-28 该不该有计划

- **9-24 今晚 22:30 会跑**(trade-nextday-plan.timer Mon..Fri,9-24 是交易日,闸门通过):生成 T=20260924 计划。
- 当前(9-24 18:55)DB 中 9-24 信号 12 条,买信号仅 `cgb_10y_etf buy_aux` + `cgb_10y_etf buy_special`(均无跟踪 ETF)→ **产物大概率仍为 `empty:true`**,但会带修复后的元信息字段:`today=20260924, is_trading_day=true, next_trading_day=20260928`(生成器 L996-1001,修复 commit 4e958566f 已确认是云上 main 的祖先)。
- **9-28 确认是 9-24 的下一交易日**:trade_dates.txt L8733-8734 只有 `20260924` `20260928`,9-25 无(中秋休市)→ 9-25 周五不交易,9-26/27 周末,9-28 周一。
- 9-28 当日的买入计划由 9-28(前一交易日)晚 22:30 以 T=20260928 生成,今晚只生成 T=9-24 的计划(其 buy_date=9-28)。
- 快照/回填段逻辑照常,不因空计划日异常。

## 5. 前端口径 vs 产物两种形态(兼容,但文案不区分成因)

前端 `static-site/lab.js`(云上已含修复,线上 lab.js curl 命中「当日无计划」字符串 ×2 验证已上线):
- 读 `plan` 数组:`_atPlanRows`(L14567+):`Array.isArray(doc.plan) && doc.date` → 逐条生成行;空计划(无 plan)→ 返回 []。
- 交易日序列 `_atTradeDates`(L14673+ 修复注释):由 steps 的 date/sell_date + plan 的 buy_date + **元信息 today(is_trading_day=true 时)/next_trading_day**(修复后新增);「旧产物无字段自动回退既有反推」→ 两种形态兼容。
- T0/T1 判定 `_atRemindPair`(L14695+):今天在交易序列 → T0=今天;不在 → 回退最近过去交易日。**9-24 白天(旧产物无元信息)序列里没有 9-24 → 前端认为 9-24 非交易日 → T0 回退 9-23;steps 键中 >9-23 最小日期=20260928 → T1=9-28** —— 与用户看到「停留在 923 和下一交易日 928」逐位吻合。这就是展示层 bug 的完整表现链:空计划日无 plan → 无 buy_date → 旧产物缺"9-24 是交易日"信息 → 前端吞日。
- 空计划展示文案(L14772-14774 `当日无计划(空)`、L14869/14881「🟢 今日 · 无计划」/「🔜 下一交易日」):
  - **「确实无信号」与「链路故障」两种情形前端显示一样**(都显示"无计划")——这是现状,区分手段在通知链路:故障=severe 告警邮件(notify.py --severe + latest.md 镜像 + 退出码非 0 + 次日计划生成失败告警),正常空=「明日买入计划 T(空)」普通邮件。
  - 建议(可选,不做强改动):若想前端区分,可在 plan_doc 里带一个哨兵如 `"empty_reason"`(如 "no_usable_buy_signal")供前端角标,但此信息对用户价值有限,主渠道仍是邮件通知;是否做由主控/用户拍板。

## 6. 诚实标注(无法证实/推断部分)

1. **9-23 22:30 时点 6 条信号的完整逐条组成无法还原**(推断:6 条=2 条 cgb_10y_etf 买信号 + 4 条非买信号):生成器日志只打印"未入样宇宙"行,非买信号静默跳过不打印;DB 已被 9-24 状态覆盖无历史版本。但**可确证的部分足以定性**:买信号候选只有 cgb_10y_etf(日志打印)且无 ETF(未入样宇宙)→ kept=0 有完整打印链。
2. **hk_cesg10 buy 是晚到信号**(判定:9-23 22:30 日志无它的任何打印,而现在 DB 有它;它是 RSI 上穿 30 的信号,9-24 才出现在 9-23 名下)→ 固化时按「晚到剔除」正确排除(与首页冻结快照同口径,防前视);且它无跟踪 ETF(board_etf_map 无 hk_cesg10 键),**即使当时可见也入不了样**,不影响空计划结论。
3. **本地 DB 停 9-17**(signal_daily 最近 20260917),无法本地重验 9-22/23;云上 DB 为生产权威,已验。
4. **9-23 21:24 手动运行的触发源未查**(可能为人工/deploy 链触发):不影响结论——21:24 与 22:30 两次独立运行主链结果一致(均空)。
5. 今晚 22:30 产物"大概率仍空"是**预测**(基于 18:55 的 DB 信号集),存在晚到信号补入的不确定性(历史上 9-22 sz_div 是 9-23 17:50 才补入);但买卖信号判定在 22:30 已相对稳定,且唯一买信号 cgb_10y_etf 无 ETF 的格局不变。

## 7. 结论与建议

- **根因定性**:9-24 没有计划 = 9-23 当日确实无(可入样)买入信号的**正常业务判定**;前端"停在 9-23/下一交易日 9-28"= 空计划日 + 旧产物缺日历元信息导致的**展示层吞日缺陷**(已修 commit 4e958566f:生成器写元信息 + 前端读元信息;云上 main 已含,前端已上线)。
- **今晚 22:30 后验证点**:产物应变为 `{"date":"20260924","today":"20260924","is_trading_day":true,"next_trading_day":"20260928","empty":true}`(若 9-24 无新买信号);前端应显示「今日 · 无计划 · 20260924」+「下一交易日 · 20260928」。可加 smoke 校验(产物含元信息字段 + 前端串)。
- **无需修复项**:空计划本身不是 bug,勿加"强制出计划"类逻辑;晚到信号(hk_cesg10)即使补计划也无 ETF 可买,无收益。
- **可选增强**(需用户拍板,非必须):空计划日通知邮件的标题已带「(空)」,若想让页面也区分"规则性空仓 vs 链路异常",可加哨兵字段,低优先。
