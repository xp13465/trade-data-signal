## 三、缺口与诚实标注

1. 00:00 轮的 `reason`(=daily-first)为**反推**(落盘不含 reason 字段):依据 = 迁移期无 items + signature==prev_signature + last_alert_date≠today + last_added_* 空,按代码分支逐条排除后唯一自洽(§2.5b-4)。直接可见的硬事实是:新 schema 落盘 + last_alert_date 跨日滚动 + 该轮真发(critical 升级)。
2. 23:45 轮及更早(旧码)的 sig 内容已被 00:00 轮覆盖,不可回看;旧版行为仅由本机 `git show 2920d5d11~1` 对照确认(字段集差异成立,其「历史落盘长什么样」不再可考,不影响结论)。
3. 取证窗口(00:03–00:10)内未到 00:15 轮,故无「00:15 轮样本」;不对未发生的事作断言(下一窗口观察点见 §2.5d)。
4. 任务书假设「check_failed_units 有独立 systemd unit」与实际不符:实际为 trade-schedule-monitor 链内 15min subprocess 调用(§2.5a)。「下次触发时点」以 `trade-schedule-monitor.timer` 为准。
