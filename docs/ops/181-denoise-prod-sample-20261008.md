### 5.2 机制(代码 + 时序,构造性论证)
- 轮标识 = `gen_schedule_stats.py` 的 `EXTRA_MARKER_SCANS[fetch_news].last_run` = **日志文件 mtime(分钟精度)**,而 skip 窗口 = [最后一条 `[fetch_news] 已写` 行, EOF)。
- fetch_news 每轮 `:01/:45:00` 先写 `轮次开始`(**flush=True,立即刷新 mtime**),数十秒后才写 `已写`(开新窗口)。
- monitor 在 `:45` 的 tick 与 fetch_news 的 `:45:00` 轮**同秒起跑**(该 tick 先跑完多任务检查才到 r2-skip 块,读时 mtime 已被 `轮次开始` 刷新)⇒ 读到的组合 = 「**窗口仍指上一轮(含 SKIPPED_LOCKED)、mtime 已是新值**」⇒ `fresh ✓ / same_round ✗` ⇒ **+1 幻影**。
- 该读法对链 E 是**唯一自洽解**:dup(15899) 已证明状态里 `last_round` 就是 01:01 轮的 mtime(`01:02`)⇒ SEVERE 行前的那次 +1 必须来自「窗口=01:01 轮 + mtime≠01:02」,而 01:45 轮本身 R2 同步 OK(窗口无 skip、不可能 +1)⇒ 只能是竞态窗口。(链 F 同构。)
- ⇒ **现网实际阈值退化为「2 个连续真 skip 轮」**(设计意图 3 轮),`①d` 单测只覆盖「同轮同 mtime」场景,未覆盖「窗口=上一轮 + mtime=新轮起跑」这一组合。
- 判定:dup 去重本身 6/6 正确、封数大幅下降均成立;但**阈值语义被幻影 +1 稀释**,两封 SEVERE 属设计意图下的假阳性 ⇒ 按 §23.7 冻结契约(上帝已上线行为)上报用户拍板是否后续修(方向:轮标识改用 `轮次开始` 时间戳——`gen_schedule_stats.py` 已有 `round_begin_re`;或对 (窗口, mtime) 加一致性校验 + 补边界竞态 fixture)。**本 agent 只读、不改码。**

### 5.3 证据口径说明(诚实边界)
