## 一、渠道定名(定了就别再改)

飞书一共四个群,名称沿用现状,这次只是**正式定名**并写进文档(零迁移、零新群):

| 群 key | 定名 | 装什么 |
|---|---|---|
| `report` | **业务渠道(报告群)** | 买卖点信号(盘后+盘中)、汪汪队信号、盘中异动、每日速递 |
| `follow` | **业务渠道(跟单群)** | 次日买入计划、次日伪跳空剔除 |
| `alert` | **故障渠道(告警群)** | 系统故障、恢复、监控、摘要、R2 锁跳过、冻结表缺失等 |
| `agent_done` | 完成通知(第三类,维持现状) | agent 任务完成 |

判断规则(唯一权威,写在 `scripts/notify.py:835` `_resolve_feishu_chat_key`):
显式声明的群 key 优先;**没显式声明时按主题里有没有 `[告警]`/`[恢复]`/`[监控]` 字样猜**——这就是这次要
消灭的"猜",业务出口和已知故障出口现在都显式写了。

## 二、为什么必须修:实测证据

- **故障落到业务群(真实发生)**:台账 12 行 / 6 天,全是这两类——
  - 「R2上传异步锁跳过」×6(`scripts/r2_upload_async.sh` 每 6 小时一条,主题无 `[告警]` ⇒ 兜底进 report 业务群);
  - 「[kelly] 冻结表缺失历史信号事件」×6(`backfill_metrics.sh`×3 / `public_fund_full.sh` / `public_fund_quarterly.sh` / `notify.py`)。
- **反方向的风险**:业务消息若带了 `[告警]` 字样就会进 alert 群,而告警群受"域聚合 + 当日预算 + 摘要"三套
  抑制链管辖(`notify.py:1241` / `:1274` / `:1332` 三处 gate **都只认 `_grp == "alert"`**)⇒ 业务信号可能被
  并进告警摘要、**从报告群消失**。现状"抑制不碰业务"全靠"路由没猜错"这一条假设撑,不牢靠。
- **业务/故障在飞书侧本来就没混**:台账实测业务 153 行全落 report(148)+follow(5),故障落 alert。这次是
  把"巧合正确"变成"结构正确"。

**注意 F3 前提订正(诚实标注)**:264D 报告 F3 写「前端=单开关(业务与故障弹同一手机横幅)」。实测**不成立**:
前端数据源是 `static-site/data/notifications.json`(由 `scripts/export_notifications.py` 生成),内容只有
业务/行情事件(买卖点/异动/预警/恐贪/涨停潮/收盘速递),**没有任何故障流**;`sw.js` 也没有 push 监听。
所以本轮的④前端开关做成了**业务分类开关**(3 类:买卖点信号 / 异动与市场预警 / 收盘速递),不是"业务 vs 故障"开关。

## 三、台账 group 口径(事项 3,⑤)

- 现状病灶:`notify.py` `send_to()` 台账把 `feishu_group` 原值直接当 `group` 记,订阅推送没传 ⇒ 落 `None`
  (台账实测 5 行 group 空值,alert_meter 侧被归到 `unknown` 桶)。
- 修法:台账 `group` 一律记**实际落群**,取值优先级 = CLI 传入(`ledger_group`) > 出口显式声明(`feishu_group`)
  > 主题文本推断兜底。改在 `scripts/notify.py:1354-1359`(send)与 `:1395-1398`(send_to)。
- **口径订正(与 264D 原文的偏差,请主控/审查留意)**:264D §六5 原文写"随 D 一并修(**填 business**)"。
  本轮**没有**填 `business`,而是填**实际落群 key**(`report`/`follow`)。理由:
  ①`group` 字段的语义就是"实际落进了哪个群"(`alert_meter.py:163/180` 按它做桶),
  ②台账 `group` 的值域现为 {report, follow, alert, agent_done},填 `business` 会多出一个**不对应任何真实群**的值,
  实发 report 群却记 business = 新的"台账与真实落群不一致"(正是本条要修的病);
  ③业务对账口径本来就是 `group ∈ {report, follow}`(264D §五)。
  若坚持"business"语义,建议**另加字段**(如 `kind=business`)而不是复用 `group`——留主控拍板。

## 七、验收口径:两个口径分开写(F4 订正)

## 十、本轮的"行为影响"诚实标注(请审查/主控留意两条)
