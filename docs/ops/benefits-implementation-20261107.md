# 业务质量与收益验证实施交接

用户本次明确授权 Codex 在独立分支接管业务实现，Claude 负责独立复核、合并与部署。该授权不改变日常外审分工。本分支基于完整监控实现及 systemd 249 凭据兼容补修，不以已经提交、收到协作回执或本地测试通过代表生产已生效。

## 本次解决的问题

1. 四维风险评估缺少输入时，原先缺项按零参与完整综合分，可能产生具有误导性的低风险描述。修复应区分完整分、部分信息与不可评估，同时保留单维异常检测。
2. 每日风险序列的缺实盘兼容值 40 曾经由用户冻结，不能批量改写历史数值。本次保留该值，并用可评估状态及同日、同窗口、同筛选范围的来源证据决定是否绘制风险点；真实有效的 40 分仍须显示。
3. 任务退出成功、通知被通道接受、文件存在，都不等于业务按时交付。本次补充生产者输入输出身份、交付归一化、私有持久化、比较工具与面板状态，避免把运维活动量直接写成业务收益。
4. 数据库备份与冻结表、映射及必要配置需要按同一捕获集合校验。数据库单文件完整，不代表回放依赖完整；隔离恢复通过，也不等于异地副本和生产消费者已验证。

## 验收原则

- 完整有效输入的风险计算权重、阈值及既有数值契约保持一致。零值有效；缺失、非数值与非有限值不得当作有效零值。
- 同一逻辑交付批次的重跑保留独立尝试证据，不能扩大交付分母。阶段间拼接必须有实际内容身份关联，不能只按同一天凑齐。
- 历史原始到达时间无证据就保留未知。不得用文件修改时间、当前重算结果、当前映射或同日另一信号替代历史原事实。
- 采样有固定来源、字节和时限预算，不能挤占既有监控上传预算。私有证据不得进入公开静态目录、公开对象存储、浏览器持久存储或日志正文。
- 收益测量不新增业务告警。既有通知链继续承担告警，即使其他告警范围显式设为 all，收益测量记录也不自行发业务通知。
- 新功能默认关闭，未配置或未迁移时明确显示未配置，并保留原监控功能的兼容性。
- 本地测试可用明确标注的合成数据验证功能；合成结果不能当作真实收益。自然形成的前后各十个实际交易日、固定口径、封闭分母、版本及来源证据不足时，比较结果必须是 not_ready。

## Claude 接力顺序

1. 固定本分支最终提交，复核完整差异与原始测试结论；本分支包含前置监控实现和凭据兼容补修，应按提交图处理，不整文件覆盖其他开发分支。
2. 先完成 systemd 249 兼容补修的真实停用安装和实读快照对账，步骤见 [监控部署说明](../../ops/monitoring/DEPLOY.md)。现有云端快照与新 canonical 暂时不一致，应由现场实读解决，不修改门禁来放行。
3. 复核并合并后，从同一已审核源部署 Worker、独立 OPS_DB 迁移与私有采集配置。先发布或同时发布新版前端，再生成新版风险 JSON；旧前端仍可能把保留的兼容 40 当作可评估点。业务证据开关、收益持久化开关及告警开关分别验收；不要一次打开真实通知来测试功能。
4. 核对实际运行代码、输入范围、交易日历、截止时间及生产消费者证明，再开启证据采集和收益测量。策略与交易日历缺失时保持未就绪，禁止事后补一份配置把原未知记录写成历史成功。
5. 以真实采样 ID、生产者回执摘要、Worker 持久记录及面板结果交叉对账。API 可读或采集进程运行成功不能单独作为业务已交付的验收依据。
6. 保留自然观察窗口。按交易日补齐观察结果后再解释成功率变化；人员耗时没有实际记录就不估算节省工时，描述性差异不直接归因为本次改动。

本文件描述交接与验收边界。字段、命令及部署选项以同分支的 monitoring 契约、收益接口说明和恢复说明为准；最终验证报告需固定提交、测试原始数字和证据摘要。
