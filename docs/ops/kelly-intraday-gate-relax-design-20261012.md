## 一、放宽方案总体设计:三者判定顺序与优先级

**一句话总架构:分层三闸分工——逐码判据做精细分类、日级 (R,D) 粗闸兜底、源健康报警独立(A3 线)。豁免是覆盖层(overlay),只调制"已确认过的面"的告警等级,永远拦不住新码/新类/新面。**

固定判定管线(优先级从高到低):

- **P0 逐码分类(绝对前置)**:每只缺口码判 `zero_volume`(两源 [30]==今日 且 今开==0,即"09:40 前零成交")/ `unfetchable`(源挂、时间戳不可证实)。分类不可算/不可证实 → 一律归 unfetchable(保守)。**类别不可得的运行,豁免与阈值闸均不得放行**(C1 前置契约:须先产出机器可读报告 `data/kelly_intraday_gate_report.json`,含逐码 class+evidence+ratio+main_source_ok——报告与豁免必须同批上线)。
- **P1 豁免查表(overlay)**:命中已确认问题面 → 按类分级(零成交类 → 放行+完全静默,仅 info 留痕;取不到类 → 放行+降级 WARN 长窗去重,**永不静默**);未命中 → 进入 P2/P3。豁免码建议从 P2/P3 的缺口分子中剔除(口径待拍板,见六)。
- **P2 单日比例闸**:剩余 ratio > R → 保持现行 fail-closed(raise → exit5 → 整轮跳过)+ WARN 即时;ratio ≤ R("容忍带")→ **放行出档**(带上"N 只未定价"meta),进入 P3。
- **P3 累计天数闸**:容忍带 `0<ratio≤R` 连续 ≥D 个"运行日" → 持续告警(**仅通知,不回溯阻断**;出档已放行)。连续计数/恢复清零规则照抄既有 `alert_denoise_rules.py:344-391` 模板,按运行日计(锁跳过轮不计数,交易日间隔复用 `check_data_gap_alerts.py:1033-1042`)。

三条关键权限边界(回答"谁先判/谁压谁"):

1. **分类 > 豁免 > 单日 > 累计**。P0 无法分类的码不得进豁免通道;豁免命中即不再触发 P2/P3;豁免失效/未命中才走 P2/P3。
2. **单日大缺口(>R)永远阻断**,任何豁免之外的东西都不能绕过(P1 命中除外,且 P1 对取不到类也只降级不静默)。
3. **"问题面变了"语义落地为一条硬规则**(消解 C2 指出的 C1 §1.3↔§2.2 二义):曾命中过豁免的面出现**新成员/新类别** → 当日**强制至少 WARN 一次**(附"扩面"命令),不等 D 天,直接对应"重新确认";**从未有豁免的全新面** → 走常规 P2/P3(容忍带 + 累计 D)。

两个边界形态必须显式定义(不在阈值网格口径内):

- **target=0 空轮**:建议 = 无对象可缺 → 正常空档 exit 0,不告警不阻断。⚠️ 但 B2 实测:现行 HEAD 两条分支(主源正常 :828-829、兜底空集 :917-920)**均会 raise**——现行码对空档日会新出 exit5;生产 09-24/09-28 当年"通过"只靠旧版偶然路径(A1 栈 6①)。实施时必须先修/定此语义并实测。
- **n<3 且缺=全部**:走绝对数判据单列(A4:全史 3 个 100% 日全部 n=1,比例指标在 n≤2 失真;n=1 的 100% 与整源挂不可区分)。

接入形态(M1/M2 双模式,C1):M1(未治本,现值)decider 挂 `scripts/kelly_intraday_rerun.sh:102-121` 出口决定告警等级,**对账 FAIL(exit3)/超时(142)/SEVERE 链不动**;M2(治本后,零成交不拒+meta 发布)decider 对每次运行报告评估。**强烈建议:放宽与治本(零成交类不拒、带"N 只未定价"meta 发布,#254 处置方向①)同批上线**——理由见第五节第 4 条(这是最重的坑)。

## 二、阈值推荐 + 数据支撑(含"数据不够"的诚实标注)

**先说缺点:推荐值不是数据推出来的,是"机制论证+保守区间+待验证假设"。** 事件基座太薄(B2 证):真实生产闸事件全史仅 **5 次**(09-17/09-23/09-30/10-08/10-12),其中 2 次不可细分(09-23 无码表、09-30/10-08 旧版"首码即 raise"清单不可重建,仅下界),逐字全量对照只有 10-12 一次;跨事件同面复发仅 164508×1 次(10-08∩10-12)。任何"<5 事件即不成立"的精确点都不能声称已由数据验证。

**样本底数(可追溯 A4/B1)**:重建序列 113 个运行日(2026-03-30~10-12,约 5.4 个月),缺口日 11 天(9.7%),ratio 序列 = [100, 33.3, 16.7, 14.3, 100, 20, 100, 33.3, 8.7, 13.3, 8.3]。生产实测侧(A1):云日志 09-14 起 15 个交易日/14 次实跑(09-29 锁跳过),exit5 ×4(09-23/09-30/10-08/10-12)+ 对账 exit3 ×1(09-17);成功日缺失恒 0 是**构造保证**(任缺即 raise 自 09-08 首发版即存在),不能当"正常日子缺失≈0"的样本。分母口径修正(B2):A4 重建靶数 vs 生产"批量加载"在 5/14 云日不符(09-17 23vs22、09-18 7vs6、09-21 5vs3、09-24 1vs0、10-08 15vs14)→ **10-08 真值 ratio = 2/14 = 14.3%(非 13.3%)**,涉重建分母的格值需附 ±1 码区间。

**缺陷先列(逐条具体):**
1. 精确点 (R=15, D=5) 的边际全压在 ≤4 个事件上;R 13→14 的边际是 1 个生产事件(10-08)、14→15 是 1 个重建事件(08-12);D=5 在 R=15 的样本内与 D=3/4 完全同值(容忍带最长连续=2 天,B2 机检 runs=[1,2,1])——**D=5 零区分力,是用户"一周"口径的产物,不是数据的产物**(这项明确标注为**待验证假设**)。
2. 旧 B1 敏感性表述有误已修正:D 1→2 翻转 = 2~5 天(建议区)/6(R=50)/9(R=100),非"2~4";D 2→3 = 0~1 天。
3. R=10 与用户示例"10% 以内不告警"存在偏离:10% 会拦 10-08(13.3/修正后 14.3)等 2 日——**10 还是 15 交用户拍板**(B2 fix)。

**推荐(区间提案,非精确点)**:
- **R = 15%(主推),备选 10%**。理由:①硬下界由两个最新实测事件钉住(09-30=8.7、10-12=8.3),R≤8 连它们都拦(仍在被抱怨形态内);②R≥14.3(修正后)才放过 10-08,故 R=10 只解云时代 4 次 exit5 中的 2 次(09-30/10-12),R=15 解 3 次(09-23=100%/n=1 仍拦);③15~25 间多放过 16.7(n=6)/20.0(n=5)两类小盘零成交日,避选 20(09-08=20.0 恰卡线)与 33(距 33.3 仅 0.3)。置信度:R 下界(≥9)高(8.7/8.3 实测钉住);R=15 附近中(4 个缺口日支撑,其中 2 个逐字生产核实、08-12 为重建);**R>20 低(样本内零触发,纯结构性,属待验证假设)**。
- **D = 5 运行日(贴用户"连续一周"口径),备选 3**。⚠️ 明说:**数据不够,这是待验证假设**——历史窗内连续容忍带最长仅 2 天(R=15)/3 天(R=50),D=5 零触发;其作用是防"小比例慢性缺口长期化",只能上线后积累验证。
- **R=50 极简档**(只拦 n=1 的 100% 日)、**R=100 禁用**(无单日闸,总崩日全放过,无防护)——仅供"只关心极端日"时选择。
- 上线后 **1~2 个月重跑本矩阵回归**,校准 R/D(尤其 D 的实际翻转率)。

**敏感性(修正后,B1+B2)**:R 邻域翻转:8→10 翻 {09-30,10-12};10→15 翻 {10-08,08-12};15→20 翻 {07-31,09-08};20→25/33 翻 0;33→50 翻 {06-12,09-29};50→100 丢全部防护(禁)。D:1→2 翻 2~5/6/9;R=15 时 D≥3 无差别;D≥5 全网格无差别(仅 R=50 时 D=3→4 翻 10-08)。脆弱点:09-08=20.0 恰卡网格 20(严格'>'刚放过);33.3 距 33 为 0.3;8.3 距 8 为 0.3;14.3 距 15 为 0.7;100% 三天全 n=1。

**一条决定阈值的硬事实(证伪 B1 假设,必须写进公示)**:源挂日 ratio(100(n=1)/8.7/13.3/8.3)与零成交日 ratio(8.3~100)**完全重叠**——"源挂≈100%"不成立(因兜底链把其余有成交标的全补上,残余缺口只剩零成交尾部)。**比例阈值不能区分成因,分类职责归逐码判据**;整源全灭日任何比例阈值都拦不住,须保持 fail-closed 或走重试/时点后移。另:09-17 旧事件(1/22=4.5%)在现行逻辑下 ratio=0(160717 有成交且已被兜底覆盖),不在阈值作用面。

## 三、豁免标记最终设计(含自动失效条件)

**先说缺点:** ①底座选型论证被 C2 证伪——C1 用的 12 个面里 7 个从无闸事件(0331/0612/0731/0812/0903 早于 09-08 功能上线,0908 无日志,0929 当日无 run),"精确集合 ≤5 日窗 0 组"论证不成立;**"数据选型"改为"机制论证"**(子集匹配=防 narrow-after-wide 反复 nag)+ 保守参数 + 可回退开关。②"精确匹配是死设计"不成立,须订正:60d TTL 尺度内 {159501} 精确复现过(8td/33td ≈ 12cd/48cd < 60cd;C2 修正:原写"49 交易日"实为 **33 交易日**,49 是自然日)。③同形不同因残余风险见下第 5 条。

**问题面(豁免身份)最终定义**:四元组 `(codes 码级集合, 逐码类别, band_cap 量级带, src_ctx 源上下文 {main_source_ok, fallback_used})`。
**匹配规则 = 子集命中**:`F.codes ⊆ E.codes`(允许缩减)+ 逐码类别一致 + src_ctx 一致 + `r ≤ band_cap` + 未失效未过期;**新增成员 = 不命中**(且按第一节硬规则当日强制 WARN);集合缩减 → 命中(窄化不引入未知,设计接受);旧豁免记录保留(防 whack-a-mole),扩面确认 = 新记录 supersede 旧记录留档。
band_cap = max(R, 确认时比例);**地板告警与 band 解耦(C2 修正)**:`k≥3 无条件 WARN` + `r≥50% 超带必 WARN`(防止 band_cap 被确认时吸收到 ≥50% 时地板不可达)。

**分级生效(绝不无条件静默)**:零成交类豁免命中 → 完全静默(仅 `info_log.jsonl` 一行,仿 schedule_monitor ack 模式);取不到类豁免命中 → 降级 WARN(`--tier warning --dedup-key kelly_intraday_rerun_fail --dedup-window 1800` 长窗去重,建议 7 天)+ 短 TTL(建议 14 天,待拍板);带外/新成员/类变/源变/到期 → 自动失效并恢复原分级,通知正文必带"原豁免 <id> 已于 <时间> <原因> 失效"。**取不到类是否允许豁免**(C1 未定项 3)= 拍板项,默认"可豁免但永不静默+14d TTL",备选"完全不可豁免"(照 `check_data_gap_alerts.py:536` 先例)。

**自动失效条件(终版五维,全部运行时机判,不靠人记)**:
1. **集合新增成员** → 不命中 + (曾命中的面)**当日强制 WARN** + 附扩面命令;旧记录保留待 supersede/revoke。
2. **类别变化**(任一覆盖码本次类别 ≠ 确认时)→ 立即 `invalidated:class`。
3. **源上下文变化**(main_source_ok / fallback 使用态 vs 确认时快照)→ 立即 `invalidated:source`。⚠️ 残余:封禁已持续 21 天+,src_ctx 失效要等主源恢复才触发 → 文档必须写明"封禁长期化时静默上限 = TTL"。
4. **量级超带**(r > band_cap)→ 单次 WARN + band_strikes+1,连续 ≥2 次 → `invalidated:band`(小分母抖动单次不杀)。
5. **TTL 到期** → 建议 60 自然日(**待拍板**),**固定从确认日起算、命中不自动续期**(防"临时问题悄悄转永久");到期后下一次命中形态运行 WARN 一次"需重新确认",不轰炸。
(另:用户撤销 → revoked;扩面 → superseded。)

**同形不同因(必须拍板)**:停牌/清盘/流动性枯竭 vs 封禁期零成交,`[30]==今日 且今开==0` 对二者同样成立,**无任何自动失效维度**(C2)。落地要求:确认卡与设计文档明示"问题面 = 观测形态,不区分原因"(§23.13 语义锚点请用户确认);或加"命中累计 ≥N 次/≥M 运行日且无源侧新证据 → 强制降级提示一次"的长期静默出口(参数待拍板)。

**存储与审计**:单一事实源 `data/alerts/kelly_intraday_gate_state.json`(flock + tmp/rename 原子写,仿 `alert_ack.py:42-49,78-96`)+ 追加式 `kelly_intraday_gate_ledger.jsonl`;可选简化(C2):runs/persist 由 ledger 派生,避免双副本角色重叠。fail-safe:状态读失败 → 当无豁免(偏告警)+ 独立 WARN(dedup 24h)。确认/撤销 CLI `kelly_intraday_gate_ack.py`(confirm/--list/--clear `<id>`)。

**§23.7 闭包(C2 补)**:本机制参数(TTL/band/faces/类集合)实施即冻结、后续变更须用户确认;**M1 下静默的完整语义必须明示 = 盘中档增量持续不生成 + 无告警**(不只是"降噪",是功能停摆转入隐形)。确认卡类语义写"09:40 前零成交"而非"当日零成交"(豁免范围不同);V2 判据上线前做多日+多形态实测(09:40 实测时点、159513 式 10:31 延迟首笔、长期零成交/停牌型)。

## 四、两个附带问题的结论

### 4.1 主源 fail-open 风险:不存在(A2 已证伪),但留两条注记

- **结论**:零成交标的在东财 f17(今开)返回字符串 `"-"`(无值占位),**不是 0、不是昨收**——f18(昨收)独立有值(0.923/1.227/1.116),排除"f17 被昨收填充";有成交对照标的 f17=真实开盘价(159513=1.916,与腾讯 [5] 实测一致)。传导链:`-` → akshare `pd.to_numeric(errors="coerce")`(本机 akshare 1.18.64 `fund/fund_etf_em.py:161`)→ NaN → `signal_kelly_backtest.py:815-818` 的 `op>0` 为 False → 进 missing。**主源健康时零成交标的必然进 missing(:2061 raise),绝不会被当 >0 假值注入**;`op>0` 判定已充当"取值可信性"校验层,放宽方案**不需要**额外加校验层。
- **注记**:①clist 本体未直测(封禁期 RST 不可达),结论自同族 ulist 接口(f12/f17/f18/f297 字段编码完全同构)外推,非 100% 直证;②"零成交"边界情形(竞价有委托未成交/临停)未穷举,但若返回 0 同样被 `op>0` 挡掉,不改安全性结论。

### 4.2 源封禁单独立案:建议立,scope 收窄,与 #254/#252/#253 互链不合并
