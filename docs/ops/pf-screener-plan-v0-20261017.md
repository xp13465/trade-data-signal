### 1.3 关键机理与既有隐患(调研发现的三个事实, 直接影响筛选器设计)

1. **工作日与周日的行数双轨**: 日频评分只算「按规模降序头部 2000 只」(`public_fund.py:3596-3600` 宇宙选择), 周日才全量 27758(`pf_score_weekly.sh`)。而 D1 同步只取 MAX(score_date) 分区 ⇒ **周一至周六 D1 = 2000 行, 周日 = 27758 行**; 前端显示的"全市场约 2.7 万只"在工作日不成立(证据: 云上分区计数 20261012=2000 / 20261011=27758; deploy 日志 22:00 校验 "fund_score: date=20261016, count=2000")。**筛选器若建在当日分区上, 工作日会静默缩到 2000 只**。
2. **"胜率"已有一半**: `kelly_win_rate` 就是**月频 3 年胜率**(净值月末聚合算, `public_fund.py:2770-2787`), 已进 D1; 缺的是**多窗口/多频(季度、1y/3y/5y)正收益期占比** 这一族。
3. **行业覆盖只有主动权益的一半**: 行业配置来自季报 `fund_industry_alloc`(8201 只; 其中 混合型6767/股票型1030/FOF404), 占全部 28235 的 29.5%、占主动权益(16754 只)的约 47%; 指数/债券基金基本没有。行业筛选是"可选但覆盖有限"的维度, 前端必须把无行业数据的基金显式标注(不能默认隐藏)。

## 三、技术方案 v0

### 3.1 总体形态

```
数据层(本地 public_fund.db, 云上定时)
  ├ fund_basic 21列 ──┐
  ├ fund_performance  │  (各表取"每只基金最新可用分区")
  ├ fund_risk_indicator ├─► 新脚本 sync_fund_screener_to_d1(全市场 1 行/只, 平表)
  ├ fund_rating        │        └─► D1 表 fund_screener(约 55-60 列, PK=fund_code)
  ├ fund_purchase_status┤
  ├ fund_manager       │
  ├ fund_industry_alloc┤
  └ fund_score(评分)   ┘  (全量取最近全量分区 + 头部2000 用当日覆盖)
                     │
服务层  CF Worker  /api/fund_screener(新增端点, 复用 auth.js 登录特权)
                     │  GET: page/size/sort/dir/search + 多条件过滤器(白名单参数)
                     │  服务端 SQL WHERE(参数化), 返回 total + data + 命中分项计数
前端层  基金评分 > 场外基金 tab
                     └► 顶部"筛选"按钮 → 筛选面板(桌面内联/移动底部抽屉)
                        → 条件 chip(可删/清空) → 列表复用现有组件(50/页)
                        → 行点击=现有详情弹窗
降级链  API 失败 → 现有 fund_score_top.json Top100 兜底 + 明示"降级态, 筛选不可用"
```

**为什么走 D1 服务端筛选(而不是静态 JSON)**: 全市场 28235 只 × 约 50 字段, 按现有 fund_score.json 实测约 1.1KB/行 ⇒ 全量 JSON 约 30MB(压缩后约 3-6MB), 与项目性能准则(内存/首屏优化待办)冲突且移动端负担大; D1 服务端 WHERE+分页是 #79 已建成并验证的路径(单查询 <100ms 量级), 且**不受 R2 故障影响**(D1 是独立服务, 现状已验证 Worker/D1 通: `/api/fund_score` 正常返回 401 鉴权响应)。

### 3.2 指标集(propose 默认集, 待用户 veto/增删)

**筛选条件(按组)**:
1. 基础: 基金类型(多选, 现有类型分布 15+ 类)、基金公司(搜索选择)、成立年限(区间, 由 setup_date 推导)、规模区间(亿元)、申购状态(开放/暂停/限大额/封闭)
2. 收益: 近1月 / 近3月 / 近6月 / 近1年 / 近3年 / 今年来(区间阈值)、成立以来(阈值)
3. 风险: 年化波动率(1y/3y)、最大回撤(3y)、夏普(3y)、索提诺、卡玛、信息比率
4. 评分: 综合评分区间、6 维子分区间(业绩/风险调整/回撤控制/稳定性/规模流动性/费率)、星级
5. 经理: 经理评分、任职年限、从业年限、在管规模、历史最佳回报
6. 费用: 管理费、托管费、申购费、销售服务费(区间)
7. 评级: 任一机构评级 ≥4 星 / 5 星家数 ≥N / 晨星评级 ≥N
8. 盈利比例: 月频 3 年胜率区间(已有); (二期)季度/年度正收益期占比
9. 行业(二期): 第一大配置行业(多选) + 该行业权重阈值; 无行业数据基金显示分组"无行业数据"
10. 仓位类: 半凯利仓位区间、建议仓位区间(已有)

**排序**: 上述数值字段全部可排序(白名单拼接, 防注入, 沿用现有模式 `worker/fund_score.js:26`)。

**默认展示列**: 代码/名称/类型/综合评分/星级/近1年/近3年/最大回撤3y/夏普3y/规模/经理/任职年限/建议仓位(与现有行渲染逐字段兼容, 只增不减)。

### 3.3 分期

**一期(最小可用, 建议范围)**
- D1: 新建 `fund_screener` 平表(全市场 1 行/只)+ 新同步脚本(取各表最新可用分区; 评分字段用"每只基金最近可用评分"解决工作日 2000 只问题)。
- Worker: 新端点 `/api/fund_screener`(登录特权同 fund_score), 支持 3.2 中 1-7 + 10 组条件(服务端 WHERE), 保留现有 /api/fund_score 行为不变(§23.7 冻结契约)。
- 前端: 场外基金 tab 顶部加「筛选」入口 + 面板 + 条件 chip + 结果计数 + 复用列表现有组件; API 失败走现有 Top100 兜底并明示。
- 数据链路: 同步脚本挂到 pf-score-daily(16:00 后)末尾; 失败不阻塞主流程 + 告警(沿用既有模式)。
- 覆盖标注: 每个条件旁展示该字段的数据覆盖率(如"行业: 8201/28235 只得季报数据"), 空值基金在"不设该条件"时不隐藏、设了该条件时给出"另有 N 只因该字段缺失被排除"的显式计数(防 §23.6 式"入样宇宙静默缩水")。

**二期(完整版)**
- 新增计算字段: 多窗口正收益期占比(月/季/年, 1y/3y/5y, 由 fund_daily_nav 计算)+ 成立以来年化 + 滚动 12 月胜率。
- 行业维度筛选落地(含口径公示)+ 行业权重排序。
- 评级变化(两次评级对比)、经理更替近期变化。
- 条件预设(如"稳健债基""长期权益")+ 条件保存/URL 分享(hash 参数)+ 结果导出(需定口径)。
- 基金对比(2-4 只并排关键指标)。
- (评估后)换手率、逐只重仓股重叠度: 需先补采集, 单独评估, 不在一二期硬塞。
