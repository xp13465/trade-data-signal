# 凯利回测费率客调快捷键预设档

> 调研产出（只调研不改代码）。供实施 agent 用：在信号凯利回测（sigkelly）条加费率预设档快捷切换。
> 调研日期：2026-08-08 ｜ 数据来源见文末

## 1. 背景与现状

### 1.1 凯利回测买什么
- **信号凯利回测**（`scripts/signal_kelly_backtest.py` → `static-site/data/signal_kelly_backtest.json`）：每指数取 track_score 第一名 ETF 作 `best_etf`，信号日收盘买 `BUY_AMOUNT=10000` 元该 ETF，按 6 种卖出模式（A 固定10天 / B 3% / C 5% / D 7% 止盈或满期 …）半凯利仓位回测。
- 前端渲染：`static-site/lab.js` `renderSigKellyLab()` / `_renderSigKellyBar()`（sub tab `sigkelly`，6象限×4模式×3周期）。
- **结论：凯利回测买 ETF，费率以 ETF 结构为主。ETF 无印花税。**

### 1.2 当前费率（simulate_trade.py L44-47，signal_kelly_backtest.py 复用）
```python
COMMISSION_RATE       = 0.0003   # 佣金万3（单边）
SLIPPAGE              = 0.001    # 滑点千1（单边）
MIN_COMMISSION        = 5.0      # 最低佣金5元/笔（不免5）
TRANSFER_FEE_RATE_SH  = 0.00001  # 沪市过户费万0.1（仅沪市ETF 51/58开头）
# 无 stamp_duty（印花税）参数 —— ETF 免印花税，当前未实现该参数
```
- signal_kelly_backtest.py L42 `from simulate_trade import COMMISSION_RATE, SLIPPAGE, MIN_COMMISSION, TRANSFER_FEE_RATE_SH`，并在 JSON `config` 段原样输出（L735-738）。
- 前端 app.js L18600-18616 infoBar 已能读 `commission_rate/slippage/min_commission/transfer_fee_rate_sh` 显示「费率: 佣金万3 + 滑点千1 + 沪市过户费万0.1（最低5元/笔）」。
- **费率当前在后端生成 JSON 时固化，前端无客调入口。** 本预设档为新增「前端快捷切换」功能提供数据。

### 1.3 费率结构：ETF vs 股票
| 费种 | ETF | 股票 |
|------|-----|------|
| 佣金（券商收，单边） | 各券商不同，万0.1~万3 | 万0.75~万5 |
| 最低佣金 | 免5 / 最低0.1 / 最低5 | 免5 / 最低5 |
| 滑点（市场摩擦，非券商费） | 千1（ETF 流动性好） | 千1~千2（个股流动性弱） |
| 过户费（沪市收） | 沪市ETF 万0.1；深市ETF 当前代码不收 | 沪深 万0.1（2022-04 统一） |
| **印花税（国税，卖方单边）** | **免征** | **万5（0.05%），2023-08-28 减半后** |

> ⚠️ **印花税率重要提示（需用户确认）**：用户给的数据为「印花税千1（0.1%）卖方」。据行业常识，**2023-08-28 起证券交易印花税减半征收**，由千1（0.1%）降至 **万5（0.05%）卖方单边**。当前（2026）应为万5。本预设档「股票默认」采用 **万5**（现行率）；若用户确认仍用千1，请在自定义档修改。web search 受 US-only 限制未能联网核实此政策时点，此结论基于行业常识，建议用户最终确认。

## 2. 预设档清单

6 档（5 预设 + 1 自定义）。ETF 档印花税恒为 0（免税），股票档含印花税供 what-if 对比。

| # | 档名 | 佣金率 | 最低佣金 | 滑点 | 过户费(沪) | 印花税(卖) | 适用场景 |
|---|------|--------|----------|------|-----------|-----------|---------|
| 0 | **0%剥离** | 0 | 0 | 0 | 0 | 0 | 看纯信号 alpha，剥离一切摩擦 |
| 1 | **ETF默认**（当前） | 万3 (0.0003) | 5元 | 千1 (0.001) | 万0.1 (0.00001) | 0 | 未议价默认，保守上限 |
| 2 | **ETF主流** | 万0.5 (0.00005) | 0.1元 | 千1 (0.001) | 万0.1 (0.00001) | 0 | 互联网券商议价后常见 |
| 3 | **ETF最便宜** | 万0.1 (0.00001) | 0（免5） | 千1 (0.001) | 万0.1 (0.00001) | 0 | 激进低费率，VIP/促销档 |
| 4 | **股票默认**（对比） | 万5 (0.0005) | 5元 | 千2 (0.002) | 万0.1 (0.00001) | 万5 (0.0005) | what-if 个股回测对比，非凯利实买 |
| C | **自定义** | 用户输入 | 用户输入 | 用户输入 | 用户输入 | 用户输入 | 任意费率组合 |

### 2.1 各档说明

**档0 0%剥离** — 全部归零。用于观察信号本身的毛 alpha，判断收益来自信号还是被成本吃掉。min_commission=0 表示无最低佣金兜底。

**档1 ETF默认（当前）** — 即 simulate_trade.py 现行参数，未议价的保守默认。万3 佣金 + 最低5元（不免5）对 1 万元单笔往返费率约 0.6%~1%（最低佣金占比高）。作为「悲观成本」基准。

**档2 ETF主流** — 用户给数据「ETF 万0.5 最低0.1起」。互联网券商（东方财富/华泰等）开户议价后常见档，免5（最低0.1元替代5元）大幅降低小单成本。对 1 万元单笔往返费率约 0.2%~0.3%。

**档3 ETF最便宜** — 行业最激进档：万0.1 佣金 + 免5（无最低佣金）。部分券商 VIP/促销/特定渠道可申请到。对 1 万元单笔往返费率约 0.12%~0.15%。标注为「最便宜可见档」，非所有用户可达。

**档4 股票默认（对比）** — 用户给股票数据「默认万5不免5」+ 印花税万5（现行）+ 滑点千2（个股流动性弱于ETF）。**凯利回测实买 ETF 不用此档**，仅供「若此信号买个股会怎样」的 what-if 对比。印花税卖方单边是股票相对 ETF 的最大额外成本（万5）。

**档C 自定义** — 5 参数全开放：佣金率 / 最低佣金 / 滑点 / 过户费 / 印花税率。覆盖任意场景（含用户若坚持印花税千1，在此填 0.001）。

### 2.2 设计决策
- **滑点跨 ETF 档恒千1**：滑点是市场摩擦非券商费，与券商档位无关；ETF 流动性好统一千1。仅股票档用千2（个股流动性弱），与 lab.js L2091 既有「低档=千1 / 高档=千2」约定一致。
- **过户费跨档恒万0.1**：过户费是交易所规费非券商费，各档不变。当前代码简化为「沪市ETF收、深市ETF不收」，预设沿用。
- **只设 1 个股票档非全套**：凯利实买 ETF，股票全套（默认/主流/最便宜）属 scope 蔓延。1 个「股票默认」对比档 + 自定义已覆盖所有股票场景。
- **0%剥离放档0**：用数字键 0 直觉对应「归零」。

## 5. 实施注意事项（架构决策点，供实施 agent 评估）

**核心矛盾**：费率当前在后端 `signal_kelly_backtest.py` 生成 JSON 时固化，前端客调切换需要「换费率→重算收益」。三条路径：

1. **前端纯展示客调（轻量，推荐起步）**：预设档切换只改前端显示的费率标注 + 对毛收益按档位费率做近似折算（往返费率 ≈ 2×(佣金+滑点+过户) + 印花税），不重跑完整回测。快但不够精确（最低佣金/分段无法精确反推）。lab.js L2083-2094 已有类似「毛收益→低档/高档」折算先例可复用。
2. **前端完整重算（精确，重）**：把 signal_kelly_backtest.py 的费率扣减逻辑移植到 JS，前端拿原始价格序列+信号重跑。需导出每信号 ETF 价格序列（数据量增大）。精确但工作量大。
3. **后端按需重生成（精确，需 API）**：加 `/api/kelly-backtest?fee_preset=etf_main` 端点，后端用选定费率重跑返回。精确但需后端计算资源+缓存。

**建议**：先做路径1（前端近似折算+费率标注客调），验证用户是否需要精确重算后再决定升级路径2/3。本档清单三种路径通用，不锁死实施方式。

**其他**：
- 算法公示同步（CLAUDE.md §21）：若 sigkelly 有费率说明文案，加预设档后同步更新公示（当前 lab.js L2091 成本档说明是 lab_simulate 的，sigkelly bar 暂无费率公示文案，实施时确认）。
- 数据一致性（CLAUDE.md §22）：若路径3后端重生成，确保前端标注费率与后端实际所用费率一致。
