# AI 预测自成长(反思总结)体系方案

> 2026-08-17 用户提出(原话要点):"现在每天 ai 预测有次日待回填功能。比如今天看上周五的预测大概率全失败了。回填失败后,不管是方向失败还是区间不精确,都应该有一个反思总结,这样才能让下次预测更好。自成长体系,比我一只给你传授经验要有用的多。"
> 状态:**Step 1 闭环已实施(2026-08-17)**;Step 2 周反思报告待主控派。2026-08-17 用户拍板"不等样本攒够,边做边改边校准边成长,闭环立即转起来",Step 1 已按此落地(详见 §6.6)。**Step 1 透明展示已落地(2026-08-17)**:本次预测实际注入的反思要点(样本数/方向失败数/最近样本日期+类型+归因)随 `meta.reflection` 归档进 `daily_brief.json`/`daily_brief_history.json`,前端所有 AI 预测展示位统一展示「🔍 含历史反思校准」区块(§22 单一数据源)。调研已完成(2026-08-17 researcher 实证,6 问全答见 §六;线上 R2 与本地产物双向核实,L09 防线已验)。

## 一、背景:现有预测反馈链路缺哪一环

已存在(2026-08-11~08-16 建成):
- **次日回填**:`scripts/gen_daily_brief.py` `backfill_hits()`(L1944)把每天预测与下一交易日实际指数对比,**三层命中**判定:
  - `range_hit`:上证次日 pct ∈ 预测区间(大盘层)
  - `middle_hits`:中间层 7 指数逐验(前 6 宽基 + 10年国债基点变化),7 全中才算
  - `sector_hits`:每个预测板块次日申万指数命中
  - `direction`(整体)= 三层全中;数据落 `static-site/data/daily_brief_history.json`(90 天滚动)
- **命中率统计**:history `stats` 30d/90d hit_rate(2026-08-16 快照 30d n=4 hit=3 = 75%)
- **过拟合监控**:`scripts/overfit_monitor.py`(21:40 定时)AI 监控卡——实盘命中率 vs 回测命中率对比、综合风险分绿黄红

**缺口(用户指出的核心)**:回填只给了"中/不中"的判定,但没有**为什么失败**(归因)、**失败模式总结**(反思)、**反哺下次预测**(注入)。即只有"考试判分",没有"错题本 + 复习 + 下次不再错"。失败样本就像一次性消费,不产生学习价值。

## 二、闭环设计(三层:归因 → 反思 → 注入)

### ① 归因层(每日,回填后自动)
每个回填失败样本生成**结构化归因记录**,先分类:
- **方向失败**(预测 down 实际 up 等):抓"预期差"——预测时依据的 `confidence_reason` / `risk_items` / `watch_list` vs 次日实际(次日 `news_digest` 新闻/次日实际涨跌幅度),定位"漏了什么信号 / 误判了什么"
- **区间不精确**(方向对但幅度偏,如预测 -0.8~-0.3% 实际 -2.5%):算**预测误差**(实际 vs 区间中点/上下沿),判断是系统性低估还是单日极端
- 归因要有证据(次日新闻/数据/情绪突变),**无证据的标「无法归因」,不臆造**(§5.1 数据说话)
- 输出:`data/daily_brief_reflections.json` 追加失败样本记录(日期/预测方向/预测区间/实际/失败类型/误差/预期差摘要/疑似原因)

### ② 反思层(每周,周报)
周反思报告(可并入现有 AI 监控/每周总结体系):
- **命中率趋势**:30d/90d 对比,周环比
- **失败模式聚类**:高频失败模式——总是方向错(系统性误判方向)?总是区间偏(幅度高估/低估)?特定板块常错?置信度是否虚高(说 60% 真的 60% 中吗,校准检验)
- **置信度校准检验**:实际命中率 vs 预测 confidence 的匹配度(用户可看"AI 说 60% 的时候真的准不准")

### ③ 注入层(每次预测,自成长关键)
反思结论反哺下次预测,三种方式:
- **方式 A(模型层,主推)**:把近期失败模式/高频坑注入 `gen_daily_brief.py` 的 prompt(如"近 3 次预测连续低估下跌幅度,单日下跌区间下沿注意放宽;板块 X 连续 2 次误判,本轮降权")——这就是用户说的"让下次预测更好",模型看到自己的历史失误主动避坑
- **方式 B(参数层)**:区间校准系数——按历史误差分布动态放宽/收紧区间(数据驱动;**必须 walk-forward 验证防过拟合**,§5.4 测试基准)
- **方式 C(规则层)**:特定失败模式兜底(如连续误判时强制降 confidence 或加 disclaimer)

## 三、关键原则

1. **数据驱动**:归因/反思全部从真实回填数据出,不靠"感觉";无证据标无法归因(§5.1)
2. **防过拟合**:方式 B 校准系数/方式 A 注入文案必须 walk-forward 验证(§5.4 v1.1.0 基准),反思过度学习=新的过拟合
3. **人机协同**:周反思报告给用户看,用户可**修正归因/补充经验**——把用户从"填鸭式传授经验"(用户原话"一只给你传授")升级为"审核式引导"(用户看系统反思对错、补认知盲区),省力且系统自迭代。这正好兑现用户说的"自成长体系比我传授有用"
4. **诚实标注**:失败的样本如实进反思,不因"这周预测差"跳过(§5.1 诚实标注)

## 四、实施顺序建议(待用户拍板)

1. **Phase 1 归因层**:回填后自动生成失败样本归因(先做可视化"错题本",不注入)——让用户看到"为什么错"
2. **Phase 2 反思周报**:周失败模式聚类 + 置信度校准检验
3. **Phase 3 注入层**:方式 A 注入 prompt(最直接的自成长);方式 B 区间校准(walk-forward 验证后)
4. 每一步数据验证后再进下一步(§5.1 穷举回测/数据说话)

## 六、调研细化(2026-08-17 researcher 实证,6 问全答)

> 核心结论一句话:**自成长体系最大的瓶颈是样本积累时间,不是实现问题**。①现在连第一个"可完整分类"的失败样本都还没回填(8-14 今晚 20:40 回填后才有);②要凑 15~30 个失败样本做聚类,按 90 天滚动上限需 4~5 个月;③主力生产路径(ai-multi)当前完全没吃历史教训。务实排序 = Phase 0 样本基建现在就做,Phase 1/2/3 按样本积累节奏推进。

### 6.1 回填数据量(样本极稀疏 = 整个体系最大瓶颈)
- **真实数字**:`static-site/data/daily_brief_history.json` items=**5 条**(线上 R2 ss.fx8.store 与本地一致,无新旧差异);stats 30d/90d 均 `n=4, hit=3, hit_rate=0.75`。90 天滚动上限 `HISTORY_LIMIT=90`(gen_daily_brief.py L1637),文件自 2026-08-10 才积累,今天第 8 天,5 条正常。
- 5 条构成:**已回填 4 条全是老格式(仅方向判定,无区间)**:8-10 flat→实际 -0.82%(失败)、8-11/8-12/8-13 flat→实际 +0.32/-0.5/+0.01%(命中);**pending 1 条 = 8-14**,唯一完整三层新格式(direction=down, range=-0.8~-0.3, index_ranges 7 项, sector_ranges 电子/汽车 2 项)。
- **含义**:①「方向失败 vs 区间不精确」两类归因,**现在连第一个可完整分类的样本都还没回填**(已回填唯一失败 8-10 是老格式无区间,做不了"区间不精确"分类);8-14 回填后才诞生第一个三层完整样本。②每周约 5 个预测、按 75% 命中率每周约 1.5 个失败,凑 15~30 个失败样本做聚类(方向型/区间型/板块型)按 90 天滚动上限**需要 4~5 个月**。→ Phase 2 聚类/校准不是实现问题,是样本积累时间问题,必须诚实标注。

### 6.2 失败归因数据源(次日实际齐,次日新闻 8-16 起才归档)
- **次日实际(齐)**:`backfill_hits()`(L1944)回填时从 DB 取次日 sh_pct + 中间层 7 指数 pct + 板块申万 pct,`_backfilled_via` 字段记实际交易日(8-14 回填后 = "20260817"),可精确还原"预测日 8-14 依据 vs 实际日 8-17"。
- **次日新闻(8-16 起向后有效)**:`data/news_digest/2026/` 只有 2 天(08-16/08-17),归档功能 **2026-08-16 14:34 才上线**(commit `49be3c317`)。→ 8-10~8-14 历史失败样本的次日新闻没归档,**只能做规则级归因,无新闻证据就标「无法归因」**;从今起每天有归档(fetch_news 每小时增量,7×24),`_load_news_inject`(L279)模式 A 重跑读对应日期归档、模式 B 增量续接。
- **upcoming 段**:"预告类"事件(标题含 预告/将于/公布/举行/发布),预测时已注入,可支撑"预期了哪些事件 vs 次日实际发生"的预期差分析。
- 结论:归因引擎数据源 = DB 实际指数(齐)+ 次日新闻归档(8-16 起)+ upcoming 预告(向后有效)。**历史 5 条做不了新闻级归因只能规则级;真正的"预期差归因"从 8-16/8-17 这批开始积累**。

### 6.3 置信度校准(样本方差为零,只能建机制)
- **真实数字**:5 条 confidence 分布 = 60, 60, 60, 60, None(8-10 没有)。**4 条全是 60 一个档位,没有任何分桶可言**,"说 60% 是不是真 60% 命中"现在算不出来(连 1:1 例子都举不出,§23.9 自查通不过)。
- 能做的:**机制先行**——confidence 分桶字段天然在(0-100 整数),统计侧按桶(50-59/60-69/70-100)累积命中率,滚动输出"该桶 n 条命中 x 条"。至少 3~6 个月才有第一个可看的校准表。

### 6.4 注入路径(雏形只到"方向级",主力路径完全没注入)
- **单 prompt 路径(有雏形)**:`compute_known_bias(history)`(L2384)——统计近 N 次看涨/看跌命中率,某方向命中率<50% 提示"请对该方向更谨慎",仅 `review_enabled` 时注入 build_prompt。**最小可行反思雏形,但只统计方向命中率,不是失败归因**。
- **多角色路径(当前主力 ai-multi,完全没注入)**:`run_multi_agent`(L2409)主编 sys_text 在 L1530-1568,规则段 1-8 之后就是合规段,无反思注入。**当前 5 条全是 ai-multi = 主力生产路径没吃任何历史教训**。
- **注入实现点**:多角色路径在主编 user dict(类似 L1596 数据锚定/板块白名单注入)加 `reflections` 段,或主编 sys_text 规则 8 后加一段;单 prompt 路径在 compute_known_bias 基础上扩展为"归因结论注入"。两条路径一起改,否则主力路径还是吃不到。
- **风险**:①注入改变 prompt → 破坏模式 A 历史重跑可复现(重跑历史日期要能还原"当时注入了什么"),注入内容必须随 date 落盘归档(news 归档同思路);②合规 scrub 要过;③**防过拟合 = walk-forward**:只注入 T 日之前样本的反思结论,严格时间隔离,开/关注入 A/B 并行对比命中率(§5.4 基准降亏回测那套 walk-forward 逻辑可复刻)。
- **必须补的坑**:news 归档踩过"8-16 才上线"的教训——**反思归档要从第一天按 date 落盘**,否则 4 个月后又是一堆"无法归因"的历史样本。

### 6.5 与 overfit-monitor 边界(粒度完全不同,不重复)
- **overfit_monitor**(`static-site/data/overfit_monitor.json`):**信号级**——每天 N 个买入信号(买类白名单),自 2025-07 起,监控 AI 降亏过滤"实盘命中率 vs 回测命中率"偏离 + 4 维风险分(当前 current.date=20260814, risk_score=39 yellow)。**不读 daily_brief_history,不碰大盘预测**。
- **反思体系**:**预测级**——每天 1 条"大盘方向+区间+中间层 7+板块",自 2026-08-10 起。
- 一句话:**overfit 管"AI 推荐的标的信号准不准",反思体系管"AI 的大盘预测准不准"**——一个管标的、一个管大盘,数据源/粒度/时间跨度都不同,不重复。周报可引用 overfit 的 risk_score 当"当日过拟合背景",不用重算。

### 6.6 实施顺序(务实排序,样本是唯一瓶颈)
- **Phase 0 样本基建(现在就做,工作量小风险低)**:①回填时失败样本自动落 `data/daily_brief_reflections.json`(date/预测方向/预测区间/actual/误差/失败类型占位/_backfilled_via),**从 8-14 这条开始**;②反思注入内容(未来 Phase 3)从第一天就按 date 归档,防重蹈 news 8-16 才归档的覆辙;③confidence 分桶统计侧搭好(0-59/60-69/70-100 三桶,滚动累积)。
- **Phase 1 归因错题本(2-4 周后,等 news 归档攒出第一批"预测日→次日新闻"对齐样本)**:每日自动生成失败样本归因,先做"错题本"可视化不注入。**别现在做**——现在就 1 个失败样本,错题本空的。
- **Phase 2 反思周报(样本≥15 条再上,约 2-3 个月后)**:失败模式聚类 + confidence 分桶校准表。周报粒度建议**滚动 30d 累积趋势**而非"周环比"(每周才 5 条,周环比无统计意义)。
- **Phase 3 注入(最后,walk-forward 验证后)**:方式 A 注入 prompt(先单 prompt 的 compute_known_bias 扩展,再多角色主编段),A/B 验证有效再全量;方式 B 区间校准系数同样 walk-forward。

> **2026-08-17 用户拍板(实施依据)**:用户原话"不等 2-4 个月,边做边改边校准边成长,闭环立即转起来"——不等 Phase 1/2/3 按样本节奏,而是**从第一条失败样本起就自动运转的持续闭环**。据此 Step 1(2026-08-17 实施)把 §6.6 的 Phase 0(样本基建)+ Phase 3 的**方式 A 注入**(规则级,非模型级)合并落地:
> ①失败样本自动落 `data/daily_brief_reflections.json`(从 8-10/8-14 起,幂等,根 data/ 本地不进 git);②规则级归因(failure_type/error_bps/expected_gap_summary/evidence_source);③confidence 分桶校准统计(机制先行,样本少如实输出);④方式 A 规则级注入(单 prompt `compute_known_bias` 扩展 + 多角色主编 sys_text,严格时间隔离 walk-forward,env `BRIEF_REFLECTION_INJECT=0` 可关,注入内容按 date 归档 `data/brief_reflections_injected.json` 可复现,过合规 scrub)。**⑤透明展示(2026-08-17)**:每次 AI 预测生成时把本次实际注入的反思要点(样本数 `n`/方向失败数 `dir_fail`/最近样本 `samples[{date,type,summary}]`,与注入 `build_reflection_inject` 同源同时间隔离)结构化写进 `brief["meta"]["reflection"]`,随 `daily_brief.json`/`daily_brief_history.json` 归档;前端 AI 预测详情块新增 `_dbReflectionHtml` 统一读 `meta.reflection` 渲染「🔍 含历史反思校准」区块(白话一句+场景+1:1 样本明细),覆盖横幅 AI 预测弹窗/收盘分析结合块/AI 预测历史弹窗全部展示位(§22 单一数据源,§23.3 举一反三);无 reflection(旧条目/兜底版/无样本)优雅降级整块不渲染。**Phase 1 归因错题本可视化 / Phase 2 周反思报告 / 方式 B 区间校准系数仍待 Step 2 及样本积累后推进(主控另派)**。
