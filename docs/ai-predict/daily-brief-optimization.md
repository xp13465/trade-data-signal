## 1. 文献调研摘要(联网实证 + 模型知识)

### 1.1 LLM 金融预测研究(arXiv 实证,curl 拉取)

| 论文 | 结论/启示 |
|------|----------|
| **PriceSeer**(LLM 实时股票预测评估) | 学界在做"数据无污染的实时评估"框架——说明 LLM 预测的**评估方法论本身是难点**(数据污染/前视偏差会虚高成绩)。启示:本平台预测必须**留可机检的断言 + 命中率回填**,否则无法判断 AI 预测是否真的有效 |
| **Deficiency of Large Language Models in Finance**(金融幻觉实证) | LLM 在金融任务上有系统性缺陷(幻觉数据/编造数字)。启示:预测 prompt 必须**强制数据锚定**(每条论断引用注入数据的具体值),并做输出后校验 |
| **ExAnte**(前视推断 benchmark) | LLM 即使被显式告知时间截止,仍会输出"截止点之后"的知识(内部知识污染预测)。启示:**盘后 17:50 跑 + prompt 声明数据截止日期**只是基础,仍需在输出标注"基于 X 日收盘数据",避免把"已知事件"当"预测" |
| **FAITH**(金融表格幻觉评估) | 金融表格输入下 LLM 也会编造值。启示:注入数据需**结构化为 JSON 给模型**,生成后校验引用的 index_id/ETF 名是否在注入集合内 |
| Uni-FinLLM / 多模态宏观风险 / 情绪分析系(标题层) | 前沿方向:宏观风险评估 + 情绪信号混合进预测,佐证"把情绪指标显式喂给模型"的方向正确 |

**共同启示(落地为 P0-1/P1-7/P1-8)**:LLM 择时不可靠是学界共识,做好"可回测 + 数据锚定 + 前视防护 + 免责"比追求"预测准确"更重要。

### 1.2 数据分析与挖掘方法(模型知识,标注)

- **恐贪指数(Fear & Greed)**:CNN 版由 7 成分(动量/波动率/避险需求/市场宽度/价差/牛市熊市信号/垃圾债需求)合成,业界用法是**极端值反向**(贪婪极端→谨慎、恐惧极端→观察反转),而非追涨杀跌。站点已有 `fear_greed` + 冰点历史,可支撑"钟摆位置"定位(见 P1-1)。
- **情绪/宽度指标组合**:涨跌家数 + 新高新低 + 量能是经典"内在强度"度量;涨停/跌停/封板/连板衡量风险偏好——站点全部已有(见 §2)。
- **日历效应**:1 月效应、月未/季末资金面(MPA/考核)、长假前避险缩量、财报季波动是 A 股真实但**弱**的统计效应(显著性有争议)。可作为 P2 提示,不可作为主预测依据(见 P1-5)。
- **技术指标组合**:站点已有 RSI/MACD/唐奇安/布林/超趋势(ATR 移动止损)等,且 signal_stats 有 5d/10d/20d 多窗口胜率——**用"信号历史胜率"而非"信号本身"做预测排序**,是站点相对一般平台的独特优势(见 P1-4)。
- **过拟合/回测不可靠**:ML 择时普遍过拟合,单段回测不可信。站点 signal_kelly_backtest 是回测产物,只能当"参考概率"不能当"必胜"——应在 UI/文案层面降权表述。

**共同启示(落地为 P1-1/P1-2)**:专业预测的核心不是"猜方向",而是"给定位 + 给论据 + 给风险",方向判断要附数据支撑且允许"震荡/看不清"。

### 1.4 TradingAgents 参考(真实拉取,两仓库 README)

### 1.5 多角色协作式分析方向评估(重点,用户定方向:引入 TradingAgents-CN 到 daily_brief)

> 用户决策(2026-08-10):用户自己部署使用 hsliuping/TradingAgents-CN 且认可其分析结果;希望 daily_brief 实现层面借鉴其**多角色协作式分析**方法(介入 deepseek 预测);配合"主控(agent 编排)+ 现有站点自研数据",目标 1+1+1>3。

#### 1.5.1 现状
现有 daily_brief 方案是**单 prompt 调用大模型生成分析**(daily-brief-research.md §5.1:一个 system + 一个 user 注入全部数据,一次生成 4 段)。优点:简单、一次调用、成本低;缺点:①所有数据揉在一个 prompt 里,模型难以"专业分工"地深挖单维度;②无多视角对抗,单方向输出易受模型立场/幻觉影响;③"数据注入量"与"输出聚焦度"互相挤占(数据多则 prompt 长、注意力分散)。

#### 1.5.2 TradingAgents 多角色 vs 单 prompt 优劣对比

| 维度 | 单 prompt(现状) | 多角色协作式(TradingAgents-CN 风格) |
|------|-----------------|--------------------------------------|
| 单维度深挖 | ❌ 数据大杂烩,每维度浅尝辄止 | ✅ 每角色只喂自己维度的数据,深挖一条论据 |
| 多视角 | ❌ 单方向 | ✅ 技术/资金/情绪/事件多视角 + 多空对抗 |
| 幻觉控制 | ⚠️ 全量数据易编造 | ✅ 角色数据域收敛,引用越轨易识别 |
| 可解释性 | ⚠️ 输出即终稿,不知依据 | ✅ 每角色产出"论据+数据引用",可溯源 |
| 成本 | 1 次调用 | 4-6 次调用(仍低,见 1.5.5 估算) |
| 实现复杂度 | 低 | 中(编排层),但可轻量实现 |
| 时延 | 秒级 | 分钟级(4-6 次串行,可控并行) |

**结论**:多角色协作式对"每日专业预测总结"收益明显——预测质量的核心是"多维度论据 + 风险提示",正是多角色架构擅长的;成本增量可忽略。

#### 1.5.3 哪些角色/流程值得引入 daily_brief(按价值排序)

| 引入角色 | TradingAgents 对应 | 在 daily_brief 的职责 | 价值 |
|----------|--------------------|----------------------|------|
| **① 技术面分析师** | Technical Analyst | 输入:均线多空/新高新低/量能/信号(买点卖点)+ 信号历史胜率 → 输出:趋势论据 + 技术信号 | 高 |
| **② 资金面分析师** | (无直接对应,补) | 输入:主力/两融/期货机构持仓/南向/北向季度 → 输出:资金方向论据 | 高 |
| **③ 情绪面分析师** | Sentiment Analyst | 输入:恐贪/情绪分/冰点历史/封板连板/板块轮动 → 输出:情绪位置 + 极端提示 | 高 |
| **④ 事件/新闻面分析师** | News Analyst | 输入:**需采集**(当日快讯摘要) → 输出:事件驱动提示 | 中(待采集) |
| **⑤ 研究员(多空辩论)** | Researcher Team(多空) | 综合 ①②③ 论据,做"多头 vs 空头"对抗,给倾向 | 中高 |
| **⑥ 风控** | Risk Management | 输入:alert 8 维 dims/波动率/量价背离 → 输出:风险清单 + 最坏情景 | 高(必备) |
| ⑦ 交易员/组合经理 | Trader/PM | 给"买卖/仓位"决策——**本项目不做**(合规红线),只到"关注/风险"层 | ❌ 不引入(合规) |

**推荐引入:①技术 ②资金 ③情绪 ⑤多空(轻量) ⑥风控**,共 5 个角色视角;④事件面待数据采集后加;⑦交易决策角色明确不引入(输出只到"关注/观察/风险",不产生"买入/卖出/仓位"指令,守住 P0-3 合规红线)。

#### 1.5.4 结合站点数据的角色 prompt 设计建议

每个角色一个子 prompt,**只注入该角色所需数据**(缩小数据域、控制幻觉,呼应 P1-8):

- **技术面分析师**(输入:ma_alignment 均线多空 / new_high_low / volume_ratio 量比 / signals_today 当日买卖点 / signal_stats 对应信号胜率)→ prompt:"你是技术分析师,基于以下技术指标与信号,给 1 条趋势论据 + 1 条技术信号(只引用给定数据,给出精确值)"。
- **资金面分析师**(输入:a_fund_main / a_fund_margin / futures_acc_trend 机构净多变化 / hk_south 南向 / a_fund_north_quarterly 北向季度)→ prompt:"你是资金分析师,基于以下资金数据,给 1 条资金面论据(注意:北向为季度口径,不得当当日方向断言)"。
- **情绪面分析师**(输入:fear_greed / a_sentiment / 6 宽基情绪 / recent_freeze 冰点历史 / a_width_fengban_rate / a_width_max_lianban / rotation)→ prompt:"你是情绪分析师,给 1 条情绪位置论据 + 极端值逆向提示(恐贪>85 或 <15 时给出)"。
- **风控**(输入:alert.high/low dims / a_qvix / 量价背离)→ prompt:"你是风控,列出 3 条风险点 + 1 句最坏情景(只引用给定 dims)"。
- **研究员(多空融合)**(输入:四角色论据)→ prompt:"你是研究员,把四角色论据整理成『多头论据 / 空头论据 / 倾向判断(涨/跌/震荡)』,倾向必须同时给出支撑与风险,允许'震荡/看不清'"。
- **主编**(最终融合)→ 组装四段输出 + 元信息(meta 断言,见 P0-1),校验指令词黑名单(见 P0-3)。

**数据可用性:全部角色输入数据均为站点已有**(§2.1 确认),仅"事件面"需采集。

#### 1.5.5 deepseek 介入方式 + 成本估算

- **模型选择**:主角色(技术/资金/情绪/风控)用 **deepseek-chat(V3)**(生成稳定、便宜、快,适合结构化论据输出);"研究员多空融合"可用 **deepseek-reasoner(R1)**(深度推理对抗,reasoning_effort 可控,CN 版已支持该字段全链路传递——真实拉取),若成本敏感可全程 V3。
- **调用编排**:本地 Python 脚本,5 个子调用**可并行**的做并行(①②③④ 互不依赖,风控依赖 alert 数据但独立),研究员/主编串行;总时延目标 <2min,超时降级(见 P1-9)。
- **成本估算**(deepseek-chat,V3,memory 参考价 ¥2/M input cache-miss、¥8/M output):
  - 每角色:input ~2-3k token(注入数据)+ output ~300 token;5 角色 + 1 融合 ≈ 6 次调用
  - 单日:input ~15-18k token ≈ ¥0.03-0.04;output ~1.8-2k token ≈ ¥0.015
  - **单日约 ¥0.05,年(250 交易日)约 ¥12-15**,即使翻倍也远低于一次 Claude 调用;reasoner 版输出贵 ~3-5 倍,年 ¥50-70 仍可接受
  - 结论:**多角色成本完全可接受**,不构成选型障碍。

#### 1.5.6 实施建议:全量多 agent 框架 vs 轻量借鉴(推荐+工作量+优先级)

| 方案 | 内容 | 工作量 | 优先级 |
|------|------|--------|--------|
| **A. 轻量借鉴(推荐)** | 不自引 TradingAgents 依赖/代码,自研 6 个角色子 prompt 的**流程编排**(并行子调用 + 融合),复用站点数据注入 + 现有 daily_brief.json 输出结构 | 4-6h(角色 prompt 编写 + 编排脚本) | **P0-4** |
| B. 全量多 agent 框架 | 引入 LangGraph 图编排 + 完整角色类(含交易员/组合经理)+ 对话式多轮辩论 | 30-50h(含前端/状态/失败恢复),且引入交易决策角色触碰合规 | P2(暂不建议) |

**推荐 A(轻量借鉴)**:①站点 daily_brief 是"每日一份总结",不需要 LangGraph 级状态机;②多角色价值在"分角色论据 + 融合",用 6 个子 prompt + 编排即可 80% 复现;③避免引入交易决策角色的合规风险;④不引入第三方框架依赖,生产稳定性可控(§14)。全量框架留作 P2 远期。

**落到完善点**:新增 **P0-4(轻量多角色协作式分析框架)** + **P1-11(研究员多空辩论增强,reasoner 可选)**。见 §3 完善点清单 ①。

### ③ 风险控制

#### P0-3. 合规强化:指令词黑名单 + 免责声明 + 输出后置校验
- **现状**:daily-brief-research.md §9 有段落级 gating(明日关注/风险点/AI预测仅登录完整版),但 prompt 只约束"禁止可能/或许",未禁止"买入/卖出/加仓/建仓"等指令词。
- **缺口**:证券合规红线是"投资建议"(买入/卖出/仓位指令),不只"预测"。gating 管了展示权限,没管**文案内容**——合规版/登录版文案都可能出现指令词。
- **建议**:①prompt 加指令词黑名单("建议买入/建仓/加仓/卖出/清仓/止损位为 X 元/仓位 X%"),只允许"关注/警惕/观察/留意";②生成后置校验脚本:正则扫指令词,命中则该句降级为数据陈述或删除;③所有预测加免责声明行("AI 生成,研究用途,不构成投资建议;历史命中率不代表未来",参考 TradingAgents-CN 免责模板,真实拉取);④gating 保持段落级不变。
- **优先级**:P0
- **数据可用性**:🔶 无(工程规则,不依赖数据)

#### P1-7. 前视偏差防护 + 生成时点标注(ExAnte 实证)
- **现状**:方案 17:50 盘后跑(收盘数据已全),天然避"盘中用未来数据",但未考虑模型内部知识污染。
- **缺口**:ExAnte(arXiv)实证:LLM 即使被给时间截止,仍会输出截止点之后的知识(把"已发生"当"预测")。
- **建议**:prompt 显式声明"当前北京时间 X,数据截至 2026-08-10 收盘;忽略任何 2026-08-10 之后发生的事件/数据";输出统一标注"基于 8 月 10 日收盘数据生成";历史回看页同步显示每期生成时点。
- **优先级**:P1
- **数据可用性**:🔶 无(工程规则)

#### P1-8. 数据锚定机制化:每条论断必须带数据引用 + 生成后校验(FAITH 幻觉实证)

- **建议**:①prompt 要求每条论断附数据来源字段(如"信号:hscei buy_special 20d胜率75%"),注入数据以 JSON 给模型(非自然语言拼接);②生成后校验:正则/代码比对断言中引用的 index_id/ETF 名是否在注入集合内,不在则拒绝该条并要求重写;③meta 断言(见 P0-1)强制机检。
- **优先级**:P1
- **数据可用性**:🔶 无(工程规则)

## 6. 调研结论

1. **现有方案主链路完整**(数据注入→段落 gating→历史归档→命中回看),三大缺口在 §0。
2. **联网实证支撑**:LLM 择时不可靠 + 幻觉 + 前视偏差是学界共识(PriceSeer/Deficiency/ExAnte/FAITH),因此"可机检回测 + 数据锚定 + 前视防护 + 合规"四件事优先级高于"预测更准"。
3. **数据维度**:站点资金/期货持仓/公募/凯利回测/信号胜率等预测维度**全部已有**,缺的只有新闻舆情(需采集)与日历(低成本)。
4. **TradingAgents 可借鉴**:多角色视角、多空辩论、数据锚定、风控段、免责声明、多 LLM 提供商封装,已提炼 6 项并入清单。
5. **多角色协作式分析方向(用户定)**:推荐轻量借鉴(6 角色子 prompt 编排,4-6h,P0-4),不引第三方框架、不做交易决策角色(合规);deepseek-chat 为主、研究员可选 reasoner,年成本 ¥12-70(§1.5.5)。
6. **优先级汇总**:4 P0 / 11 P1 / 2 P2 + 6 TradingAgents 参考,详见 §3-§5。
