## 行为与入口

默认保护 `data/nextday_plan.json`、`data/auto_trade_steps.json`、`data/signal_kelly_day_snapshot.json`、过拟合主/ext，以及 `nav_bucket/*.json`。所有这些键经 `_upload_glob` 使用同一保护链；增量、data-files、verify 修复和 raw upload 均纳入。raw 关键键要求运行树内的规范源路径，净值桶源为 `STATIC_DIR/data/nav_bucket/`。

1. 冻结新 bytes / SHA256；旧 bytes 和强 ETag 从同一次 GET 获取。只有明确 `NoSuchKey` 才按真新键处理，403/其他404/短读不能变成新建许可。
2. 旧 bytes 持久保存本地，并用 `If-None-Match:*` 写独立备份桶的 `protected-versions/v1/<主桶>/<key>/<旧SHA256>`。回读整个备份并核 SHA256，同长度不算通过。
3. 持久逐键许可、write-id、原条件和新 bytes；先落 `unknown + pending_purge` 再提交。覆盖使用 `If-Match`，首建使用 `If-None-Match:*`。
4. 条件提交不在底层偷偷重试。明确拒绝不推进成功；响应丢失/5xx 保留 unknown，最多两次 GET 以 write-id + SHA256 确认。其他写者的相同内容不算本次提交确认。
5. 分片在 Create 和最终 Complete 都带条件；Complete 前保存同 upload-id / part-list / 条件，重入可精确确认。HTTP 200 内嵌 Error 不算成功。412、409、未知不会降级无条件覆盖。
6. 确认后清普通路径和 /r2/ 代理路径缓存；任一路径清除失败保留持久任务并返回未完成，增量 state/checkpoint 不得借此跳过。重入先补清缓存，不再重复 PUT。非关键独立对象继续上传；非关键对象原 PhaseA 兼容策略保留。

保留原域锁、全局屏障、小通道锁；新增关键单键/过拟合配对互斥，不缩短锁域。`R2_PHASE` 逐键输出 prepare_hash、old_read、backup_write、backup_readback、upload、state、purge 的单阶段耗时。沿同一工作 deadline，purge 重试也受预算约束；传输块间重查预算、刷新 socket 超时，不足1秒不向上扩到1秒。

## 主/ext 部分发布与恢复

触及任意过拟合键时同时冻结两件，要求顶层 `publication_run_id` 相同且匹配 `[A-Za-z0-9][A-Za-z0-9_.:-]{0,127}`，并辅助核对 `generated_at`。Ops 生产者每次 `build_output` 计算一对时生成一次 `uuid4.hex`，主/ext共用；同 invocation 内第二次计算必须换 token，publish-only 保留原 token。`OPS_BUSINESS_RUN` 仍为发布尝试/run绑定，不用作生成 token。本分支不编辑 Ops 生产者，生产者连续两次构建断言由 Ops owner 实施、父任务整合联测。

两件旧对象及不可变配对清单均备份、回读成功后，才开始逐键提交。旧对象没有合法相同 token 时仅称逐字节保全：相同时间戳标 `legacy_timestamp_matched_only`，旧不一致或缺件标 `old_bytes_preserved_generation_unverified`，`old_pair.generation_verified=false`；均允许升级至带新 token 的一对。旧时间戳不能证明代际。`pair_id` 关联原旧版本和新 SHA；单键日志标识 confirmed/failed/unknown，部分成功仍返回失败。下一轮相同目标可续原配对；若外部写者已改变失败对象，则拒绝续写，保留恢复配对。

这不是多对象事务，读者可能在两次 CAS 之间看见混合版本。token 验证只证明本次冻结的两份输入属于同一次生成；要实现消费者原子切换，需要父任务另行协调生产者/消费者的不可变版本 manifest，本次不越界修改它们。

运行树 `data/.r2-protected/` 包含逐键日志、`history/`、`payloads/` 和 `pairs/`。文件原子替换并 fsync 数据及父目录，磁盘不足在发送前阻断；发送后落盘失败保留之前的 unknown 供重入确认。恢复时保留整个目录及远端两类 protected 前缀，不要删除日志来“解锁”。

在正常生产调用环境、原锁域与工作预算配置下可执行：

```sh
REPO=<运行树绝对路径> R2_UPLOAD_WORK_TIMEOUT=300 \
  python3 scripts/upload_r2.py recover-protected
```

该命令会确认原写入，补 pending purge；必要时仅重放原 write-id、原 bytes、原条件，不换新许可。未解决、准备但未提交或失败的条目仍非零退出。准备态由原业务命令重入；部分配对冲突交 Claude 根据 `pairs/<pair_id>.json` 和对应 SHA 旧版本恢复，不自动覆盖第三方新版本。普通上传面对未确认的单 PUT 只读确认，不自动重放；显式恢复命令才重放原请求。

本地按持久引用做 GC：保留所有当前日志、unknown/pending-purge、未完成配对历史，以及这些条目引用的旧/新 payload 与整份配对。完成且无引用的旧历史/内容可清除，先 fsync 引用 manifest 再删；坏日志/manifest、symlink、GC ENOSPC/崩溃一律停止，不猜测可删除集合。`.gc.lock` 只保护本地存储引用更新，保留所有原业务锁域；不把它称为性能优化。

容量默认 `R2_PROTECTED_MAX_BYTES=2147483648`（2GiB），并限制8192个受管文件；`R2_PROTECTED_HISTORY_KEEP=1`（允许0..16）控制每键额外完成历史。当前/未知/部分配对不受历史数量裁剪。计入文件内容、每文件4096字节开销以及原文件+新临时文件峰值，容量不足报告 used/extra/cap 并拒写。每次落盘前预检真实磁盘空闲，`R2_PROTECTED_MIN_FREE_BYTES=134217728`（128MiB）为可配置保留空间；不足报告 free/extra/reserve。预检不能阻止别的进程随后占满磁盘，实际 ENOSPC 仍按上述崩溃协议处理。

容量依据为父任务提供的本机实际尺寸：256 个 nav_bucket 共 **574,207,502 bytes**，最大桶 **2,826,563**；overfit 主 **4,007,963**、ext **10,606,607**。全桶和 pair 同时保存 new+old 合计 **1,177,644,144 bytes**（未含日志/临时峰值），2GiB 默认预算留有约0.97GB余量。未在测试中分配这批真实数据；容量算式有测试，真实全量运行由父任务验收。

远端 `protected-versions/v1/` / `protected-pairs/v1/` 不参与旧 `pre-upload/<day>/` 7天删除；本次未读写或部署远端 lifecycle，**不能宣称远端增长已自动有界**。部署前必须明确远端容量预算/监测和按恢复引用清理的保留策略：当前/unknown/partial pair 的两件旧备份及配对 manifest 不得按固定天数盲删；只回收已完成且无引用的旧代，删除前再次校验归属，容量不足应暂停保护写入。若使用生命周期，只可作用于确认退休、与恢复锚点隔离的前缀，不能直接给全部 protected 前缀挂短期过期。此为父/Claude部署验收项，不是本子任务已完成的配置。

## 给父任务的真实隔离探针

`scripts/r2_isolated_probe.py` 默认 `plan` 只生成计划；本子任务仅执行 plan 和 transport fake 测试，不执行下面的 execute/cleanup 网络命令。父任务选定有权限的桶，先运行并检查唯一前缀、四个键及 bytes，再执行同一计划：

```sh

python3 scripts/r2_isolated_probe.py execute --state /tmp/r2-isolated-probe-unique.json
python3 scripts/r2_isolated_probe.py cleanup --state /tmp/r2-isolated-probe-unique.json
```

所有对象只在 `__codex_validation__/ops-backlog-<uuid>/`，精确四键 allowlist；不改保护键集合，不访问业务对象，不通知、不 purge、不递归 LIST。计划不得重复执行。实际使用 uploader 的 SigV4 / S3 / multipart 函数，两个客户端共享旧 ETag 竞争须出现200/412；备份 GET 对 SHA；5MiB+31字节两 part 在 Create 后、Complete 前注入已知对手，再证最终 Complete412，随后新条件成功200；主动丢弃一次成功响应后只用原 write-id+hash 确认。全部流程180秒，单个逻辑请求（含重试）25秒预算；发送前写入独立 `/tmp` 归属日志，记录 Complete 条件与响应。完整对象最大常驻约5MiB，正常计划上传数据约10MiB；底层分片最多五次尝试，数据流量上限约50MiB（不含小型XML/HTTP头），同时受上述总预算约束。失败分片另需服务端回收未完成upload。网络异常如实失败/未知，不伪造 PASS。

清理限制：官方 [S3兼容表](https://developers.cloudflare.com/r2/api/s3/api/) 没有承诺 DeleteObject 条件原子性。为满足“绝不删不明版本”，cleanup 重新 GET 对 hash/write-id，只报告 owned/UNKNOWN/absent，**所有完整对象均保留、不做无条件DELETE**（GET后删除存在竞态）。仅底层分片中断可 abort 本次记录过的 upload-id；响应丢失未记录的 upload-id 不能猜删。父/Claude需明确安全清理/生命周期方式；本分支不会声称探针已自动清干净，更不会为了清理删除不明版本。

官方依据：[R2 conditional operations](https://developers.cloudflare.com/r2/api/s3/conditional-operations/)（2026-11-11读取，页面更新2026-11-10；原文备份为证据目录的 `conditional-operations.md`）。它明确要求条件出现在最终 Complete 上，并说明 write-id、412、409、负读和完成响应丢失的差异。
