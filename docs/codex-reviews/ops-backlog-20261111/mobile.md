# HC22 移动端参数可用性修复

本次用户已授权实施；仅在 Codex 集成分支修改源码，未修改主工作树、min 产物或线上版本。Claude 审合部署后仍须真机验收。

## 实际问题与修改

旧线上双视口脚本返回 15 PASS，但它只覆盖 390/1280，参数不存在或未打开时的零高度也可能通过，且跳过通知入口。补测实际源码发现：320×568 的参数区高306.72px，吸顶条底部537.72px，已超过底栏起点507px；760×360 的展开面板底部349.39px，超过底栏起点299px。601–760px 的 CSS 已为移动端，默认展开判断仍以600px为界。原按钮为22px，并非需要再次统一放大。

修复保持原按钮的字体、padding及尺寸。仅在≤760px用导航吸顶偏移、标题实际换行高度、底栏、visualViewport计算剩余高度；面板最多46%可视高度，且为结果留56px空间。极矮横屏/软键盘使空间不足时解除本块吸顶，继续通过页面滚动访问所有内容。参数内部独立滚动；移动默认折叠边界统一为760px；用户保存的展开偏好继续保留。补上aria-expanded/aria-controls与区域名称，移动端Escape收起并返回按钮焦点。ResizeObserver只观察标题/底栏，重渲染前断开上一观察器；resize监听仅注册一次。

没有改变市场全景、全站按钮规则、操作计划、通知入口或风险文案。桌面>760px仍按原布局；新增ARIA语义不改变尺寸。
