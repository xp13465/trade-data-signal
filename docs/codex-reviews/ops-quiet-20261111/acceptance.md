# 验收合同

## 通知正反例

| 输入与证据 | 预期 |
|---|---|
| 正常完成、合法空、未到约定公布时间 | 内部面板/台账留证，默认运维外发 0 |
| 短暂重试或锁等待，业务截止前正确交付 | 保留 attempt；无故障外发，也无多余恢复通知 |
| 缓冲后已证恢复且无需人工处理 | 发送前重新检查，零外发；未知不能冒充恢复 |
| 数据损坏、错误公开结果、超业务期限或明确人工项 | 及时且可行动的首次告警 |
| 同一已完成 run 被多次轮询 | 不累计成多轮失败，不重复首报 |
| 同一事件持续未恢复 | 保留故障；按影响扩大或认领逾期规则升级，不按日机械群发 |
| ACK 但业务仍失败 | 仅改变认领状态，不改健康结论 |
| 首次发送失败 | 不占成功去重窗，后续可重试；不得假称已通知 |
| 真实恢复 | 只匹配实际已通知的原事件，配对一次 |
| 同域但不同任务/新影响/新故障 | 不得被过宽去重吞掉 |
| 用户订阅的业务日报/交易通知 | 保留原订阅语义，不与例行运维混同 |

外部提供方受理后丢失回包仍可能产生结果不明；记录 event/attempt，不承诺跨第三方网络严格 exactly-once。渠道受理不能冒充用户收到或已读。

## 业务与通知两套账

观察前固定部署代码/配置身份、应跑任务槽位、业务日期、截止时间和最低覆盖。重试属于同一轮。缺启动、缺日志、上游失败、部分交付和人工补救不能事后从分母删除。成功必须有对应自然 run、正确日期与覆盖、产物 hash 和公开验证；仅 exit 0 或文件存在不够。

保留旧飞书 alert 群统计以便历史比较，另核所有运维通知渠道。事件数、消息数、渠道尝试及受理数分别计，report 改道不算收益。缺日志/缺事件身份保留未知，不得按零计而判通过。

初验建议从核实新部署身份后连续 14 个自然日开始，至少覆盖 7 个交易日、周末与高峰；周频关键任务至少两个自然轮，不足则延长。月季频单列待自然验证，30 日复核趋势。窗口未满不作长期通过结论；已证失败不能因窗口未满隐藏。

纳入的关键链目标：截止前正确完整交付；已知同类机制故障复发、人工救火、无需行动的默认运维通知、同事件重复首报均为 0。真实外部故障仍计业务未达标并单独归因，真故障必须可达。失败项继续保留原问题 ID，不能靠重命名或删告警关闭。
