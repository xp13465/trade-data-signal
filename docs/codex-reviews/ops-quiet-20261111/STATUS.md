## 已实现的范围

| 部分 | 改动与边界 |
|---|---|
| 通知出口 | 事件引用、实际发送者回写、按渠道补发、HTML 摘要合同、未知传输结果、领取过期后停止后续发送；未承诺跨第三方 exactly-once |
| 计划任务 | 同一完成 run 重复轮询不累计多次失败，持续事件不按日重首报，恢复只配对实际受理，ACK 与回执同锁合并，内部结论不补发邮件 |
| 两个核心 failed unit | 公募/过拟合与 schedule 共享事件与回执，校验 InvocationID/exit/state；身份不符回退可见；配置漂移/其他 unit 独立保留 |
| 例行生产者 | 正常 update_all 完成与明确非生产保护走内部 info；业务日报与真失败保留。R2 skip 登记/清理失败不再声称保存成功 |
| 双账与验收 | 旧 alert 群统计保留，增加全渠道实际 attempt/受理/未知；业务按固定显式 slots、真实格式凭证、公开字节核对。旧成功晚评估不能清除新失败 |
| 期限合同 | 复用已有新鲜度、FOF 验收预期、overfit 同日与 R2 接力判据；[既有合同](existing-contracts.md)列出依据与真正未定义的边界 |

通知阶段累计渠道字段与每次 attempt 字段严格分开：补发不能把之前已成功的邮件再算一次受理。`channels=null` 表示本次该渠道结果未知，false 不是用户未收件的证明。部分渠道有同事件持久回执时，CFU 不另报“全部未送达”；未确认渠道仍按原事件重试，不消除其未知状态。

## 审查与复验的真实边界

独立审查先复现了通知四项缺陷和业务验收旧成功覆盖新失败问题，原 FAIL 留存。随后部分并行助手额度耗尽，主会话接管修复与剩余原脚本复验，不把接管后的作者复验称为独立批准。另一个只读 Codex 会话针对固定源码 hash 独立复验了三项通知和两项验收反例，范围和 hash 随最终报告保留，仍不替代 Claude 最终审查。

隔离验证包括真实通知 CLI、异步 flush、并发领取、实际 ACK、完整 schedule 嵌入入口及 shell→CFU→notify。SMTP/HTTP/systemd 外部边界使用隔离夹具，不能称真实收件或自然生产成功。测试失败、环境失败和测试口径修正分别记录，不写成一次全量全绿。

验收器只核显式提供的清单，尚未独立认证日程全集。`declared_subset=true`、`denominator_completeness=unknown`、`execution_coverage_satisfied=null`；`elapsed_window_mature` 仅是时间跨度/声明频次，`window_mature=null`。即使一槽的输入一致性返回 REPLAY_OK，也不表示完整14日覆盖。生产输入始终 `production_stability=NOT_CERTIFIED`。
