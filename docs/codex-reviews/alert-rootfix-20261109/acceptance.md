## Claude 审合与部署顺序

1. 以最终交接 packet 的**完整 head + 报告 SHA-256**为准，核当前 main 到 `codex/reviewer` 的实际 diff。初始 scope packet 和中间分支报告均不能代替最终固定版本。复验发现的 P2 修在原分支，原始 FAIL 报告保留。
2. 核六组文件归属；共享 pending-index 沿用 main，不整文件覆盖。子分支提交保留在整合提交图中，使用现行 `main-merge.sh` 流程，由 Claude 审核合并；不在服务器手写另一份修复。
3. Worker 安全分类与采集器受限重试配套发布；先发布 Worker，再同步云上对应采集器代码。确认 active Worker 版本和云端实际文件 hash，随后利用自然 15 分钟采样核 ID/回执、退出与分类。保留真失败，不能只 reset-failed。
4. D1 两个脚本随代码正常同步，按自然 16:00 等既有日程记录真实 `rows_written/rows_read`、哈希变化和首次迁移状态，再观察完整 UTC 日（北京时间 08:00 重置）。若真实工作量仍超额度，单独提交预算/套餐决策；本轮不代替用户更改订阅。
5. 行情 writer 随正常启动执行幂等加列，先确认旧库迁移和强来源保护，再验下一真实交易日“占位→最终行情→同日信号→冻结持久化”。不主动重跑大回测，不将历史 136/五缺键计入已修复数。
6. 备份按现有日/周节奏产生本轮来源 receipt，核对象签名 metadata、恢复 hash/integrity/关键计数、健康库失败隔离和 parent 的 local/upload/verify RC。verifier 只读 GET/HEAD，不能自动补传。旧 standalone 缺证明应为 unknown/失败，不能沿用旧 PASS 预期。
7. 04:21 只读 `df/stat`：云盘可用约 16.54GB，四个 DB 主文件合计约 3.77GB（其中 public_fund 约 3.07GB）。这只是当前容量快照，不是空间预留；GB 级耗时、WAL 增长与并行占盘未做恢复基准。执行前复核实际余量，沿用新预检，不能自动清历史备份腾空间。

若上线后异常，按本轮固定提交逐项回退代码；不能撤销业务历史或清掉原故障证据。
