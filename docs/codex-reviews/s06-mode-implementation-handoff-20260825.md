# S06 降亏模式实施交接（2026-08-25）

> 作者：Codex 外部深度 tester/reviewer
> 目标：新增一个与 `NEW14+1 · 15键(new15)` 同级、前端可选择的 `S06` 动态降亏模式，用于检验结果；不改生产默认档。
> 结论：S06 通过无前视审计和参数邻域稳健性验证，可以进入前端实验模式。

## 一、模式定义

- 模式 ID 建议：`s06`。
- 展示名建议：`S06 · 大盘领先切换`。
- 规则：
  - 当 `csi1000_ret20 - hs300_ret20 < -3.524224785046781` 时使用 `A` 基座；
  - 否则使用 `NEW14+1 / new15` 基座；
  - A 前提连续破坏 15 个交易日后切回兜底；
  - A 最短持有 10 个交易日；
  - T 日收盘判定，T+1 生效。
- 阈值来源：2016-2020 选段 q30 冻结值，未用 2021 后验段或全史分位调参。

## 二、关键验证结果

同一当前交易快照、同一 `mine28.simulate` 引擎：

| 方案 | 2021-2026 净利 | MDD | 胜率 | 年切换 | 强平净利 |
|---|---:|---:|---:|---:|---:|
| **S06 → A / NEW14** | **+94,151** | -3,811 | 64.3% | 4.0 | +81,772 |
| **S06 → A / NEW14+1** | **+93,813** | -3,811 | 64.4% | 4.0 | +81,435 |
| NEW14+1 静态 | +83,718 | **-3,550** | 65.2% | 0 | **+83,718** |
| NEW14 静态 | +82,263 | -4,178 | 63.8% | 0 | +82,263 |

S06 相比 `NEW14+1`：自然过渡多约 `+10,095`，MDD 只深约 `261`；强平口径低约 `2,283`。

## 三、无前视审计

已确认：

1. `ret20` 为纯 trailing 收益，不含未来 K 线。
2. `csi1000` 与 `hs300` 同交易日对齐。
3. 状态机为 T 日收盘生成信号、T+1 日生效。
4. `confirm=15`、`min_hold=10` 只累计历史交易日。
5. 阈值只来自 2016-2020 选段 q30：
   - 选段 q30 = `-3.524224785046781`；
   - 验证段 q30 = `-1.894186918584995`，未被使用；
   - 全史 q30 = `-2.846433118529035`，未被使用。
6. 抽样核对 2021-2026 全部生效切换，决策日均为生效日前一交易日。

参数邻域验证：q20-q60 × 确认期 5/10/15/20/25/30 共 36 组，全部验段净利高于静态 NEW14。Bootstrap 2000 次重采样中，q30 在选段被选中的比例为 100%。

## 四、实施要求

### 数据层

新增单源快照，例如：

```text
static-site/data/kelly_mode_s06_state.json
```

必须包含：

```json
{
  "version": 1,
  "generated_at": "...",
  "mode_id": "s06",
  "threshold": -3.524224785046781,
  "confirm_days": 15,
  "min_hold_days": 10,
  "on_base": "a9",
  "off_base": "new15",
  "decision_timing": "T_close_signal_T_plus_1_execution",
  "daily": [
    {
      "date": "YYYYMMDD",
      "size_spread": 0,
      "premise": false,
      "effective_mode": "new15",
      "decision_date": "YYYYMMDD"
    }
  ],
  "current": {
    "date": "YYYYMMDD",
    "mode": "a9",
    "since": "YYYYMMDD"
  }
}
```

生成器应独立脚本化，例如 `scripts/gen_kelly_mode_s06_state.py`，并保证：

- 因子只用已有收盘序列；
- 输出数组不可因重跑改变历史状态；
- 快照带版本和生成时间；
- 缺文件时前端明确降级提示，不允许静默退回其他模式。

### 前端模式注册

在 `common.js _KELLY_FADE_MODE_PRESETS` 新增 `s06` 可选档：

- 默认档保持 `new14`，不得变更；
- `s06` 排在 `new15` 后；
- 名称：`S06 · 大盘领先切换`；
- 标注：动态切换 / 实验可选档 / 非默认；
- tooltip 必须写清 A 与 NEW14+1 切换规则、T+1 生效、阈值来源和当前为检验用途。

因为 S06 不是固定键组合，不能只用现有 `keys` 数组表达。所有消费点遇到 `s06` 时必须读取日期对应 `effective_mode`，再套用 `a9` 或 `new15` 的键集；禁止把 S06 错误展开成某个静态 keys 组合。

### 消费点一致性

至少覆盖以下展示/交互位置：

1. 模拟回测弹窗的 AI 降亏模式下拉；
2. 凯利区模式选择与标签勾选态；
3. 首页信号 AI 降亏过滤；
4. 过拟合监控卡模式组集；
5. 邮件 AI 通知如已支持模式口径，需要同步或显式声明暂不启用 `s06`。

手动勾选任一键后仍进入“自定义组合”，不应继续显示 S06。

## 五、验收标准

### 功能验收

1. 三端下拉出现 `s06`，默认仍是 `NEW 14键`。
2. 选择 `s06` 后，页面按日期使用正确基座：
   - `2026-06-09` 生效 `A`；
   - `2026-04-28` 生效 `NEW14+1`。
3. 手动修改任一键后显示自定义，不再保留 S06 标识。
4. 模式记忆 TTL 到期后回到 `new14`。
5. 快照缺失、字段缺失或日期不匹配时给出可见降级提示。

### 数据验收

1. 快照中每个 `effective_mode` 与独立状态机复算一致。
2. 每个生效日对应的 `decision_date` 是上一交易日。
3. `a9` / `new15` 键集与现有预设逐位一致。
4. 回测结果与 Codex 同引擎对照允许实现误差小于 `0.5%`；若不同需先解释费率/补位/强平差异。

### 工程验收

1. `common.js/app.js/lab.js` 与对应 min 文件同步。
2. 后端/脚本登记点同步；不引入第二个阈值事实源。
3. 公示文案同步到 purpose notes。
4. Playwright 桌面 + iPhone/iPad viewport 无 JS error。
5. 三站数据层和 min 文件 smoke 通过。

## 六、上线边界

- 本次只做实验可选模式，供用户前端选择检验结果。
- 不改默认 AI 降亏模式。
- 不直接替换实盘邮件或交易路径。
- 若后续要用于生产通知或真实过滤，必须先完成 shadow mode 至少一个完整风格周期，并单独评审强平/缺数据/延迟更新行为。
