# 凯利回测总收益不随窗口线性提升分析

> 生成日期：2026-08-09 ｜ 调研性质不commit ｜ 数据源：`static-site/data/signal_kelly_backtest.json`（线上版 2026-08-09 19:22 生成）+ `scripts/signal_kelly_backtest.py` 代码 + `static-site/lab.js` 渲染逻辑
> 纯只读分析，未改脚本未跑模拟（backtest.json 已含全周期全字段，对比即得结论）

## 0. 摘要（核心结论先讲）

**用户现象**：信号凯利回测里，近1年/近3年/近5年窗口的"总收益"基本稳定在一个固定比例，没有随窗口线性提升。"1年赚100，交易3年也赚100，交易10年也赚100"，期望总收益每年稳固提升。

**根因一句话**：`BUY_AMOUNT=10000` 固定每笔非复利回测，卡片主显的百分比指标（单笔均收益率/年化）都是**平均化口径**（每笔独立投10000元结算再平均），不随时间累积；真正随窗口增长的 `total_profit`（元）和 `total_return`（累积收益率%）虽已计算，但前者视觉不突出、后者根本未在卡片显示。

**3 条核心发现：**

1. **卡片显示的百分比都是平均化的，设计上不累积**——`mean_return`（单笔均收益率）= `total_return_pct`（总收益率%）= `sum(每笔return_pct)/n`，每笔 `return_pct=profit/10000*100` 独立结算。近1年和近10年的平均每笔收益率理应接近（同信号源同策略），所以"稳定在固定比例"是平均化口径的正常表现，非 bug。

2. **`total_profit`（元）其实随窗口增长，但被行情和信号密度扰动**——`sig_main` A 模式 y1=25,878元 → y5=110,950元 → y10=124,222元 基本增长；但 `etf_strong`/`mkt_a` 出现 y3 > y5（2022-2023 熊市亏损拉低5年累计），`rating_high` 因评级近年才有老数据少（y1=44笔 vs y10=85笔）增长平缓。卡片"最终盈亏"列有显示但视觉不突出。

3. **`annualized_return`（年化）反而随窗口递减**——当前年化 = `(1+平均化收益率)^(1/年数)-1`，把"平均每笔收益率"当作"该周期累积总收益率"来开方年化，语义错误。平均化收益率本就稳定偏低（0.5%~2%），开5次/10次方后被进一步稀释（如 `sig_main` A：y1=0.90% → y5=0.18% → y10=0.09%），给用户"越久年化越低"的误导。

**推荐改进方向（详见 §5）：**
1. 突出 `total_profit`（元）的窗口增长趋势（已有列，强化视觉/排序）
2. 前移或加注 `return_pct_max_holding`（最大持仓收益率=总利润/峰值占用资金）——这是唯一随窗口增长的累积百分比指标（`sig_main` A：y1=3.04% → y10=14.61%），最贴合用户期望
3. 修正 `annualized_return` 计算口径（改用累积收益率而非平均化收益率做年化基础）
4. 卡片新增"累积收益率"列（`total_profit/峰值占用资金*100` 或显示已有但隐藏的 `total_return`）

## 2. return_pct / total_profit 计算口径（代码行号）

### 2.1 单笔层面（signal_kelly_backtest.py）

```python
BUY_AMOUNT = 10000  # L47 每笔买入金额(元),固定非复利

# L263 买入
buy_price, shares, _comm, _tf = _buy_with_fees(BUY_AMOUNT, buy_nav, etf_code)
# L283-284 卖出后结算
profit = net - BUY_AMOUNT              # 绝对盈亏(元)
return_pct = profit / BUY_AMOUNT * 100  # 单笔收益率%(分母恒为10000)
```

每笔投入固定 10000 元，`return_pct` 是单笔独立收益率，**不把上一笔利润滚入下一笔本金**（非复利）。

### 2.2 聚合层面（`_compute_stats` L482-588）

```python
# L518 平均每笔收益率
mean_return = sum(t["return_pct"] for t in trades) / n

# L519 累积收益率(总利润/单笔本金*100) -- 卡片未显示
total_return = sum(t["profit"] for t in trades) / BUY_AMOUNT * 100

# L543-545 平均化总收益率(总利润/总投入*100)
total_invest = n * BUY_AMOUNT
total_profit = round(sum(t["profit"] for t in trades), 4)       # L544 绝对盈亏(元)
total_return_pct = round(total_profit / total_invest * 100, 4)  # L545 平均化收益率

# L548-550 最大持仓收益率(总利润/峰值占用资金*100)
max_concurrent_capital = max_conc * BUY_AMOUNT
return_pct_max_holding = round(total_profit / max_concurrent_capital * 100, 4)

# L552 年化(基于total_return_pct开方)
annualized = _annualized_return(total_return_pct, period_key, trades)
```

### 2.3 关键等式（每笔投入相同时成立）

```
mean_return == total_return_pct
```

因为 `total_return_pct = total_profit / (n×10000) × 100 = [sum(profit)/n] / 10000 × 100 = mean(profit/10000×100) = mean(return_pct) = mean_return`。

两者都是**平均化收益率**（每笔独立收益率的平均），不随交易笔数累积。

### 2.4 年化计算（`_annualized_return` L444-466）

```python
r = total_return_pct / 100.0   # L451 用平均化收益率当 r
if period_key == "y1":
    return total_return_pct     # L455 y1 直接返回平均化收益率
elif period_key == "y3":
    return ((1+r)**(1/3)-1)*100 # L457 开3次方
elif period_key == "y5":
    return ((1+r)**(1/5)-1)*100 # L459 开5次方
...
```

**语义问题**：年化公式 `(1+r)^(1/年数)-1` 的 `r` 应为"该周期累积总收益率"，但这里用的是 `total_return_pct`（平均化收益率）。平均化收益率本就偏低且不随时间累积，再开 n 次方后被稀释，导致年化随窗口递减。

## 4. 根因分析

### 4.1 直接原因：平均化收益率口径不累积

用户看到的"总收益稳定在固定比例"是 `mean_return%`（单笔均收益率）或 `annualized_return%`（年化），两者都是**平均化口径**：

- `mean_return = mean(每笔return_pct)`：每笔 `return_pct = profit/10000*100` 独立结算，n 笔取平均。近1年和近10年的平均每笔收益率理应接近（同信号源同策略），所以"稳定在固定比例"是平均化的正常表现。
- `annualized = (1+mean_return)^(1/年数)-1`：基于平均化收益率开方，反而随窗口递减（稀释）。

### 4.2 根本原因：BUY_AMOUNT=10000 固定每笔非复利回测设计

`signal_kelly_backtest.py` L47 `BUY_AMOUNT = 10000`，每笔独立投入 10000 元，**不把上一笔利润滚入下一笔本金**（非复利）。这是评估信号质量的标准回测口径（每笔同等条件独立验证），但导致：

1. 收益率按每笔独立计算（`return_pct=profit/10000*100`），再取平均（`mean_return`）
2. 平均化收益率不随交易笔数累积（n笔的平均 ≈ 1笔的期望，不随n增长）
3. 总收益率 `total_return_pct = total_profit/(n×10000)*100` 也是平均化（分母随笔数线性增大，分子也线性增大，比值稳定）

### 4.3 这是设计行为还是 bug？

**设计行为**（非 bug）：固定金额非复利回测的本质特征。该口径用于评估"信号本身的每笔期望收益"，不评估"资金曲线复利增长"。

**但存在展示问题**：
1. 卡片主显的百分比都是平均化的，没有突出"总收益随时间增长"的视角
2. `total_profit`（元，随窗口增长）虽有"最终盈亏"列但视觉不突出
3. `total_return`（累积收益率%，随窗口增长）已计算但未显示
4. `annualized_return` 计算语义有误（用平均化收益率当累积收益率开方）

### 4.4 total_profit（元）为何也不严格线性

尽管 `total_profit` 元随窗口增长，但不严格线性，受两个因素扰动：

1. **信号密度随时间变化**：`rating_high` 评级近年才有（y1=44笔 vs y10=85笔），老数据信号少，total_profit 增长平缓
2. **熊市年份亏损拉低累计**：2022-2023 熊市（`mkt_a`/`etf_strong` 的 y3 > y5），熊市年份的亏损交易拉低5年累计利润

这进一步加深用户"总收益没随窗口提升"的观感——连绝对值都不严格线性，百分比又稳定。

## 5. 改进方案

### 方案A：突出 total_profit（元）的窗口增长（最小改动，推荐先行）

卡片已有"最终盈亏"列（`total_profit` 元），但位置第7列、视觉平淡。改进：
- 强化视觉（加粗/配色/趋势箭头），让用户切周期时直观看到绝对盈亏随窗口增长
- 在周期切换栏或卡片标题处显示该象限×模式的 total_profit 跨周期趋势（如 y1→y5→y10 的小型趋势条）

优点：零计算改动，纯前端展示优化。
缺点：total_profit 不严格线性（熊市扰动），仍可能让用户困惑。

### 方案B：前移+加注 return_pct_max_holding（最大持仓收益率，推荐）

`return_pct_max_holding = total_profit / 峰值占用资金 * 100`（L550），是唯一随窗口增长的累积百分比指标：
- `sig_main` A：y1=3.04% → y5=13.05% → y10=14.61%（递增）
- 含义清晰：实际动用资金（峰值同时持仓占用）下的累积回报率
- 已在卡片第9列显示，但位置靠后且列名"最大持仓(动用资金)收益率"晦涩

改进：
- 前移到"最终盈亏"附近，改名为"累积收益率（按峰值资金）"或"资金占用总收益率"
- 加 tooltip 说明"=总盈亏/峰值同时持仓资金，反映实际资金占用下的累积回报，随回测周期增长"

优点：字段已存在无需改计算，语义最贴合用户期望的"总收益随时间提升"。
缺点：分母是峰值占用资金（max_concurrent×10000），若近期信号密集峰值高会稀释该指标。

### 方案C：新增累积收益率列（total_return 或按基准本金）

显示已计算但隐藏的 `total_return`（L519：`sum(profit)/BUY_AMOUNT*100`，总利润/单笔本金）：
- `sig_main` A：y1=258.78% → y5=1109.50% → y10=1242.22%（大幅递增）

改进：新增"累积收益率"列显示 `total_return`。

优点：随窗口大幅增长，最直观满足用户"总收益随时间提升"期望。
缺点：分母是单笔 10000 元（非真实占用资金），数值偏大（动辄几百上千%），语义不如 return_pct_max_holding 严谨。可改用"总利润/初始本金"但需定义初始本金。

### 方案D：修正 annualized_return 计算（推荐，但改动较大）

当前年化（L444-466）用 `total_return_pct`（平均化收益率）做 `(1+r)^(1/年数)-1`，语义错误。应改用累积总收益率做年化基础：

```python
# 当前(有误): r = total_return_pct / 100  (平均化收益率)
# 修正: r = return_pct_max_holding / 100  (峰值资金累积收益率)
#   或 r = total_return / 100             (单笔本金累积收益率,数值偏大)
```

用 `return_pct_max_holding` 年化示例（`sig_main` A y5）：
- 当前：`(1+0.0092)^(1/5)-1 = 0.18%`（平均化开方，过低）
- 修正：`(1+0.1305)^(1/5)-1 = 2.49%`（峰值资金累积开方，合理）

优点：年化数值合理且随窗口相对稳定（反映真实年化回报）。
缺点：改动后端计算+重新生成 JSON+前端公示文案同步（§21），需走实施流程。

### 推荐实施排序
