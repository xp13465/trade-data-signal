## 1. 现状全链路梳理(110 笔在哪、走什么链路)

### 1.1 数据/产物/前端链路

```
signal_kelly_trades.json(原始信号, 含 2011 起 110 笔老信号, 只在产物层存原始事实)
   │  回测引擎(前端 replay, 不落盘)按 signal_date 逐笔读基座键集过滤
   ▼
kelly_mode_s06_state.json(单源快照, 覆盖期 20141114~now, **S06 兜底实现源头**)
   │  前端 _tdsS06BaseForDate(date): byDate 命中→直接返回; 日期在覆盖期外→
   │  {ok:true, base:off_base(现=new14), reason:"out_of_range_fallback"} ← **110 笔永久兜底在这**
   ▼
消费点(lab 凯利页 / sim 弹窗 / 首页 AI建议 / 监控卡)按 base 键集真过滤(§23.15 兜底过滤, 非 fail-open)
```

- **关键结论:永久兜底实现在「快照数据层 + 前端判定函数」,不在回测产物层**。回测产物
  (`signal_kelly_backtest.json`) 只存原始信号与静态聚合,**不含 s06 动态态锚点数**;前端展示的
  230.83% 等 S06 数字全由页面 replay 引擎从原始信号+快照实时算出。因此消灭兜底不需要重跑回测产物。
- 权威对账脚本 `docs/kelly/analysis/scripts/trade-method-final-repro.mjs`(切片 common.js/lab.js
  单源跑 VM)是页面 replay 的镜像副本;其 s06 H 卡基线 230.8326% 与 purpose-notes.js 公示的
  230.83% **逐位一致**(本报告影响面脚本基于同一引擎, 见 §3)。

### 1.2 兜底现状(root cause)

- 快照 `coverage_start = 20141114`, 因生产因子 `csi1000_ret20 - hs300_ret20` 且 csi1000 数据源最早
  20141017, 扣 20 交易日 LOOKBACK 后最早可判日 = 20141114。
- 全部 110 笔老信号 signal_date ∈ [20110119, 20141113], 均在覆盖期外 → `_tdsS06BaseForDate` 走
  `out_of_range_fallback` → 按 `off_base(new14)` 键集过滤。
- 即:**110 笔从未被 S06 动态判定过**, 死锁在 new14 键集(即使当日小盘显著跑输应为 a9, 也按 new14
  过滤)。2026-09-02 用户拍板消灭此死角。

### 1.3 方案选择(用户已拍板)

- 2014 前段 csi1000 无数据 → 用同构价差代理因子 **`csi500_ret20 - hs300_ret20`**(中证500 数据自
  20100104, 覆盖 2014 前段无缺口; 与生产因子同为「小盘 20 日收益 - 大盘 20 日收益」的价差语义)。
- 阈值 **沿用现冻结值 -3.524224785046781**、参数 **CONFIRM_DAYS=15/MIN_HOLD_DAYS=10**(同现快照),
  不重新调参(防前视: 全为固定常数, 非 2014 前段滚动拟合)。

## 2. 方案2 实现设计

### 2.1 核心:数据供给扩展,前端判定零改动

`_tdsS06BaseForDate` 逻辑(L.985-1010)是**先查 `_tdsS06ByDate`, 命中直接返回**;只有查不到才判
`out_of_range_fallback`。因此方案2 的实现 = **把 20100104~20141113 的 daily 行 prepend 进快照**:

```
改前: coverage_start=20141114, daily=[20141114 ... 20260902]
改后: coverage_start=20100201, daily=[20100201 ... 20141113(新前段行) ... 20141114 ... 20260902]
```

- prepend 后, 110 笔 signal_date 全部命中 `_tdsS06ByDate` → `_tdsS06BaseForDate` 直接返回对应
  `effective_mode`(a9/new14), **不再进 fallback 分支**。
- 前端四个消费点(lab 凯利页/sim 弹窗/首页 AI建议/监控卡)全部走 `_tdsS06BaseForDate`/
  `_tdsS06FiltersForDate`/`_tdsS06KeysForDate`, **无需改判定逻辑**, 自动跟随。
- pre-2014 行 `effective_mode` 只会是 a9/new14(合法基座), 不会触发 `bad_mode_fallback`。

### 2.2 前段基座生成(方案2 sticky, 与生产状态机同语义)

沿用 `gen_kelly_mode_s06_state.py` 的 `build_daily` sticky 状态机(codex008 F2 新语义: T 日收盘判定
→ T+1 生效; 进入 a9 立即; a9 内 held 逐日+1; 退出需连续破坏 15 且持满 10):

```
因子:  pre(20100201~20141113)   spread = csi500_ret20 - hs300_ret20(代理, 用户拍板)
       post(20141114~now)        spread = csi1000_ret20 - hs300_ret20(现状不变)
阈值:  -3.524224785046781(现冻结值, 2016-2020 q30, 不重新调参)
种子:  PRE_OFF = new14; 前段首日无决策日 → new14(同生产首日语义)
拼接:  [前段行] ++ [现快照 daily 行](现快照 20141114 首日独立 seed new14, 保持不变 ——
       见 §2.3 拼接缝分析, 对 110 笔零影响)
```

### 2.3 拼接缝(20141113→20141114)分析

- 现快照 `daily[0]=20141114` 是 `decision_date:None` 的独立 seed new14 行;方案2 prepend 不改它。
- 前段末日(20141113)的 sticky 状态(可能停在 a9 或 new14)**不跨缝传给 20141114** → 20141114 仍为
  new14, 与现快照逐位一致;从 20141115 起由生产因子接管判定。
- **影响判定:110 笔的 signal_date 全部 ≤20141113, 无任何信号落在缝上**, 拼接缝对 110 笔改判
  结果零影响(= 本报告影响面数字直接用 `PRE_DAILY.concat(s06.daily)` 即为此语义)。
- 2014 后段(<20141114 后)所有交易日基座逐位不变(§3 已实测 Δ=0)。

### 2.4 快照 schema 变更(建议, 待 implementer 落定)

`kelly_mode_s06_state.json` 增加/变更:

```jsonc
{
  "coverage_start": "20100201",                        // 前移
  "pre_segment": {
    "feature": "csi500_ret20 - hs300_ret20 (%)",       // 前段代理因子显式声明(§23.6 yaml/快照单源)
    "date_from": "20100201", "date_to": "20141113",
    "proxy_reason": "csi1000 数据源 20141017 起, 2014 前段无生产因子, 用户拍板 csi500 代理"
  },
  "factor": "csi1000_ret20 - hs300_ret20 (%) (2014-11-14 起) / csi500_ret20 - hs300_ret20 (%) (2014-11-13 前)",
  "daily": [ /* pre 行(20100201..20141113) ++ 原行 */ ]
}
```

- 前端 `_tdsS06Status`(common.js L.970 回显 coverageStart)等按需展示, 消费点零代码改动。
- 唯一需同步的机检:`scripts/check_s06_state.py`(独立第二实现)需覆盖「前段行因子为 csi500-hs300、
  后段行因子为 csi1000-hs300、缝语义」——属于实施范围, 本报告只列需求。
