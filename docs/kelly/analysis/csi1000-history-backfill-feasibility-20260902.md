# 中证1000(000852)历史数据前滚到基日 2004-12-31 可行性调研报告

- 日期:2026-09-02(researcher 调研,供用户拍板)
- 触发:用户希望根治 s06 动态模式快照覆盖期(现状 20141114 起),把快照+采集前滚到中证1000 基日 2004-12-31
- 数据正确标准(用户 2026-09-02 补充):**快照覆盖期 ≥ 现有采集数据(signal 交易)最早统计时间点**。现有信号交易最早 = 2011-01-19(index_daily 里 hs300 已到 2002),故 csi1000 老段至少要到 2011 年,理想到基日 2004-12-31。兜底(fallback)只是过渡保险,不算最终正确。

## 结论摘要

**方案 A(前滚到基日)可行、免费、数据零台阶**:中证指数公司官网(index-perf 接口)提供中证1000 自基日 2004-12-31 起的**官方回溯点位全史**(2004-12-31 ~ 2026-09-01 共 5265 个交易日,OHLC 全字段,免费无 token),与项目现用新浪源在 2014-10-17 起的重合段 2889 个交易日**逐日一致(偏差全部 ≤0.05,仅小数位舍入差,零台阶零断点)**。一次性回填 2004-12-31~2014-10-16 约 2400 个交易日即可把 s06 快照覆盖期前滚到基日,达到用户"数据正确标准"(覆盖 ≥ 2011-01-19 信号最早交易日)。

## 二、证据(数据说话)

### 2.1 官网全史拉取实测
- 接口:`GET https://www.csindex.com.cn/csindex-home/perf/index-perf?indexCode=000852&startDate=20041231&endDate=20260902` + Referer 头
- 返回:2004-12-31 ~ 2026-09-01 共 **5265 个交易日**(分段 20041231~20150101 得 2428 行、20150101~20260902 得 2837 行,因单次响应受服务器约 1.2MB 截断,分段即可)
- OHLC 全字段:open/high/low/close/tradingVol/tradingValue/consNumber/peg(滚动市盈率)
- 日期连续性:最大间隔均对应春节/国庆/元旦假期,无数据空洞

### 2.2 拼接一致性对账(风险点"台阶/断点"的核心验证)
- 重合段(2014-10-17 ~ 2026-09-01)2889 个交易日,官网 close vs 项目新浪源 close **偏差>0.05 的天数 = 0**(2339 天偏差为 0;其余均为 3位小数 vs 2位小数的舍入差,最大 0.03,如 6058.668 vs 6058.67)
- 2014-10-17 衔接点:新浪 6058.668 vs 官网 6058.67;**零台阶**
- 结论:**前滚拼接无断点/无台阶,口径一致**(两者都复权无除权概念,指数点位现成)

### 2.3 老段(2004-2014)数据合理性抽查
| 时期 | 官网数值 | 与常识核对 |
|---|---|---|
| 2005 年末 | 843 | 合理(基日 1000 附近起步) |
| 2007-09-19 顶 | 4676 | 2007 大牛市中小盘顶部,合理 |
| 2008-11-04 底 | 1343 | 2008 熊市深跌,合理 |
| 2010-11-11 高 | 5739 | 2010 中小盘行情,合理 |
| 2013-06-25 低 | 3331 | 钱荒低点,合理 |
| 2015-06-12 峰 | 15086.44 | 2015 中小创巅峰(公认值),**精确吻合** |
- 老段点位形态与历史常识完全吻合,数据可信

### 2.4 官网数据已发现的小瑕疵(诚实标注,影响可忽略)
- **节假日重复行 2 处**:2005-01-04(与基日 2004-12-31 完全相同)、2015-01-01(元旦,与 2015-01-05 相同);akshare 接口对 2008-01-01 等元旦也返回重复行
- 基日点位:官网日行情 2004-12-31 close=**989.98**(实算值;指数定义基值 1000,部分数据商显示基日为 1000.00,存在 ±1% 定义值取舍差异,仅影响最早几日,20 日因子摊薄后对状态机无实质影响)
- 处理:回填脚本去重 + 按交易日清洗即可(本报告脚本已去重)

## 三、前滚工程方案(要做/差什么/花多少)

### 所需改动(一次性)
1. **数据层回填**:新增一次性脚本(或扩 index_backfill.py),用 akshare `stock_zh_index_hist_csindex("000852", "20041231", "20141016")` 拉老段(~2400 交易日,1-2 次请求),拼 index_daily 表标准字段(date/index_id/open/high/low/close/pct_change/amount),经 `upsert_index_rows` 写入 sentiment.db index_daily(该函数 UPSERT 语义,天然支持历史回填,见 @app/collector/index_backfill.py:278 RUNNER upsert 调用);老段数据写入后即固化在本地 DB,不依赖官网长期在线
2. **产物重跑**:重跑 export_index_detail 生成 csi1000-all.json(首日 20141017 → 20041231)→ 重跑 scripts/gen_kelly_mode_s06_state.py(s06 快照覆盖期 20141114 → 20041231)→ 第 2.1 节全部"覆盖期外 fallback 兜底"交易变逐日切基座 → **历史战绩整体重算**
3. **对账(铁律)**:重算后必须执行 §5.4⑦ 复现脚本同构对账机检 + Playwright 无痕浏览器页面实测锚点对账(逐位对比),防口径漂移进报告/界面
4. **落档**:新脚本进 docs/kelly/analysis/scripts/(本报告已带);若动默认组合/算法本身,按 §5.4⑥ 发中间版本

### 时间/成本估算
- 数据成本:0 元(官网免费,无 token/注册)
- 工程成本:回填脚本+清洗 ~1 小时;重跑数据产物+s06 快照 ~30 分钟(回测/对账另计);页面对账 ~1-2 小时。合计约 **0.5 个工作日**
- 采集趋势增量:老段一次性落库;**新段保持现链路(新浪主源)不动**,不对每日采集链路增加任何依赖/时点(官网接口仅用这一次)
- 验证窗口:重跑对账建议避开盘后定时任务时点(§14:15:35/16:00/17:50/20:35/22:00),放安全窗口或周末(周末休市可随时 deploy)

### 环境/工具注意(已实测)
- 本机 akshare 1.18.64 可用,`stock_zh_index_hist_csindex` 返回 OHLC 全字段(akshare 文档注释"只有收盘价"的说法已过时)
- 东财域名(push2his.eastmoney.com / push2.eastmoney.com)在本机当前网络**不可达**(curl 000/ProxyError),东财渠道本轮无法实测,标"待验证"
- WebSearch/WebFetch 在本次会话被全局 deny/域名安全校验全拦,社区佐证通道不可用;本报告以官网一手实测为准

## 五、方案 A vs 方案 B(供用户拍板)

### 方案 A:前滚到基日 2004-12-31(推荐)
- 做:回填脚本(akshare 官网源)→ 重跑 csi1000-all.json + s06 快照 → 对账上线
- 差:0 元数据成本;约 0.5 个工作日工程;重算后全量对账
- 得:覆盖期 ≥ 2011-01-19 信号最早交易日(**达到用户数据正确标准**);s06 历史检验从 11 年 → 21 年,增加 2007/2008/2013 等极端周期样本;所有交易逐日切基座真实治理,兜底仅作为兜底
- 风险:见上表(均可控/可标注)

### 方案 B:维持现状 + 覆盖期外 fallback 兜底
- 做:无
- 差:快照只覆盖 2014-11-14 起,**不达到用户数据正确标准**(2011-01-19 ~ 2014-11 的信号交易仍落兜底);s06 缺 2005-2013 全部极端周期检验样本
- 定位:过渡保险形态,按用户口径不算最终正确

### 建议
选**方案 A**,一次性根治;回填用官网官方回溯点位(唯一免费权威全史源),固化本地;重算后严格走 §5.4⑦ 对账 + §5.1⑤ 按年/极端周期分解报告再上线。可选优化:前滚后 csi1000 老段若要在"实盘可获取口径"上更贴近当年,可另用中证官网点位对照(指数公司回溯口径即官方单一口径,不存在第二份实盘口径,无需纠结)。
