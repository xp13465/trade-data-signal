# GHI 卖出口径查证(2026-08-30)

> 调研对象:凯利回测区 G 模式弹走势图,用户疑问「GHI 交易模式,出现 1 次卖出信号时,是卖光全部仓位还是只卖 1 手 1 万?用户预期卖光」。用户举例:卖出 20260710 配买入 20260408、卖出 20260710 配买入 20261125。本调研只读查证,不改代码。

## 一、核心结论(可直接回答用户)

1. **卖出信号语义 = 卖光全部当前持仓,不存在「只卖 1 手 1 万」。** 后端把每个买点独立成一笔(每笔本金 1 万 = BUY_AMOUNT),卖出信号触发时**该笔全部份额清仓卖出**(非部分卖出、非分批)。证据 = `scripts/signal_kelly_backtest.py:764 卖出全量 shares`。
2. **同一卖出信号日会命中该指数当时所有未卖出的持仓笔, 全在同一天卖光。** 每个买点是独立交易,各自找「买入后第一个匹配卖信号日」;若 8 笔都建在  20260710 这个卖信号之前且期间无更早信号 → 8 笔同在 20260710 全部卖出。实证 = 562870 证券ETF 嘉实 G 模式 8 笔买 → 全卖 20260710,合计净亏 -262 元(8 万本金全部清仓)。
3. **「1个卖点只配1个买点」是展示层 pin 按交易行配对(每行天然 1买1卖)的视觉结果, 不是卖出量语义。** 一行= 一笔完整的「买入→卖出」, 走势图把每行画成 1pin 线, 同日多笔就是一个卖日多个 sell pin 横排(同 chart-pin-ui-rootcause 2026-08-30 问题2a)。用户 hover 到买 20260408→卖 20260710 那行, 没注意同日还有 7 个卖pin。
4. **另有一条真正的「分批」链路= GIH 仓位管理(前端 _kellyAihlineApply, 默认开)**, 但它的分批是 **cap 硬控** 不是卖出信号:- 当持仓笔数×1万 > cap( G=10 万 / H=5 万 / I=9 万) 时, 在**持仓超 cap 那日**先把「冷≤3天年轻仓」或最老仓强制平掉(对应 card 口径). 这是「仓位管理分批卖」, 卖出日=强平日(forced), 与卖出信号日无关。 到自然卖出信号日, 剩余持仓仍全部卖光。
5. 用户举例「卖出 20260710 配买入 20261125」:库里 buy/sell 日期 20261125 均为 6 行(未来日期不存在), 应为笔误——实际数据是 562870 的买 20251125 → 卖 20260710。

## 二、后端卖出逻辑(证据: `scripts/signal_kelly_backtest.py`)

- L71 `BUY_AMOUNT = 10000` → 每笔买入本金固定 1 万。(注: 说明 L529 文注「买1000 元」 是过时文注, 实际是 10000)
- L572 买入 `buy_price, shares, … = _buy_with_fees(10000, buy_nav, …)` → 每笔份额=1 万对应的全部份额。
- L582-588 `if sell_mode in ("G","H","I") → _backtest_signal_sell(...)` → G/H/I 走信号驱动卖出分支。
- L687  `_backtest_signal_sell` docstring → G=第一个 sell 信号日卖 / H=sell or sell_stop_loss 任一最早日卖 / I=buy_special 交易用 H 逻辑其余用 G。
- **L764 `sell_price, _sell_amount, … = _sell_with_fees(shares, sell_nav, etf_code, …)` → 卖出传入的 `shares` = L572 买入的全部份额 → 全量清仓这一笔。**
- L718-760 无信号 → 持有至回测结束「持中」, 无卖出。

→ 后端语义:**每笔独立建仓 1 万,卖出信号触发时整笔全量卖出(shares 全卖)** 。不存在「卖 100 股/卖1手/卖一半仓位」逻辑。

## 四、前端展示逻辑验证 (证据: `static-site/lab.js`)

- L12288-12304 pin 真对配对:每个 buy 事件取同行 sell( `buy.t ===  sell.t`) → **结构性 1 行 1 卖配 1 买**(同期数据产物也是每行 1买1卖(无分批))。
- L11754-11790 弹窗在 GIH 开时(默认开)直接套 `_kellyAihlineApply` real 通路重算自然卖出行的真实卖价/净利(如 562870 卖20260710 那行 profit=+649.1 与产物一致=未经强平改造), 并有 `row._gihForced = k.forced` 标记强平行。
- L7849-7858 `_kellySharedGih` 默认 `on:true`(用户 GIH 默认开)。L8035 `_kellyAihlineP3dCap`= P法强平逻辑:超 cap 时整行强平整行卖(先卖≤3天年轻仓, 无年轻仓卖最老)。
- L8006-8015 FIFO 强平、L8108 HoldCap(满仓不买)同理均为**整行卖出/整行停买**, 不存在部分手数卖出。

→ 前端展示:**自然卖出 = 整行已清仓(卖光该笔), 强平 = 整行提前卖光(仓位管理)**; 不存在「只卖 1 万里的 1 手」的代码路径。

## 五、三源核对(§23.13)

| 源 | 位于 | 卖出口径表述 | 与代码/产物是否一致 |
|---|---|---|---|
| 代码现状 | scripts/signal_kelly_backtest.py L680-790 + lab.js _kellyAihlineApply | 卖信号日整笔全量清仓卖出 | 基准 |
| 产物层 | static-site/data/signal_kelly_trades.json | 同卖日多买点全卖(562870 8笔/全库常态) |  一致 |
| 公示文案 | purpose-notes.js lab.sigkelly →「G/H/I为卖信号驱动卖出… 信号触发平仓」 | 平仓=卖光 |  一致 |
| 公示文案 | static-site/app.js L1650 →「回测 G 口径=信号驱动卖出全量…」 |  全量卖出 |  一致 |
| 展示层 | lab.js pin 按行配对 → 1 卖日 N 买点但视觉逐行 1:1 |  展示粒度与产物一致(行级) |  视觉易误解(同日多卖 pin 横排) |

**不统一点(展示层)**:数据产物与后端都是「1 卖日 → N 行同日全卖」, 但 pin 图按行画, 每行 1 卖配 1 买, 用户不 hover 同日其他 pin 就无法看到「这 1 卖点受影响的全部买点」 → 观感像「只卖 1 万」 。 这是展示粒度的非数据不一致, 不是 bug(卖出口径各源一致) 。

## 六、用户预期 vs 现状差异定性

- **用户预期**: 出现 1 次卖出信号 = 卖光全部仓位。
- **现状**: ①后端与产物:恰好就是卖光全部(同日所有持仓全卖, 562870 8 笔实证); ②前端 pin 图:按行 1:1 展示, 同日多卖 pin 需注意横排才能看出「全清」 ③GIH 仓位管理(默认开)额外在持仓超 cap 时**分批先卖部分**(强平年轻仓), 这是 cap 管理不是卖出信号, 会增加「分批卖出」观感。
- **定性**: 不是「代码只卖 1 万/分批卖出信号」的 bug —— 卖出信号语义=全量清仓, 符合用户预期。 用户疑虑主要来自展示层 pin 粒度 + GIH 强平把资金曲线画成分批。 若要在 UI 上向「1 卖点聚合显示全部被卖买点」 聚合或加「同日卖 N 笔」标识 = 需求变更(可议) 。
