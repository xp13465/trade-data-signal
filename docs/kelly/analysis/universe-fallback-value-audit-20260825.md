3. export 时 `app/queries.py` L1115 `_align_home_top1_to_backtest` 命中冻结 → L291-294 把冻结条目 **prepend 进 etfs(即使 map 是空数组)** → L1119 `_bt_in_universe = any(track_score is not None)` 判 **True**。
4. 校验脚本按 map 重算(bj50=[])= False → assertion1 FAIL 3 条(bj50 buy × 3 个信号日),阻断上线。
   现场:`/tmp/deploy-30win.log`,FAIL 明细 `bj50 signal=buy overview_bt=True recompute=False`;校验读的是 trade-data 镜像(`/Users/linhuichen/code/trade-data/static-site/data/overview.json`,signals_today=515,date=20260824)。
5. `config/universe_rules.yaml` 「空数组」排除类别**硬编码只有 ["ftse100","kospi"]**,其余 32 个空数组指数不在任何声明类别(灰色地带),yaml 的 inclusion_dependency(require map key + track_score 非空)事实上把它们挡在宇宙外——除 bj50 被冻结表穿透。

用实际价格算跟踪度(etf_daily close 日收益相关;对照组剔 20220902 单日脏数据 +176%):

| 配对 | n | 日收益相关 | 方向一致率 | 累计收益对比 |

另:bj50 vs 512100(中证1000ETF)相关也只有 0.6515——北证50 与任何沪深宽基都是弱相关,**没有可用代理**。

## 八、口径诚实标注

- 全史统计用本地主库 sentiment.db;线上展示位用 trade-data 镜像 overview(date=20260824)。两库历史段一致性此前已核验(warn_signal_window_caliber_20260825 报告),但主库近期信号与镜像存在已知滞后差(memory export-syspath-rootcause),T1 近期计数以主库为准可能比线上少最新 1 个交易日。
- T2B 用指数价格而非 ETF 价格(任务指定口径),衡量的是信号本身质量;T2A 用回测 trades(ETF 结算价),衡量的是兜底落地后的实际损益。两者方向相反的差异正是"标的错配"的证据。
- T5 清单来自东财基金搜索接口关键词命中,"同名板块 ETF"≠"精确跟踪该指数";实施前必须以 etf_index_map.json 反查 track_index_code 逐个确认,防止 kw 兜底式错配重演。
- 方案 C 未做穷举回测(配 ETF 后这些信号的费后贡献需按 mine 系列同款流程另行回测),本报告只回答"值不值得配"的方向性证据。
