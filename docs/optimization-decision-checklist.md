## 15 项明细

### 1. 🧊 凯利回测默认口径:收盘 → 次日开盘
- **要拍板什么**:lab.js 回测默认买入口径是否从「当日收盘」改为「次日开盘」(次日玩法已作为操作建议进首页参考说明 0eb1ef5ea,但回测默认口径没改)。
- **好处**:口径更贴近实盘可复现(收盘价买入无法 1:1 跟单),数字更可信。
- **缺点/风险**:动已发布默认行为(§23.7);改后全站回测数字基线口径变化。
- **数据依据**:穷举回测已证次日开盘 vs 当日收盘净利差 ≈ -0.01%(每日池)/-0.57%(每笔固定),成本可忽略;次日 open 覆盖率 100%;开盘下方 -1% 限价单 K=1 净利 +84.5 万(+6 万)、收益率 52.81%(+3.8pt)、触达率 39.8%。
- **建议**:**推荐做**——数据充分、代价≈0,但属冻结项必须点头。

### 4. ⏰ R2 上传失败阻断 push
- **要拍板什么**:是否接受「关键文件(overview/board_etf_map)R2 上传失败即阻断 push」(可能误阻正常 deploy)。
- **好处**:防「R2 旧版残留 + push 新代码」不一致(§22),线上数据时效有保障。
- **缺点/风险**:网络抖动/临时失败会卡住整个上线链(误阻正常 deploy);§14 动 deploy 主链路。
- **现状**:P0 已加「upload_r2 空时 notify 告警」;方案3 含 last-modified 校验。
- **建议**:**可选**——若做,建议「失败阻断 + 明确重试/继续选项」而非硬阻断;退一步只加 last-modified 校验,把阻断面收敛到关键文件。

### 5. ⏰ edge cache purge 兜底
- **状态**:✅ 已完成(2026-08-18 上线,upload_r2.py 新增 purge-low-freq 命令,124 低频文件消除 4h 残留)
- **要拍板什么**:低频文件(max-age=14400,4h 旧版残留,如 daily_metric)的兜底方案选哪种:deploy 末尾统一 purge / Worker 定时清理 / HIGH_FREQ TTL=5s。
- **好处**:低频文件不再有 4h 旧版残留窗口。
- **缺点/风险**:deploy 末尾统一 purge 增加 deploy 时长/R2 调用;Worker 定时清理增复杂度;TTL=5s 让低频文件 edge cache 失效回源增加。
- **现状**:P0 方案2 已对高频文件(overview/intraday_snapshot/board_etf_map)ttl=0 no-store。
- **建议**:**推荐「deploy 末尾统一 purge」**——与现有 upload_r2 各命令已 purge 的机制同构,改动最直白。
