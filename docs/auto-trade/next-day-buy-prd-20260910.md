# 自动化次日买入操作 PRD(细化报告)

> 版本: v1(2026-09-10 初稿, 供用户审阅拍板)
> 状态: 待用户审阅 -> 拍板后落档定稿
> 对应需求: 「做一个自动化的次日买入操作。需要有哪些步骤。比如在什么时间点干嘛 等等。给我做一个细化的prd报告并落档 方便后续开发」
> 测试基准: current baseline(memory test-baseline-v112-anchor, v1.1.7, S06 动态基座 + NEW14/15 按日切 + AI仓位建议 K=1 每日资金池 1 万等分)

---

## 0. 一句话目标与评价标准

**目标**: 在现有「S06 动态基座 + AI仓位建议 K=1(每日只买最优 1 笔·每日资金池 1 万等分)+ A 模式卖出(固定 10 个交易日)」信号链路基础上, 把「T 日盘后选标的 -> T+1 日开盘买入 -> A 模式到期卖出」全流程自动化: 每天 21 点前生成次日买入计划, 次日 9:25 集合竞价按行情自动挂单执行, 成交后记账通知, 到期按 A 模式自动卖出。

**评价标准**(用户钉死, 贯穿全文): 操作尽量简单 + 利益最大化 + 可实操 + 完整表述。

**边界(首期范围)**:
- 首期只做**买入**自动化, 卖出(A 模式到期)首期走「系统提醒 + 手动确认执行」(Phase1), Phase2 再做卖出自动化
- 资金来源: 需用户确认「每日 1 万」的现金来源(券商账户可用资金), 计划生成前校验可用资金 ≥ 计划金额, 不足自动降额/跳过并告警
- 只做 ETF(A 模式回测宇宙=ETF), 不做个股
- 首期单账户, 账户切换(easytrader 已支持)留到 Phase2

### 1.2 信号链路(买入标的从哪来) —— 按用户定调 S06+K=1+A

- **买入标的选取 = AI仓位建议 K=1**: 从信号凯利回测入样宇宙(S06 动态基座 + 降亏键过滤 + A 模式三 rating 伪象限)按 `track_score DESC -> rating(high>mid>low) -> signal(buy_backup>buy>buy_aux>buy_special) -> buy_date ASC` 排序, **每日只保留最优 1 笔**; 金额 = 每日资金池 1 万等分(K=1 即 1 万/笔)
  - 证据: kelly_posrating.py L588-630 `_position_cap_kept_keys`, lab.js L7800 同构; latest_posrating.json `values.1 = {最激进, ret 163.37%, dd 3.89%, n 545}`
- **卖出方法 = A 模式(固定 10 天)**: `SELL_MODES["A"] = {label: 固定10天, hold_days: 10, stop_profit: None}` —— 买入后第 10 个交易日收盘价卖出, 不止盈不止损
  - 证据: signal_kelly_backtest.py L86, L774-775「模式 A/E/F: 最后一天卖出(不止盈)」; sell_reason="到期"
- **买入价口径 = 信号次日开盘价**: `KELLY_BUY_NEXTDAY=1`(v1.1.4 起默认) = 信号日收盘后固化, 次日开盘才成交; buy_price = 信号日 accum_nav × (次日原始 open / 信号日原始 close); 伪跳空(±20%)剔除
  - 证据: signal_kelly_backtest.py L669-688
- **每日计划产物** = 每天一条 {signal_date, buy_date(次日), etf_code, etf_name, 挂单价上限(昨收), amount 1万, signal, track_score}: 由回测同一逻辑在线化生成(见 §3)
- **卖出产物**: 回测已有 sell_date/sell_price(复权), 实盘卖出按第 10 交易日收盘价市价单执行

## 2. 每日时间轴(pipeline)

```
T 日盘后                               T+1 日(执行日)
17:50 update-all(数据)                  9:15  计划校验+集合竞价挂单(昨收价限价单)
  ↕ 信号/回测/快照数据就绪                 9:25  撮合成交: 开盘价 = O; 挂单 > O 时以 O 成交
20:35 s06-snapshot(定稿+T日状态)          9:25-9:30 查成交(/today_trades) -> 成交则记账并通知
20:40 daily-brief                       9:30-14:45 未成交则盯盘: 每 5 分钟查价格, 回落至挂单价自动成交
21:00 次日买入计划生成(新任务)              14:55 仍未成交 -> 尾盘市价兜底买入(保证资金投出)
21:05 计划通知(邮件+飞书+页面)             15:00 收盘 -> 全天执行总结告警
```

**各步「谁·干什么·产出·失败怎么办」**:

| 步骤 | 时点 | 由谁 | 干什么 | 产出 | 失败处理 |
|---|---|---|---|---|---|
| 1. 数据就绪 | 17:50-20:35 | 既有任务链 | update_all + s06_snapshot 定稿 | signal_kelly_trades/backtest/s06_state/posrating | 20:35 快照 FAIL -> 计划生成延后 1 小时重试, 仍失败 -> 发告警并跳过当日计划 |
| 2. 生成次日计划 | 21:00 | 新增 launchd `com.trade.nextday-plan` | 读以上 4 产物 + etf_daily 昨收 -> 判定 T 日 K=1 top1 标的 -> 生成 plan JSON | `data/nextday_plan.json` {date, plan:[{etf_code,name,prev_close,amount,signal,track_score}]} | 无信号/T日非交易日 -> 空计划跳过; 生成失败 -> 告警 |
| 3. 计划通知 | 21:05 | 同脚本尾段 | 邮件/飞书推送「明日计划」(复用 notify 链路) | 通知 | 发送失败->记录, 次日照常执行 |
| 4. 集合竞价挂单 | 9:15 | 新增 launchd `com.trade.nextday-exec` | prepare 校验登录 -> 查 /balance 可用资金 -> 挂限价买单 `price=昨收` | 委托号 | 登录失败 -> 重试 3 次 -> 仍失败走 9:30 市价兜底; 资金不足 -> 降额到可用资金 |
| 5. 开盘确认 | 9:25 | 同脚本 | 查 /today_entrusts|/today_trades | 成交/未成交状态 | 9:25 查不到 -> 9:30 后再查一次(撮合可能晚) |
| 6. 盯盘回落 | 9:30-14:45 | 同脚本后台循环 或 独立轮询 launchd(5min) | 未成交单: 若行情回落至挂单价以下自动成交(委托单已挂在盘面上, 无需操作) | 成交回报 | 无需操作(限价单挂在盘面自动成交); 只需查成交 |
| 7. 尾盘兜底 | 14:55 | 同脚本 | 仍未成交 -> 撤单 + 市价单买入 | 成交回报 | 市价单失败 -> 15:00 后告警「当日计划未执行」 |
| 8. 记账通知 | 15:05 | 同脚本尾段 | 写本地账本(§6) + 邮件/飞书执行总结 | 账本记录 + 通知 | - |
| 9. 到期卖出(A 模式) | buy_date+10 交易日 15:00 | Phase1: 系统 9:00 提醒手动; Phase2: launchd 自动 | 第 10 交易日收盘市价卖出 | 卖出成交回报 | 卖出失败 -> 次日继续提醒/重试 |

**关键设计**: 集合竞价挂单用**昨收价**限价单(理由见 §4 回测结论), 9:25 撮合时若开盘价 O ≤ 昨收(低开)则系统自动以 O 成交(比挂单价更好), 若 O > 昨收则挂单保留进入连续竞价, 等待盯盘回落成交; 14:55 仍未成交 -> 撤单改市价兜底。

## 3. 信号 -> 计划生成模块

**输入**(全部是 T 日盘后已定稿产物, 数据源唯一, 不自行重算):
1. `static-site/data/signal_kelly_trades.json`(17:50 export 生成, 含当日最新信号与回测记录, 26 字段/笔)
2. `static-site/data/signal_kelly_backtest.json`(config.sell_modes 定义 A 模式)
3. `static-site/data/kelly_mode_s06_state.json`(20:35 重生, T 日 S06 状态)
4. `static-site/data/kelly_loss_features.json`(降亏特征, 低频)
5. `data/etf_national_team.db` etf_daily(取标的昨日收盘价 -> 作为次日挂单价上限)

**生成逻辑**(与回测完全同构, 防前视一致):
1. 复用 `kelly_posrating.py` 模块: `make_passes_fade`(S06 动态基座+降亏键过滤) + `_collect_base_pool`(入样宇宙去重) + `_position_cap_kept_keys(K=1)`(每日 top1)
2. 对当日(signal_date = T)通过过滤且被 K=1 保留的交易 -> 生成计划条目
3. 每条: `{etf_code, etf_name, prev_close(昨日收盘=挂单价上限), amount:10000, signal, track_score, signal_date:T, buy_date:T+1}`
4. 空计划(无信号/非交易日/无标的) -> 正常跳过, 写 `nextday_plan.json {date, empty:true}`

**双校验**(生成时):
- 信号非空 & 标的有 ETF 跟踪(track_tier != 空, 已在入样宇宙保证)
- prev_close > 0 且非停牌(etf_daily 该标的前一日有成交)
- 价格合理性: prev_close 相对信号日收盘 涨跌幅在 ±20% 内(伪跳空剔除同款)

**产出**: `data/nextday_plan.json`(本地) + 同步 `static-site/data/nextday_plan.json`(用户页面可见次日计划) + R2/CF(§22 三步同步)。

## 4. 执行模块(挂单策略 —— 数据回测定稿)

### 4.1 回测设计

对 **S06+K=1+A 模式全史 545 笔交易**(2011-2026, 每笔信号次日买入、第 10 交易日收盘卖出, 每日资金池 1 万), 用 `etf_daily` 的 open/high/low/close **重放买入执行方式**, 对比 5 种挂单策略 vs 开盘直接买:

| 策略 | 定义 |
|---|---|
| S0-baseline | T+1 开盘价直接买入(= 回测基准 buy_price) |
| S0-挂昨收 | 9:25 集合竞价挂「昨日收盘价」限价单; O≤昨收 -> 以 O 成交; O>昨收且日内 L≤昨收 -> 以昨收成交; 否则未成交 |
| S(d)+skip | 挂「昨收×(1-d)」折扣单; 未成交 -> 放弃(资金留存) |
| S(d)+tail | 挂「昨收×(1-d)」折扣单; 未成交 -> 14:55 尾盘市价兜底(C×(1+0.1%)) |
| 盯盘价值 | 仅集合竞价成交(60% 低开) vs +回落触及(85.3%) 的差 |

### 4.2 回测结果(545 笔, 卖出沿用 A 模式第 10 交易日收盘)

```

S0-挂昨收价限价(skip):               +165,407 元  收益率 +3.03%  成交率 85.3%(低开60%+回落25%)
挂昨收-0.3% skip:                     +120,468 元  收益率 +3.21%  成交率 68.8%
挂昨收-0.5% skip:                     +108,814 元  收益率 +3.32%  成交率 60.2%

挂昨收-1.5% skip:                      +44,753 元  收益率 +4.39%  成交率 18.7%

### 4.3 用户假设验证(用户原话给的回测口径)

| 用户假设 | 实测(数据说话) | 结论 |
|---|---|---|
| 挂 -0.5% 有 85% 成交 | **60.2%**(对昨收基准) | 高估 ~25pp |
| 挂 -1% 有 60% 成交 | **34.5%** | 高估 ~25pp |
| 挂 -0.5% 成交均价 -0.275% | 成交折价 **-0.426%**(平均每万省 42.6 元) | 实测折价更深, 更好 |
| 挂 -1% 成交均价 -0.2% | **-0.755%** | 更好 |
| 「综合平均买入价最低 + 成交率够高」最优档 | skip 口径 -0.6%~-0.8% 综合最优(-0.271%/-0.281%), -0.5% 接近最优且简单 | **方向对, 落在 -0.5% 附近合理** |
| 未成交「收盘改市价」假设 | 尾盘兜底(tail)全档位总收益 12.9~14.8 万 < 开盘直买 15.8 万 | **该假设负优化**: 尾盘 C 平均高于开盘 O, 兜底买贵吃掉折扣 |

### 4.4 回测结论(推荐默认执行策略)

1. **集合竞价挂「昨收价」限价单是纯增益且最简单的执行方式**: 85.3% 成交(60% 低开以更低的开盘价成交 + 25% 日内回落至昨收成交), 全史 +165,407 元 > 开盘直买 +158,397 元(+4.4%), 且操作只是「9:25 前挂一单」, 无盯盘压力。
2. **盯盘回落价值 ≈ +3.2 万元**: 挂昨收价若只做集合竞价(60% 成交)不盯盘, 会漏掉 138 笔「高开回踩昨收」的成交(25%), 这部分全史约值 3.2 万元。自动化系统建议做 9:30 后回落盯盘(限价单挂盘面自动成交, 系统只需查成交, 无需主动操作)。
3. **尾盘兜底是负优化, 但资金全投约束下可接受**: 若系统「当日必须投出」(用户原话「未成交收盘改市价」), tail 全档位都比开盘直买略差(-0.7%~-1.5%)。**若要绝对收益最大, 挂昨收价+盯盘(85% 成交)+15% 尾盘兜底 ≈ 开盘直买水平**。
4. **收益率 vs 绝对收益的取舍**: 折扣越深(放弃未成交), 收益率越高(+2.91% -> +4.39%)但绝对收益和资金利用率骤降(15.8 万 -> 4.5 万, 成交率 85% -> 19%)。**推荐默认 = 挂昨收价(不折扣或 -0.3% 微折) + 盯盘 + 尾盘兜底**(资金全投, 绝对收益最优, 简单); **可选模式 = 挂 -0.5% + 放弃**(资金可闲置时提高每万收益率 +0.40pp)。
5. **稳定性**: 挂 -0.5% skip 按年 13/15 年优于开盘直买, 分半两半均优(前半 +3.83% vs +3.38%, 后半 +2.83% vs +2.45%), 方向一致。S0 胜率 69.4%(A 模式固定 10 天)。

### 4.5 执行时序明细(调 easytrader 哪个接口)

| 步骤 | 接口 | 参数 | 说明 |
|---|---|---|---|
| 连接校验 | POST /prepare | broker=ths | 确认已登录, 失败重试 3 次 |
| 查资金 | GET /balance | - | 可用资金 ≥ 计划金额, 不足降额/跳过 |
| 挂限价单 | POST /buy | security=etf_code, price=昨收价, amount=按金额算的 100 份整数倍 | 返回 entrust_no; 9:15-9:20 可撤改价 |
| 查成交 | GET /today_trades | - | 9:25 后查是否成交; 部分成交处理(见 §6) |
| 盯盘查价 | GET /today_trades / /position | - | 9:30-14:45 每 5 分钟查(限价单自动成交, 无需改单) |
| 尾盘兜底 | POST /cancel_entrust + /market_buy | entrust_no; security+amount | 14:55 撤未成交单, 改市价买 |
| 到期卖出 | POST /market_sell | security, amount(全部持仓) | Phase2; Phase1 提醒手动 |
| 手动开关 | 配置项 `AUTO_EXEC_ON` | bool | false = 只生成计划不执行(干跑) |

**下单前置校验**(每次下单前):
- 可用资金 ≥ 委托金额(含费用估算)
- 持仓不重复(该 etf 无未卖出持仓/当日已买不重买)
- 当日计划幂等(计划 date=今日 & 未执行过)

**失败分类与重试策略**:

| 失败类型 | 判定 | 重试策略 |
|---|---|---|
| 登录失败 | /prepare 非 2xx 或 423 需人工 | 重试 3 次(间隔 30s) -> 仍失败 9:30 转市价兜底 -> 告警 |
| 验证码风控 | 接口超时/500 | 服务端已自动解卡; 客户端等 1s 节流后重试 |
| 资金不足 | /balance 可用 < 委托金额 | 降额到可用资金; 仍不足 -> 跳过+告警 |
| 限价未达 | /today_trades 无该委托成交记录 | 不重试(限价单挂着), 走盯盘/尾盘兜底 |
| 接口异常 | HTTP 5xx / 超时 | 重试 3 次(指数退避 1s/3s/9s) -> 告警 |
| 委托被拒(涨跌停/废单) | /today_entrusts 状态=废单 | 记录 + 告警 + 转市价兜底(如涨停价无法成交则放弃并告警) |

## 5. 风控与熔断

| 风控项 | 规则 | 触发动作 |

## 6. 结果确认与记账

- **成交回报读取**: 队列监听(easytrader 服务端已有队列)或轮询查询 `/today_trades`(9:25 后必查 + 盯盘每 5 分钟 + 15:00 收尾)

- **写入本地账本**: **独立新账本** `data/auto_trade/ledger.json`(不污染 signal_kelly_trades 回测结构):
  ```
  {date, plan_id, etf_code, etf_name, signal_date, buy_date,
   planned_amount, plan_price(=昨收), actual_price, actual_shares, actual_amount,

## 9. 用户可执行操作指引(未来页面展示用 · 白话版)

> 目标用户: 你(系统主人)。每天只需要在手机上花 1 分钟看两条消息, 其余全自动。

### 每天流程(白话)

**晚上 21:00 左右**(交易日):
- 系统自动算出「明天要买什么」(规则: 每天只买 1 只, 每天 1 万元, 选跟踪分最高的那个信号, 就是你现在首页「AI仓位建议 K=1」推荐的那只)
- 你会收到: 邮件/飞书推送「明日买入计划」, 长这样:
  - `明日计划: 512480 半导体ETF国联安 | 昨收 1.082 | 买入 1 万元 | 信号: buy_special | 跟踪分 36.2`
- **你只需瞄一眼**, 不需要操作; 想拦住它 -> 回一句「停」或登录页面关掉自动开关(见下)

**次日早上 9:25 前**(系统自动):
- 系统在 9:15-9:25 集合竞价期间, 以「昨收价」挂限价买单
- 集合竞价撮合规则: 如果今天低开(开盘价 < 昨收), 你就按**更低的开盘价**买入(白赚); 如果高开, 单子保留, 等盘中跌回来按昨收价买入
- 9:25 后: 如果成交了, 你收到「✅ 已买入 512480, 成交价 1.061」; 如果没成交, 系统盯盘, 跌到昨收价自动成交; 到 14:55 还没成交, 系统撤单按当时市价买入(保证今天一定买上)

**第 10 个交易日(系统提醒)**:
- 持有 10 个交易日后系统提醒「到卖出日」, Phase1 你确认后手动卖出(或 Phase2 全自动)
- 卖出后给你一笔记账: 买入价/卖出价/盈亏

### 手动开关(安全兜底)

| 开关 | 位置 | 效果 |
|---|---|---|
| 自动买入总开关 | 配置 `AUTO_EXEC_ON` | 关 = 只生成计划不执行(干跑) |
| 一键全撤 | easytrader 面板 /cancel_all_entrusts | 撤当日全部挂单 |
| 熔断状态 | 连续 3 天失败自动停 3 天 | 停单后需人工确认恢复 |

### 1:1 实例(拿真实数据说话)

以回测 545 笔为例(2011-2026, S06+K=1+A 模式, 每日 1 万):
- 全部用「昨收价挂单」: 85.3% 的交易日能买成(其中 60% 是低开, 直接按更便宜的开盘价成交), 剩下 14.7% 尾盘市价兜底
- 比「开盘直接买」全史多赚 7,010 元(每笔平均多赚 12.9 元), 而且操作零负担(就是挂一单)
- 如果挂「昨收-0.5%」且没成交就放弃: 只有 60.2% 能买成, 但买成的每笔平均比开盘价便宜 42.6 元, 每万收益提高 0.40pp —— **代价是 40% 的天数买不到**(资金闲置)
- 用户原假设「挂-0.5% 85%成交」经数据验证实际是 60%,「收盘改市价兜底」经验证是负优化(尾盘价平均比开盘价贵) —— 这两点已按真实数据修正进本 PRD

**简单口诀**: 晚上看一眼计划 -> 早上系统自动昨收价挂单 -> 成交了看推送 -> 10天后卖。全流程最多 3 条手机推送。
