- **多源多维度换方法**:调研"无/0/不可改善"类结论,不只验证当前算法覆盖范围,换方法/换数据源(第三方平台如同花顺概念搜索)+考虑不同关联维度(持仓重叠 vs 成分重叠),不轻断"不可改善";调研结论里列"已验证哪些方法/数据源"便于主控判断充分性(L13 量子科技"0量子ETF"误判)
- **归属/分类前复述口径**:null/极弱/无匹配等分类归属前复述口径让用户确认,不靠语义猜测(L08 ETF拆档null归属:null 有 ETF 算得出分应归"有跟踪ETF"档,非"概念无ETF")
- **口径验算**:指定计算口径前先验算典型值合理性,年化>100% 或负值应警觉查口径定义(L14 annualized:总盈亏/单笔本金 开方 y1=258% 不合理,改峰值资金收益率才合理)
- **断定前验证**:不凭 memory/印象断定,memory 可能过时(L04 .gz凭memory断定)
- **结论带证据**:每个结论带可复核证据点(文件:行号/命令输出/数据值),不自称"大概/应该";读到即用不反复重查

## 3. §5.1 数据回测穷举最大化执行规范(2026-08-12 用户定)
- **用户原话**:"不要怕久或者要跑的多。我愿意等。我希望你走的是最大化最完整的穷举回测跑数据模式" + "具体还是要你用数据说话。给我跑出结果后给我建议。我主要是提供想法"
- **核心 5 条**:
  - ①**穷举最大化**:回测不省计算/不怕久,用户明确愿意等;所有待验证维度全跑(报告"待进一步验证"项不留尾巴:K 值敏感性全谱/前向测试样本外/组合规则/叠加全矩阵/按年分解/模式敏感性)
  - ②**数据说话**:结论必须用真实回测数据支撑,不主观臆断;交互/产品形态疑问(多选vs单选等)也要数据+逻辑双支撑回答
  - ③**口径对比**:用户提出新口径时,新旧口径全对比(最大持仓元/收益率/净盈亏/是否爆炸),用数据选优,不预设
  - ④**诚实标注**:退化年/转负模式/净利降幅是设计还是 bug 都如实标注,不选择性隐瞒
  - ⑤**全局核心问题报告维度全**(2026-08-19 用户定,教训:四档升级 v2 主报告只给总量前3,稳定性/按年/回撤/大熊市全被用户提醒才补,补测见 docs/market-state/kelly-fourtier-v2-multiindex-stability.md):凡「多方案选优/换判定源/换口径/动默认组合或核心实用功能」这类**全局核心问题**的报告,默认必须一次给全维度,不靠用户点名补。**维度清单(出报告初稿前先自查,缺=验收不过)**:①基线复现(基准落在 v1.1.0/v1.1.2 定义 §5.4) ②按年分解(含领先是否靠近期行情撑起/剔除近期行情重排) ③稳定性(按年方向一致率/分半/共享cap vs 按年独立/cap敏感性) ④回撤与恢复(最大回撤金额·占本金%/谷日/恢复日/恢复期) ⑤大熊市及极端窗口专项(单边熊/阴跌/独立走弱窗口逐一测) ⑥不同周期/参数变体(9模式矩阵/P档/K档等) ⑦口径诚实标注(归因证伪/表述修正/对照不纯,不选择性隐瞒)。报告末尾附「维度清单完成度」表格,漏列维度=用户点名补=违规。
- **认知有限→上网调研算法**(2026-08-12 用户强化,原话"如果你的认知有限 可以去往上调研可用的数据分析 数据挖掘。和不同算法来跑"):自己知道的方法不够/不确定最优时,主动 WebSearch/WebFetch 调研业界可用的数据分析/数据挖掘方法(如决策树/关联规则/聚类/因子挖掘/组合优化/ML 分类等)与不同回测算法,挑合适的拿来跑,不固守自己会的几种;调研后落档 docs/ 方法论,供后续复用

### 3.1 防前视铁律=调研回测核心宗旨(2026-08-23 用户定,§5.1⑥ 全文;也是防过拟合手段)
> 用户原话:「牛熊分界等这种变化信号一定不能是后视镜模式。就是在某个时间点只能用时间点前的数据信号判断,不能用未来的数据判断过去」。
- **适用**:任何择时/状态/切换类信号(牛熊分界/QVIX 分位/市场宽度阈值/两融北向状态等)在时间点 t **只能用 t 之前的数据判定**;惯例=t 日收盘出信号、t+1 日生效;报告必须含「防前视」专节。
- **三条硬机检(验收项,缺一不过)**:
  1. **分位数阈值禁用全期分位**(最易踩暗坑):「X 处于历史 N% 分位」若分位按全样本算=暗用未来数据;必须 expanding(截至 t 的全部历史)或滚动窗口分位,并写明窗口参数;
  2. **特征库固化口径核查**:复用既有特征库(如 mine10_features)先逐特征核查其分位/阈值的固化口径,全期固化的重算纯历史口径再入状态库,核查结论逐条列进报告;
  3. **时点穿越测试**(机检):选 2-3 个历史时点 t,把数据截断到 t 重算全部信号序列,断言与全量数据算出的 t 之前部分**逐位一致**;不一致=存在前视,修到一致为止。测试代码进 scripts 同目录可复跑。
- **同族精神**:回测侧 ETF 冻结防换标(signal_kelly_etf_freeze.json,memory kelly-etf-freeze-lookahead)——成交日冻结标的防未来信息;全期排名/事后最优参数不能直接当切换条件(样本外必做:选段找规则、验段验证)。
- **实施联动**:回测结论出来前,实施 agent 代码结构先支持多口径/多档位可配置,数据定稿后直接切默认值,不返工

### 3.2 复现脚本同构对账铁律:第二份实现必对账,报告数字必对页面(2026-09-02 用户定,repro 脚本假数字 P0 事故)
> 根因(a 5357077f3 s06NoBull bug):`trade-method-final-repro.mjs` node vm 切片复刻前端「s06NoBull」返回过滤器对象(恒 truthy)而非布尔 → G/H/I 长线模式不过滤 → 报告 H 近1年 **-5.17%/-4.70% 假数**;页面真实是 **+25.20%**(Playwright 无痕浏览器实测钉死)。假数字进 09-01 报告 → 用户质疑 → 核数 agent 误判「你切过档位」→ researcher 无痕实测才钉死 → 多轮排查浪费。**切片复刻=第二份实现,前端改逻辑副本不自动跟,漂移是必然;无对账即发布=假数进报告。**
- **触发词**:写/改报告复现脚本、回测脚本、任何"复刻前端逻辑/前端同构引擎"脚本;数字与页面不一致时;报告数字发布前。
- **① 同构对账机检**:复刻脚本必须有「脚本输出 vs 页面真实渲染」的逐位对账断言(至少覆盖 GIH 模式×y1/all 两周期),漂移即 FAIL 不静默;每次前端算法改动后必须重跑对账
- **② 页面实测锚点优先(第一手段)**:涉「页面显示数字」对账,用 Playwright/puppeteer **无痕浏览器**实测(零 localStorage),**禁止预设"用户记错/切过档/看错位"**——先测页面再定性,researcher 自己造不出页面就是能力不足要明说
- **③ 报告发布前对账**:任何进报告的核心数字(尤其是「结论/主推建议」依赖的数字)发布前,至少抽样一次与页面实测对账;对不上=停,查根因再发
- **④ 诚实标注修复链**:发现假数字修正后,报告复现段标注修复说明(改了什么、页面实测锚点值),旧假数保留在诚实标注段可反查;**勿让用户看旧报告当现行**
- **⑤ 切片的函数级审计**:切片复刻前端长函数时,逐词对照原函数(s06NoBull 实例:原函数 `return passesFadeNoBull(...)` vs 复刻写死 `return _s6NB[b.base]`),类型/返回值布尔 vs 对象是最易漂移点
- **验收口径**:涉复刻脚本/报告数字任务自验含「同构对账机检 PASS + 页面实测锚点 + 报告复现段修复说明」,缺任一=验收不过。对应 CLAUDE.md §5.4⑦(共享核心反向标注) + §23.5 报告闭环;全文见 memory `repro-script-second-implementation-drift`。

## 4. 数据挖掘方法论(教训 E10/E12 提炼,多特征组合优化场景)
- 决策树/子群发现:手写 CART 决策树+beam search 子群+关联规则+多维交叉,超越人工 2 特征穷举,找高纯度叶节点=高比值标志
- 数据挖掘盲区发现:对比数据源全部字段 vs 历轮实际挖过的字段,未覆盖字段=最大机会(降亏第三轮 market_state 从未挖过=盲区=优先挖掘目标)
- 多 toggle/标志评估:新候选必须算叠加现有配置的边际贡献,不被 standalone 比值误导(E13)
- 多轮挖掘前先核对字段覆盖(E12)
