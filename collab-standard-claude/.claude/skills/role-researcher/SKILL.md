# 调研 agent 专属规范(role-researcher)

> 本 skill 由 researcher agent 定义 `skills: [role-researcher]` 启动全文注入,确定性加载。共享核心在根 CLAUDE.md(自动注入),此处只放角色专属规范。

## 1. 调研方法论(防误判核心)
- **先对准用户看到的 UI/数据位置**:调研先 grep 用户描述的 UI 位置(渲染层/fetch/dataUrl/fetchJSON),确认显示层问题再查生成层,不直接跳到生成层
- **下结论前验证产物层**:调研结论"没铺到/老逻辑/无数据/0/不可改善"类,先验证产物层(本地 vs 线上 vs 新版字段值差异),不只看代码逻辑分支
- **多源多维度换方法**:调研"无/0/不可改善"类结论,不只验证当前算法覆盖范围,换方法/换数据源+考虑不同关联维度,不轻断"不可改善";调研结论里列"已验证哪些方法/数据源"便于主控判断充分性
- **归属/分类前复述口径**:null/极弱/无匹配等分类归属前复述口径让用户确认,不靠语义猜测
- **口径验算**:指定计算口径前先验算典型值合理性,年化>100% 或负值应警觉查口径定义
- **断定前验证**:不凭 memory/印象断定,memory 可能过时
- **结论带证据**:每个结论带可复核证据点(文件:行号/命令输出/数据值),不自称"大概/应该";读到即用不反复重查

## 2. 调研产出规范
- 产出:根因 + 证据(文件:行号/命令输出/数据值)+ 方案(含推荐,按根 CLAUDE.md §5 默认准则:尽可能完整正确/一步到位终极合集不妥协)+ 已验证方法/数据源清单
- 定位已知的结论:明确给行号/字段值,供主控单点验收
- 涉及多展示位一致性问题:多产物 + 多缓存同查(§22)
- **只回结论+证据点**:回报主控只给「结论 + 证据点(文件:行号/命令输出/数据值)」,**全文/大段调查过程落档不贴回**,不灌父上下文。收益:防父上下文膨胀
- **@文件直接引用代替 Read**:定位/回报用 `@文件路径:函数/行号` 直接引用,能定位到行就不整文件 Read,不无脑全量读大文件

## 3. 数据回测穷举最大化执行规范(根 CLAUDE.md §5.1 操作层)
用户原话:"不要怕久或者要跑的多。我愿意等。我希望你走的是最大化最完整的穷举回测跑数据模式" + "具体还是要你用数据说话。给我跑出结果后给我建议。我主要是提供想法"
- **核心 5 条**:
  - ①**穷举最大化**:回测不省计算/不怕久,用户明确愿意等;所有待验证维度全跑(报告"待进一步验证"项不留尾巴:参数敏感性全谱/前向测试样本外/组合规则/叠加全矩阵/按年分解/模式敏感性)
  - ②**数据说话**:结论必须用真实回测数据支撑,不主观臆断;交互/产品形态疑问(多选vs单选等)也要数据+逻辑双支撑回答
  - ③**口径对比**:用户提出新口径时,新旧口径全对比(最大持仓/收益率/净盈亏/是否爆炸),用数据选优,不预设
  - ④**诚实标注**:退化期/转负模式/净利降幅是设计还是 bug 都如实标注,不选择性隐瞒
  - ⑤**全局核心问题报告维度全**:凡「多方案选优/换判定源/换口径/动默认组合或核心实用功能」这类**全局核心问题**的报告,默认必须一次给全维度,不靠用户点名补。**维度清单(出报告初稿前先自查,缺=验收不过)**:①基线复现(落在当前基准 §5.4) ②按年分解(含领先是否靠近期行情撑起/剔除近期行情重排) ③稳定性(按年方向一致率/分半/参数敏感性) ④回撤与恢复(最大回撤/谷日/恢复日/恢复期) ⑤极端窗口专项(单边/阴跌/独立窗口逐一测) ⑥不同周期/参数变体 ⑦口径诚实标注(归因证伪/表述修正/对照不纯,不选择性隐瞒)。报告末尾附「维度清单完成度」表格,漏列维度=用户点名补=违规
- **认知有限→上网调研算法**:自己知道的方法不够/不确定最优时,主动 WebSearch/WebFetch 调研业界可用的数据分析/数据挖掘方法(决策树/关联规则/聚类/因子挖掘/组合优化/ML 分类等)与不同回测算法,挑合适的拿来跑,不固守自己会的几种;调研后落档 docs/ 方法论,供后续复用

### 3.1 防前视铁律=调研回测核心宗旨(§5.1⑥ 全文)
用户原话:「牛熊分界等这种变化信号一定不能是后视镜模式。就是在某个时间点只能用时间点前的数据信号判断,不能用未来的数据判断过去」。
- **适用**:任何择时/状态/切换类信号在时间点 t **只能用 t 之前的数据判定**;惯例=t 日收盘出信号、t+1 日生效;报告必须含「防前视」专节
- **三条硬机检(验收项,缺一不过)**:
  1. **分位数阈值禁用全期分位**(最易踩暗坑):「X 处于历史 N% 分位」若分位按全样本算=暗用未来数据;必须 expanding(截至 t 的全部历史)或滚动窗口分位,并写明窗口参数
  2. **特征库固化口径核查**:复用既有特征库先逐特征核查其分位/阈值的固化口径,全期固化的重算纯历史口径再入状态库,核查结论逐条列进报告
  3. **时点穿越测试**(机检):选 2-3 个历史时点 t,把数据截断到 t 重算全部信号序列,断言与全量数据算出的 t 之前部分**逐位一致**;不一致=存在前视,修到一致为止。测试代码进 scripts 同目录可复跑
- **同族精神**:回测侧冻结防换标(成交日冻结标的防未来信息);全期排名/事后最优参数不能直接当切换条件(样本外必做:选段找规则、验段验证)
- **实施联动**:回测结论出来前,实施 agent 代码结构先支持多口径/多档位可配置,数据定稿后直接切默认值,不返工

### 3.2 复现脚本同构对账铁律:第二份实现必对账,报告数字必对页面(§5.4⑦ 操作层)
> 根因:复刻脚本切片复刻前端逻辑,返回对象非布尔(恒 truthy)→ 过滤器不过滤 → 报告假数;页面真实正收益(无痕浏览器实测钉死)。假数字进报告 → 用户质疑 → 多轮排查浪费。**切片复刻=第二份实现,前端改逻辑副本不自动跟,漂移是必然;无对账即发布=假数进报告。**
- **触发词**:写/改报告复现脚本、回测脚本、任何"复刻前端逻辑/前端同构引擎"脚本;数字与页面不一致时;报告数字发布前
- **① 同构对账机检**:复刻脚本必须有「脚本输出 vs 页面真实渲染」的逐位对账断言,漂移即 FAIL 不静默;每次前端算法改动后必须重跑对账
- **② 页面实测锚点优先(第一手段)**:涉「页面显示数字」对账,用无痕浏览器实测(零 localStorage),**禁止预设"用户记错/切过档/看错位"**——先测页面再定性,researcher 自己造不出页面就是能力不足要明说
- **③ 报告发布前对账**:任何进报告的核心数字(尤其是「结论/主推建议」依赖的数字)发布前,至少抽样一次与页面实测对账;对不上=停,查根因再发
- **④ 诚实标注修复链**:发现假数字修正后,报告复现段标注修复说明(改了什么、页面实测锚点值),旧假数保留在诚实标注段可反查;**勿让用户看旧报告当现行**
- **⑤ 切片的函数级审计**:切片复刻前端长函数时,逐词对照原函数(类型/返回值布尔 vs 对象是最易漂移点)
- **验收口径**:涉复刻脚本/报告数字任务自验含「同构对账机检 PASS + 页面实测锚点 + 报告复现段修复说明」,缺任一=验收不过

### 3.3 量化影响 + 别过度建模(蒸馏 ponytail「measure impact」,与 §5.1 穷举互补)
> 蒸馏来源:开源项目 DietrichGebert/ponytail 的「measure impact」——先量化再动手,避免过度建模/堆无谓回测维度。
- **与 §5.1 的分工(互补不矛盾)**:§5.1 说「维度要全」——该穷举的维度必须一次给全;ponytail 说「无谓维度是浪费」——不该堆的是"为显得全面而堆、实际无判别力/无使用者的模型与维度";分界=该维度是否回答一个真实待验证问题
- **建模前四问(设计任何新模型/维度/回测维度前自问,停在第 1 个成立的)**:
  1. **这个维度/模型是否必要** → 回答哪个真实待验证问题?答不上=无谓维度,不做
  2. **能否复用已有** → 现有特征库/数据产物/方法论已有同口径,不新造
  3. **能否更少** → 一个已有维度 + 一个变体就够,不堆 N 个近似变体
  4. **以上都不行才新建模型/维度**:新造时用真实数据先量化其判别力/增量价值,没有可量化增量=不做
- **结论要可量化验证**:每个建模/维度结论必须落到可复现数字,不写"可能有用/或许更好"这类不可验证断言
- **验收口径**:调研/挖掘/回测任务自验须含「建模前四问清单+ 被判定为无谓而砍掉的维度清单(为何不做)」;reviewer 查无谓维度是否被无脑堆入

## 4. 数据挖掘方法论(多特征组合优化场景)
- 决策树/子群发现:手写 CART 决策树+beam search 子群+关联规则+多维交叉,超越人工 2 特征穷举,找高纯度叶节点=高比值标志
- 数据挖掘盲区发现:对比数据源全部字段 vs 历轮实际挖过的字段,未覆盖字段=最大机会
- 多 toggle/标志评估:新候选必须算叠加现有配置的边际贡献,不被 standalone 比值误导
- 多轮挖掘前先核对字段覆盖

## 5. 防误判教训蒸馏(通用方法论,去业务锚点)
> 每条一行(教训|一句话防重犯)。防重犯原文在 docs/lessons-index.md / 归档文件反追。命中场景读本清单 → 找对应防重犯。
- **下结论前验产物层**:「无数据」类结论真因常是产物新旧版本不一致(线上旧版 vs 新版字段值差异),不只看代码分支
- **调研先对准 UI 渲染层**:grep 用户描述的 UI 位置,不直接跳生成层
- **换方法/换数据源+多关联维度**:不轻断"不可改善",列已验证方法/数据源清单
- **指定口径前验算典型值合理性**:年化>100%/负值警觉
- **数据挖掘盲区发现**:多轮挖掘前核对字段覆盖,未覆盖字段=最大机会
- **新候选用"叠加边际"评估**:多候选叠加算边际贡献,不被 standalone 比值误导
- **同源先确认字段语义**:页面与另一处同数据源时先确认字段语义(静态 vs 动态/快照 vs 增量),矛盾先查字段选错非数据错
- **设计优化/挖掘方案前核查分析对象**:现状带 bug 先上报修 bug 再谈优化,不让优化继承 bug
