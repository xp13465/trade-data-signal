## 删除前必备份且实测可恢复

- **现象**:清理文件/目录/缓存时,删完才发现删错了或还想用,而东西已经没了,不可逆。
- **根因**:删除是不可逆动作;在"无法恢复"的状态下删,任何后悔都无法挽回。
- **防再犯**:任何删除类动作,**先做备份再删**:①备份必须存在至少一份**可独立恢复**的副本(异地/远端/打包归档),且**备份完成于删除之前**;②备份要**实测可恢复**(清单全量比对 + 抽样取回逐位一致),不是"应该有备份";③验过即直接删(已建立可逆性,不必逐项请示),**验不过就停下报警**,绝不"先删再说";④删除报告要写明**怎么恢复**(从哪取回 + 恢复命令),写不出=不算可逆=不许删。
- **反例/代价**:无备份删除=一旦删错就无法挽回;最常见的悔恨是"以为不需要了,结果还需要"。
- **来源**:§25、mem:backup-before-delete-reversible(原项目编号/记忆名,仅供溯源)

## 有备份不等于可以删

- **现象**:看到一个"有备份"的旧镜像/旧副本,就当作冗余清掉;但它其实是被刻意保留的"回退保险",不能被清。
- **根因**:把"有备份"等同于"可以删",忽略了它可能是某次拍板刻意保留的回退路径。
- **防再犯**:**有备份 ≠ 可以删**——既有的保留决定优先;保留对象是"保险"不是"垃圾",清理前先确认它有没有被显式保留(如"保留至某个到期日")。
- **反例/代价**:清掉刻意的回退保险,等于在下一次需要回退时无路可退,风险从"有保障"变成"裸奔"。
- **来源**:mem:staticdata-old-mirror-keep-decision(原项目编号/记忆名,仅供溯源)

## 删除或重构前先列删除与保留清单

- **现象**:重构/删除时凭印象改,删掉了还在用的东西,或保留了本该删的旧物,越改越乱。
- **根因**:动删除前没系统核对"哪些该删、哪些该留";只凭印象容易搞反。
- **防再犯**:删除/重构前,先看原实现,列出**删除清单 + 保留清单**,逐项确认;删前最好保留一份原实现(例如从版本历史里能看到),以便反查。
- **反例/代价**:删清单不核,容易删到在用的代码/数据,或在代码里留下"半删"的悬空引用。
- **来源**:L30(原项目编号,仅供溯源)

## 杀进程前先核实进程属主链

- **现象**:用进程名匹配去清理残留进程,结果误杀了同名的生产进程,把正在跑的服务杀了。
- **根因**:按名字匹配范围过宽,会命中同名的其它进程(尤其生产进程与测试进程同名);没核实目标进程的属主链。
- **防再犯**:杀进程前**先核实属主链**(目标进程是谁启动的、是不是你要清的那个);按端口精确定位再杀(`先找到占用该端口的进程号,再杀那个`)或用精确的唯一前缀匹配,**禁止裸按名字全量匹配**;清理测试实例前先排除生产进程。
- **反例/代价**:误杀生产进程会造成服务中断(即使有自动拉起,也是一次真实故障),且容易误伤不知情。
- **来源**:mem:kill-residual-verify-ppid-chain(原项目编号/记忆名,仅供溯源)

## 会翻滚的备份等于没有备份

- **现象**:以为备份一直在,"需要时取回就行";真要用时才发现备份被按天滚动覆盖了、或从没成功做过完整快照,取不回完整数据。
- **根因**:备份项按天/按期翻滚(新旧同名覆盖),或备份从未真正完成过完整快照;这种备份只保留了最近一份,历史不可重建。
- **防再犯**:灾备设计必须能**重建一份完整快照**——备份项要么带日期(不覆盖历史),要么有独立的全量快照;并**实测验证"能不能从备份完整恢复"**,不是只验证"备份文件存在"。
- **反例/代价**:会翻滚的备份形同虚设,出事时取不回历史状态,灾备承诺落空。
- **来源**:mem:r2-large-json-backup-never-complete(原项目编号/记忆名,仅供溯源)

## 覆盖写入前先加备份护栏

- **现象**:某次覆盖写入(上传/导出/重跑)把线上好数据覆盖成了坏数据,没有退路。
- **根因**:覆盖动作没有前置的备份护栏,一旦覆盖了错的源,好数据当场就没了。
- **防再犯**:覆盖写入**前先加备份护栏**(覆盖前先备份将被覆盖的目标);防误操作要设**多层防线**(闸门 + 路径白名单 + 审计留痕);覆盖后保留可回退的旧版本。
- **反例/代价**:无护栏的覆盖=一次误操作就让线上数据倒退到坏版本,且无旧版可恢复。
- **来源**:doc:237-r2-overwrite-backup-guard-design-20261009、doc:export-guard-implementation-20261003(原项目文档名,仅供溯源)
