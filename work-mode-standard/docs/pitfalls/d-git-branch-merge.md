## 冲突覆盖与版本倒退绝不静默

- **现象**:合并/提交/推送/发布环节出现了冲突、文件被覆盖、版本号倒退、diff 异常等苗头,处理者为了"先把流程走完"悄悄吞掉或绕过它。
- **根因**:冲突/覆盖这类问题如果当场吞掉,它会以更隐蔽、更晚的方式爆发;当下的"顺一下"换来的是后面前更大的坑。
- **防再犯**:任何冲突、覆盖、版本倒退、异常 diff,**绝不静默吞掉**——宁可当场卡住、上报,也不能"先过再修"把它藏起来;遇到苗头就回报(现象/根因/影响/是否已停下)。涉及合并/发布的任务,自验要含"全程无静默吞掉事件"。
- **反例/代价**:静默吞掉=把可控的小问题养成难查的大 bug,危害里还多了一层"没人知道它发生过"。
- **来源**:§23.11、mem:conflict-never-silent(原项目编号/记忆名,仅供溯源)

## 判分支独有内容用内容哈希逐位比

- **现象**:用三点 diff(如 `main...branch`)判断"某内容只在分支上有",得到的结论是假的——它把分支上其实已经合并的内容也报成"新增"。
- **根因**:三点 diff 的基准是两分支的合并基,不是目标的当前状态;当目标侧路径/历史有变化时,它会误报"分支独有"。
- **防再犯**:判断"内容在不在目标里""是不是分支独有",用**内容哈希(blob hash)逐位比对**(跨路径也比内容),不要相信三点 diff 的"新增"结论。
- **反例/代价**:误信三点 diff,会以为分支有独有改动而重复合并/重复搬运,或漏掉真正的独有内容。
- **来源**:mem:git-three-dot-diff-false-novelty(原项目编号/记忆名,仅供溯源)

## 拿版本控制输出当清单要防中文名漏扫

- **现象**:把版本控制命令的输出(如列出文件、列 diff)当文件清单喂给程序解析,结果带特殊字符/中文的文件名被转义成引号包裹的形式,程序静默漏扫了一批文件。
- **根因**:默认输出会对特殊字符做转义(给文件名加引号),直接按行解析就会把转义串当文件名,匹配不上真实文件。
- **防再犯**:拿版本控制输出当清单解析给程序用时,必须关掉转义(例如设置 `core.quotepath=false`)或用行分隔的空终止格式(`-z`),保证文件名原样、逐条成行。
- **反例/代价**:静默漏扫会造成"清单不全却不报错",后续按不完整清单做的操作(删除、同步、校验)全都缺项。
- **来源**:mem:git-output-needs-quotepath-false(原项目编号/记忆名,仅供溯源)

## 精准暂存,禁用全量暂存

- **现象**:提交时用"全量暂存"(`git add -A` 之类)一把梭,把工作目录里不该提交的大文件/临时文件也带了进去,推送被拒或污染仓库。
- **根因**:全量暂存会无差别纳入工作目录里所有未跟踪/已改动文件;工作目录里常有大文件、临时产物、本不该入库的东西。
- **防再犯**:暂存**精准指定**要提交的文件/目录,禁用全量暂存;提交前用 `git status --porcelain` 过一眼,确认没有意外文件被纳入。
- **反例/代价**:误带大文件会被远端拒绝(甚至撑爆仓库历史),清理要改写历史,代价高;误带敏感文件更麻烦。
- **来源**:mem:git-add-a-large-file-incident(原项目编号/记忆名,仅供溯源)

## 清理引用记录前先检查暂存区

- **现象**:跑"清理引用记录/垃圾回收"(reflog expire / gc)时,以为只是清理,结果把暂存区(stash)里的东西也一起清了,而之前声称"不删任何引用"。
- **根因**:某些清理命令的作用范围比宣称的更广,会连带影响暂存区等引用;清理前没先把暂存区单独摘出来。
- **防再犯**:跑这类清理命令前,先 `git stash list` 检查暂存区;暂存里有东西就先落成一个正式提交或用别的方式保全,再清理;清理后复核引用没被意外删除。
- **反例/代价**:连带清掉暂存区会造成"以为安全地清理了垃圾,结果丢了在途工作",且符合"声称不删却删了"的失真。
- **来源**:mem:git-reflog-expire-all-kills-stash(原项目编号/记忆名,仅供溯源)

## 改已推送提交用同串推新引用名

- **现象**:需要改动一个已经推送出去的提交,常规做法要强制推送(force),风险高(可能覆盖他人工作)。
- **根因**:强制推送会改写远端历史,可能覆盖别人基于旧历史的工作;在共享仓库里这是高风险动作。
- **防再犯**:把改好的同一条提交内容**推到一个新引用名**(新分支/新标签)即可,这是一次普通推送,不需要任何 force;需要的地方再去引用这个新引用名。判"内容有没有丢"用内容哈希逐位比。
- **反例/代价**:一开始就上 force,可能覆盖别人的提交;用新引用名可零风险达到同样目的。
- **来源**:mem:force-push-avoid-new-ref(原项目编号/记忆名,仅供溯源)

## 合文档分支前先核它只含文档

- **现象**:把一个"只该含报告/审查文档"的分支合入主线,结果把分支上顺带带的代码提交也一起合了进来。
- **根因**:分支往往不止一个提交,做文档的同时可能顺手提交过代码;合分支是"整条分支"进来,不是"只要那几个文档"。
- **防再犯**:合"报告/审查"这类文档分支前,**先核对它的改动面只含文档**(用改动统计看涉及的文件类型);发现夹带代码,先剔除或改用只挑文档的方式,再合。
- **反例/代价**:夹带代码一起合入主线,等于未经评审把代码带上了线,破坏"文档分支只走文档"的约定。
- **来源**:mem:merge-report-branch-carries-code(原项目编号/记忆名,仅供溯源)

## 合并前先取最新再核实本地引用

- **现象**:合并前本地引用是过期的,合并后发现有提交"凭空消失",其实是基于旧的本地引用操作的。
- **根因**:本地保存的远端引用不会自动刷新;基于过期引用做合并/比较,会漏掉最近其他人的提交,造成静默丢内容。
- **防再犯**:合并前**先取最新**(fetch),再核实本地引用的新鲜度(确认本地引用已包含远端最新);base 落后就先同步再提交,别基于旧 base 操作。
- **反例/代价**:基于过期引用合并=静默丢掉最近的提交,且丢得无声无息,要靠事后逐位比对才发现。
- **来源**:mem:main-merge-stale-local-ref-drop-commits(原项目编号/记忆名,仅供溯源)

## 合并中途失败会留半完成态

- **现象**:合并流程走到一半失败,仓库处在"半完成态"(一部分已合、一部分没合),而汇报时说"某改动已就位",其实它卡在中间。
- **根因**:合并是多步流程,中途失败不会回滚到起点;此时仓库状态既不等于起点也不等于终点,容易误报。
- **防再犯**:合并流程失败后,**汇报现状必须说清每个改动落在哪个分支/哪个提交**,明确"哪些已成、哪些没成、当前停在哪一步";不笼统地说"已就位"。
- **反例/代价**:把半完成态当完成态汇报,后续基于错误现状继续操作,会产生重复合并或漏合并。
- **来源**:mem:main-merge-fail-leaves-half-merged-main(原项目编号/记忆名,仅供溯源)

## 发版本先全量核对版本链

- **现象**:要发某个版本,只处理了被点名的那一个版本标记,没核对整条版本链,结果发现历史上有版本漏打标记,被默默补上没告诉人。
- **根因**:版本标记是一条连续的链;只做点名处,会漏掉链上的历史疏漏;发现疏漏后默默补,又剥夺了他人的知情与决策。
- **防再犯**:发版本/打标记第一件事 = **全量核对整条版本链**(从头到尾逐个确认齐不齐);发现历史疏漏,**先上报再补**,不默默补;验收口径 = 标记真实存在且已推送到远端。
- **反例/代价**:版本链断点会让"发版"这件事失真(以为发了其实链不全);默默补历史疏漏则掩盖了流程问题。
- **来源**:L40(原项目编号,仅供溯源)

## 报告类交付要四件套齐备

- **现象**:报告在索引里有条目,但本体其实没提交(还躺在本地未跟踪状态),别人按索引去找却找不到。
- **根因**:索引/引用先建了,产物本体却漏提交;或产物生成了但没纳入版本跟踪,索引与实际脱节。
- **防再犯**:报告类交付 = **四件套**(本体 + 生成脚本 + 复现段 + 配套提交),缺一不可;提交前核对本体真的被版本跟踪(不是未跟踪状态)。
- **反例/代价**:索引指着一个不存在的本体,别人按图索骥落空;复现段缺失则结论无法被独立复现。
- **来源**:L34(原项目编号,仅供溯源)

## 提交时间戳不等于任务触发时点

- **现象**:用某文件的提交时间戳去推断"某个任务是不是在那个时点跑过",得出结论,但两者其实没有对应关系。
- **根因**:提交时间戳是"这次提交发生的时间",与"任务是否被触发/执行"是两回事;任务可能没跑、跑失败、或产物由别的方式写入。
- **防再犯**:判断任务是否真的跑过,看**运行日志/产物生成记录**这类执行证据,不看提交时间戳;提交时间戳只能说明"提交了",不能说明"任务跑了"。
- **反例/代价**:用提交时间戳推任务行为,会把"没跑"误判成"跑了",据此下的排查/结论都建立在不成立的前提上。
- **来源**:mem:commit-timestamp-not-trigger(原项目编号/记忆名,仅供溯源)
