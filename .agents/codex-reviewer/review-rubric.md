# Codex Review Rubric —— 5 维评分表

> 用途：每份 codex report 的固定章节，让二审不再靠猜。
> 生效位置：作为 `.agents/codex-reviewer/SKILL.md` 的子规范引用。
> 状态：草案，跑 2 周后定稿。

## 评分总览

| 维度 | 满分 | 权重 | 核心校验 |
|---|---|---|---|
| 需求覆盖 | 30 | 30% | focus_areas 逐条命中，无遗漏 |
| 证据强度 | 25 | 25% | 每条 finding 有 path:line + 可复现命令 |
| 风险定性 | 20 | 20% | P0/P1/P2/P3 分级 + 触发条件清晰 |
| 落地建议 | 15 | 15% | 修复点可直接落 PR，不给"建议考虑" |
| 收尾合规 | 10 | 10% | schema + done 信号 + 原子写 |

总分 >= 85 PASS;70~84 需补;< 70 退回重做

## 维度 1：需求覆盖（30 分）

- focus_areas 每条都有对应 finding -> 满分
- 漏 1 条 -> 扣 10 分
- 漏 2 条及以上 -> 扣 20 分，且必须在 Open Questions 说明为什么没覆盖
- 禁止：把"没找到问题"写成"全部 PASS"而不列覆盖清单

## 维度 2：证据强度（25 分）

- 每条 finding 有真实 path:line -> 满分
- 有 finding 只有结论没有 path -> 每条扣 5 分
- 引用 agent 自验报告当证据 -> 每条扣 10 分（违反 L05）
- 红线：说不清具体输入/状态/路径的 finding，直接降为 P3

## 维度 3：风险定性（20 分）

- P0/P1/P2/P3 分级与 SKILL 定义一致 -> 满分
- 把 P3 写成 P0（噪音淹没真告警）-> 扣 10 分
- 把 P0 写成 P2（漏报）-> 扣 20 分
- 每个 finding 必须写清"什么场景下触发"

## 维度 4：落地建议（15 分）

- 给出可直接落 PR 的修复点 -> 满分
- 只给"建议考虑""可能优化" -> 每条扣 3 分
- 修复点必须含：改哪几个文件、改什么、改完怎么验证

## 维度 5：收尾合规（10 分）

- 报告先写 .tmp 再 mv -> 满分
- request_id 与请求一致 -> 满分
- 调用了 codex_review_complete.py 建 done 信号 -> 满分
- 进度文件 /tmp/codex-reports/<id>-progress.md 存在 -> 满分
- 缺任一项 -> 总分封顶 80

## 反向蒸馏通道

每份报告末尾加一栏 ## Codex 蒸馏建议，长期反向喂给本 rubric：
- 哪些 finding 反复出现 -> 说明 rubric 维度权重需要调
- 哪些 P0 总是被降级 -> 说明分级定义需要澄清
- 哪些验证步骤总是跳过 -> 说明 runbook 步骤需要细化
