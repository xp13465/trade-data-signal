# 防重犯锚点索引(lessons-index.md)

> 通用方法论教训全量归档,本项目去业务化(剔除具体域名 / 业务表名 / 业务算法名 / 业务数据产物名),只留「可移植的协作方法论教训」。逐条可反追原文。移植到新项目:保留本文件所有条目,把「<占位符>」替换为对应项目事实即可使用。
>
> 使用方式:命中场景 → 读本索引找对应防重犯 → `grep 锚点` 到 `<docs/archive/CLAUDE-errors-<月份>.md>` 反差原文(每条一节,含根因+场景+复现教训)。**归档前教训条数 == 索引行数 + 归档文件 grep 数,不一致=零丢失校验失败。**
>
> 记录规则(用户定):慢慢积累经验迭代完美,每次犯错追加,不重犯同类。每日/会话级总结走「历史对照」:先读全部历史过错 → 新过错先分类(全新模式→追加新条目;同一类复发→不新开条,在原条目加"第 N 次复发"标注+强化对应防重犯条款)。复发强化清单是总结必含产出。

| 锚点 | 主题 | 一句话防重犯 |
|---|---|---|
| G-I01 | 改算法/数值忘同步公示 | 改算法逻辑/数值必须同步改前端算法公示文案(前端公示说明文字);已复发 2 次,是用户铁律(§21) |
| G-I02 | 改代码必 bump 版本串+同 commit 重建产物 | 改静态源码必同 commit:改源 → bump 版本串 → 重建 min → push → 验线上 index 引用? 与产物内容 md5 一致;禁 reset --soft 对齐分支 |

| G-I04 | 修 bug 只补点名处不修根因 | 修 bug 走三铁律:修完整(先列同类错误面清单)+自测完成(全覆盖)+排查同类(根因修,不逐文件打补丁) |
| G-I05 | 做 A 只做 A 不举一反三 | 用户点名做 A 时,主动列出同模式/同数据源/同组件还被谁用+相关展示位,逐项覆盖,不只做点名处 |

| G-I07 | 改前端字串后缓存滞留 | 版本串必须随内容强制刷新(如发布序号而非纯内容哈希),改码同 commit bump;线上验证内容哈希==index 引用版本串 |
| G-I08 | 取决于前置数据就绪才敢说上线 | 上线必完整版:数据就绪清单+覆盖范围/展示范围核对,有残缺=每秒钟都是事故;发现"先上残缺版"念头立即上报停住 |
| G-I09 | 并发 worktree 不隔离 | 多实施 agent 必须独立 worktree(不看是否改不同文件:HEAD/分支/工作区是全局的,checkout 即错位) |
| G-I10 | reset --soft 留旧 M 脏文件 | 禁 reset --soft 对齐分支(reset --soft 只移 HEAD 不动工作区,留旧 M 脏文件被 build 读走);要让 HEAD 对齐用 checkout <commit> -- <文件>,确需 reset 事后 git status 核对无 M 脏文件 |
| G-I11 | 回测/测试口径与前端展示链路不一致 | 结论用 top-K 前过滤补位口径(与前端链路一致),删笔仅对照附注;替补盈亏必分解查 |
| G-I12 | 改数据产物漏"生成→挂载→机检→告警"四件 | 动态/状态/择时类功能数据供给链路四件(生成→定时挂载→机检→过期告警)缺一不算 done;静态/手动等降级形态必须作为方向分叉上报 |
| G-I13 | 删函数/键忘删调用方 | 重构/优化删 def 定义,必 grep 全仓调用方同步删;删定义忘删调用=静默失败 |
| G-I14 | 定义色值/几何等常量在多个前端组件直接写死 | 同一事实(颜色/尺寸/字段名)多处代码副本时 grep 全部登记点同步改,不靠人肉记忆;机检比对一致挂部署链 |
| G-I15 | 半路开工/续跑不查待办索引 | 开工前先查已落档未开发功能索引同模块项+预留位置(§23.4);同模块多任务不许后覆盖前 |
| G-I16 | 小任务不 spawn 子 agent | 单个小改动(A 级)主控直接改或打包,不每个 spawn 一个 agent(冷启动+重读成本高于直接改) |
| G-I17 | 写了新文档/产物不落档归类 | 新产物从创建起就放最合适位置+归类一次到位+索引当场更新;报告四件套(本体+生成脚本+复现段+配套 commit)缺一不可;commit 前 git ls-files 验已 tracked |
| G-I18 | 提交大文件/data 进 git | 绝不 git add -A;数据/大文件走产物目录/对象存储,不进 git 仓库 |

### 调研(分析层)专属

| 锚点 | 主题 | 一句话防重犯 |
|---|---|---|
| G-R01 | 下结论前不验产物层 | 调研"无/0/不可改善"类结论先验证产物层(本地 vs 线上 vs 新版字段值差异),不只看代码分支 |
| G-R02 | 调研不先对准 UI 渲染层 | grep 用户描述的 UI 位置,确认显示层问题再查生成层,不直接跳生成层 |
| G-R03 | 轻断"不可改善" | 换方法/换数据源+考虑不同的关联维度,不轻断"不可改善";列已验证方法/数据源清单 |
| G-R04 | 指定口径前不验算典型值 | 计算口径指定前先验算典型值合理性:年化>100% 或负值应警觉查口径定义 |
| G-R05 | 回测用不可操作口径当基准 | 回测/挖掘第一件事=确认基线落在当前基准;测非基准口径(剔除交易/裸模型/其他档位)必须显式声明+说明为何测+标注口径差异,不作主推结论 |
| G-R06 | 前视:分位数用全期 | t 时点只用 t 前数据判定;分位数阈值禁用全期分位,必须 expanding/滚动窗口并写明参数;时点穿越测试逐位一致才 PASS |
| G-R07 | 切片复刻逻辑漂移出假数 | 复刻脚本=第二份实现会静默漂移;报告核心数字发布前必须同构对账机检+页面无痕实测锚点优先+报告复现段标注修复链 |
| G-R08 | 数据挖掘盲区 | 多轮挖掘前先对比数据源全部字段 vs 历轮实际挖过的字段,未覆盖字段=最大机会 |
| G-R09 | 新候选不看叠加边际 | 多 toggle/标志评估必须算叠加现有配置的边际贡献,不被 standalone 比值误导 |
| G-R10 | 同源先确认字段语义 | 页面与另一处同数据源时先确认字段语义(静态 vs 动态/快照 vs 增量),矛盾先查字段选错非数据错 |
| G-R11 | 设计优化/挖掘方案时继承现状 bug | 现状带 bug 先上报修 bug 再谈优化,不让优化继承 bug |
| G-R12 | 外部系统未知行为闭门实验 | 排查跨厂商/网关/API 参数/第三方库未知行为,第一动作上网查社区+官方文档,自己推演方案用社区先例佐证,不闭门堆实验 |
| G-R13 | 穷举不彻底留"待进一步验证"尾巴 | 回测不省计算/不怕久,所有待验证维度全跑干净(参数敏感性/样本外/组合矩阵/按年分解),报告不留"待验证"尾巴 |
| G-R14 | 全局核心问题报告维度不全 | 多方案/口径/默认组合类全局核心问题报告默认一次给全维度(基线/按年/稳定性/回撤/极端窗口/参数变体/口径标注),不靠用户点名补 |

### 审查(审阅层)专属

| 锚点 | 主题 | 一句话防重犯 |
|---|---|---|
| G-V01 | reviewer 不改代码只挑错 | review 不看新功能,专看"改动可能影响哪些老功能";grep 改动文件被谁引用 + 跑关键老功能点,不占主控上下文 |
| G-V02 | 算法公示查证漏 | 实施改了算法/数值,查公示文案是否同步新规则;算法改了公示没改=review 不通过 |
| G-V03 | 前端重算对齐失 | review 前端 replay/recompute 类改动,取一个数据逐字段对比后端输出,不只汇总总计 |
| G-V04 | 验数据产物信 agent 自验 | 验数据产物必须真读线上文件(非同源文件/agent 自验);多层验收任一层信结论不验文件=漏洞 |
| G-V05 | 档位/阈值语义不附三源对照 | diff 含归类/阈值/档位语义时,必取「UI 文案↔产品文档↔代码现状」三源对照记录,缺源或对不上=FAIL;警惕「报告↔代码」互证闭环 |
| G-V06 | 静默失败不专查 | diff 含 try-except/catch/fallback 必查空 except/宽捕/option chain/return None 掩盖;监控脚本 exit 0 不可信 |
| G-V07 | finding 无 trace/verifier | 每条 finding 必带 diff_range/linkage/user_request(trace)+ command/expected/observed(verifier);<80 置信度不进报告但报告末尾附已滤数量 |
| G-V08 | 误报当 finding | 误报清单 6 类(有男主独有?)不算 finding:pre-existing(不算但走冻结契约上报)/机检已覆盖/纯 nitpick/未改动行上的问题/用户故意保留/已在待拍板队列 |
| G-V09 | 每步不 echo 进度文件 | 每步 echo /tmp/agent-progress-<名>.md,不写=主控无法监控按卡死重派 |
| G-V10 | 期望值核实漏 | 发现期望值与实际不符时,先查任务描述是否笔误,按真实数据判合规,不盲信任务描述期望值 |
| G-V11 | 帮人删代码/建议未经量化 | 给删除/简化建议附 action(delete/simplify)+saves_lines+rationale(命中 7 级阶梯哪一层),不空泛说"这段冗余" |
| G-V12 | 挡在历史防御代码前 | 「看似冗余实为修过某 bug 的防御代码」先 git log/blame 看历史意图,尊重历史防御代码,不硬删 |

### 测试(验证层)专属

| 锚点 | 主题 | 一句话防重犯 |
|---|---|---|
| G-T01 | curl 带认证头诊断 -v/-i | 会打印请求头泄漏 token;token 从 .env 读不硬编码不 echo |
| G-T02 | 只验①②不验③(前端展示层) | 验收"已上线"必须三查齐:main 链含 commit + 数据层生效(curl 线上字段有值)+前端展示层上线(curl 线上 min 产物含新功能字符串)。只验①②不验③=用户看不到 |
| G-T03 | min 版用变量名验证 | terser mangle 重命名局部变量,max 版验证用 class 名/中文字符串/常量,非变量名 |
| G-T04 | exit 0 当作无错 | 校验脚本吞异常/语法错也 exit 0;读全输出+核 exit code+数 failure 条数;grep 无匹配返回 1≠故障 |
| G-T05 | 验证门少一步就下结论 | 完成前验证门四步(指认/真跑/读全/对账)缺一不许开口"PASS/已修复/已上线";禁用「应该/大概/看起来」 |
| G-T06 | 尺子坏了信尺子 | 自验/机检脚本可能是坏的:造坏样本(改坏字段/空数组/删 key)确认脚本报 FAIL,坏样本也 PASS=尺子坏了,修尺子不信结果 |
| G-T07 | 懒但安全边界乱 | 安全底线(输入验证/安全检查/数据丢失拦截/资损信号上传链路)绝不作"懒"的省略区;懒=不堆多余的,不省底线;最小充分=主路径+关键边界 |
| G-T08 | 贪多测冗余 | 不为行覆盖率给琐碎处补检查;不重复测已有机检/部署前置校验覆盖项;不预写无使用者的测试桩 |
| G-T09 | 断断言具体值不是"不报错" | 断言到键集/条数/数值(守恒/占比阈值/条数比对),不只「脚本没抛异常」 |

## 主控专属经验(通用方法论)

| 锚点 | 主题 | 一句话经验 |
|---|---|---|
| G-E01 | 部署约 90s | online curl 验上线先 sleep 等部署完成 |
| G-E02 | 通知架构演进方向 | TaskCompleted hook 发现(待验证) |
| G-E03 | 子 agent 做中间层不可行 | 先算模型回合数成本再定 |
| G-E04 | 口径/基准切换先派影响面审计 | 会反转/数值变化/自愈三类分类逐项评估,并行修根因再全面修正受影响功能 |
| G-E05 | 发现派单基准过时立即同步在跑 agent | 第一时间同步修正,不留到跑完返工,越早越好 |
| G-E06 | 版本发布机制 | 动核心实用功能必须发中间版本,全站对齐审计(后端/前端/公示四处置 0 过时) |
| G-E07 | token 优化 6 条零成本行为层 | 输出简洁/命令静默/派单只回结论/@文件直引/小任务不 spawn/失败方向用 rewind |
| G-E08 | 优化/修复落地后定期巡检机制 | 每天定时巡检 6 项指标+判定标准,严重止损回滚、小问题迭代 |
| G-E09 | 跨 agent 消息通道防误读 | 请求必带 status 字段 + 发起侧先清场 + 原子写(tmp→rename)+ 同 id 重跑换新 id |
| G-E10 | 测试基准锚点 = 一切回测前提 | 当前基准版本定义存项目专项,权威;测非基准口径显式声明+说明为何测+标注口径差异 |
| G-E11 | 免费异源多重兜底 | 数据源单源项→寻免费异源组合逐源实测,任一源必须有其他源兜底,fallback 不走同源 |

## 归档说明

- 全文原文(含根因+场景+防重犯全文)在 `<docs/archive/CLAUDE-errors-<月份>.md`,本索引只留一句话防重犯
- 新条目追加规则:锚点 = `G-<角色首字母>-<序号>`,按角色归类;复发 = 原条目加"第 N 次复发+强化防重犯条款",不新开条
- 零丢失校验:归档前教训条数 == 本索引行数 + 归档文件 grep 数,不一致=校验失败
- **使用纪律**:命中场景时先查本索引 → `grep 锚点` 归档原文 → 完整条款仍在,一条不丢(§26)
